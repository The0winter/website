# Web exact reading progress v1

The browser uses the same `/api/v1/me/reading-progress/:bookId` contract as the Android repository, through existing same-origin Cookie + `safeFetch` CSRF handling. The injected state machine is `reading-progress.ts`; React lifecycle/account isolation is `reading-progress-react.ts`; actual glyph geometry and normalization are in `reading-progress-dom.ts`.

- Account authentication finishes before loading progress. A cloud GET completes (or fails visibly with a retained offline queue) before the reader publishes a position. Matching chapter anchors restore before first paint; a different explicit URL/catalog chapter stays selected.
- `shared/reader-paragraphs.mjs` is the only paragraph-normalization/key implementation. Offsets count UTF-16 units and never split a surrogate pair. DOM Range measures the first visible character of the actual paragraph, including a paragraph continued across CSS columns. A page number or percentage is only presentation/legacy fallback and never becomes a synced anchor.
- Font, line-height, viewport, fullscreen and reading-mode changes retain the exact paragraph/character until the next intentional turn/scroll. Continuous scrolling reports the visible chapter, including its own server contentVersion, and keeps native scrolling/keyed chapter DOM.
- Outboxes use `reader-progress:v1:<account>:<book>` localStorage keys. Each in-flight operation is immutable with a UUID operationId, deviceId and baseRevision. New movement is retained separately and becomes a new operation only after its predecessor's receipt. Reconnection replays pending books for the current account. Every progress request carries `X-Reading-Account`; after authenticating that exact request the server asserts ownership and rejects a changed Cookie identity with `ACCOUNT_CHANGED`. The preliminary session check improves feedback, while the server assertion closes the cross-tab race. Rejection retains the original queue and stops blind retries.
- A lost acknowledgement replays the exact operation ID. An older receipt cannot replace a newer cloud snapshot fetched during reconnect. A 409 retains both positions and presents explicit cloud/local choices. A cloud deletion accepted by the user stays deleted until an intentional reading movement; layout callbacks cannot resurrect it.
- Body version or missing paragraph-key changes display a confirmation. The UI refreshes the real chapter DTO, restores the matching key or falls back by paragraph index, and uses the returned contentVersion only after the user's choice. It never fabricates a body version.
- Precise reader mounts skip the duplicate legacy history mutation in `RecordBookVisit`. Successful precise writes already update server history. Book-detail visits and existing intentional library-entry behavior remain compatible.

Verification uses a local Next frontend on `127.0.0.1:3000` against the isolated real API on `127.0.0.1:5081`; tests create their own books and never write production data. Private account credentials are read from the ignored fixture file and are not logged or committed. Run the local frontend with `tests/reading-progress-dev.cjs`, the state machine tests with Node's `--experimental-transform-types --test`, and `tests/reading-progress-live.spec.ts` with the repository browser test runner. All Windows Node entrypoints must preload the hidden-process helper and the project test environment.
