# 适配小说来源

面向本机 `F:/Website/Test1` 的拾页窗口。先定位含 `tools/novel-crawler/desktop/sources.mjs` 的项目根；读取该根目录下 `docs/小说采集窗口与站点适配.md` 的站点配置部分。全局 Skill 可能通过目录联接安装，文档从项目根定位，不从 Skill 联接路径推算。

用户提供一个或多个网址时，实际查看其搜索页面、书籍详情、完整目录和少量正文页面的结构，确定适配范围。优先添加 `tools/novel-crawler/sites/<id>.json`；窗口会自动发现配置，无需在界面中硬编码网站。已有配置损坏时修复同一文件，保留其他来源。

## 适配与验收

- 书名和作者从同一个搜索结果卡片提取；详情页再次核对。搜索结果多本同名书时交给窗口选择，不能自动挑近似书名或忽略作者不匹配。搜索没有可用入口时可先适配详情页模式，交付时说明需要填书籍详情页。
- 配置中的书籍 ID 使用 `book.urlPattern` 的命名捕获，不能把示例书 ID、章节总数或标题固定为整个站点的规则。目录分页、分卷重编号和章节分页分开处理，下一章链接不能作为正文下一页。已有正文提取能力见 `docs/智能找书与采集.md`。
- 采集及质量检查沿用现有代码。程序支持正常浏览器渲染，不靠逐章调用模型检测，也不把大量正文输出给模型。只查看规则、统计及定位问题所需的少量样本；遇到无法恢复顺序的正文混淆，明确记录该来源暂不支持。
- 如声明式配置不足，补足实际需要的解析能力和针对性测试，保持请求域名限制、作品核对、检查点完整性及输出保护。不要执行页面提供的本地脚本或安装包。
- 在独立的 `.novel-crawler/adapter-checks/<id>/` 状态目录验证 `searchBooks`、`resolveBook` 和 `acquire(..., {mode:'probe'})`，不复用旧书的成功报告充当新适配的验证。优先检查用户选定的示例书；有易取得的另一部适当作品时验证书籍 ID 和目录泛化，避免只适配一册。不要为验证站点默认为每本书整本下载。
- 修改提取规则需更新 `spec.variant` 的版本，避免混用旧检查点；窗口默认按当前配置生成单本规则。明确区分“站内搜索已验证”“详情页可用”“抽样通过”和“整本已下载”。
- 运行 `node --test tools/novel-crawler/tests/desktop.test.mjs tools/novel-crawler/tests/crawler.test.mjs`，核对新来源在窗口列表中出现，报告试采错误及未覆盖的模式。依项目 Git 约定提交配置、代码、维护文档，缓存与正文留在已忽略的运行目录。

交付时给出支持的域名、输入方式、试采结果与实际限制。后续用户在窗口输入网址和书名即可使用；适配不等于上传或发布采集结果。
