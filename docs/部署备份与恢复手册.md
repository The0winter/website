# 部署、备份与恢复手册（候选，尚未生产执行）

## 当前证据和运行方式

采用一套 Linux systemd + nginx + Node 22.23.2 + MongoDB 7.0.40 单节点副本集。保留现有 Next、Express、Mongoose；不引入 Test2。配置在 infra/systemd 与 infra/nginx-production.conf。Windows 本机已验证 nginx→Next生产构建/API→真实MongoDB的等效链路；Linux开机启动、systemd沙箱、目标证书和目标机器资源尚未实跑。Docker Desktop引擎不可用，不另维护Compose方案。

用户已明确取消旧数据恢复、迁移和导入，将在网站完善后自行重新上传。本手册用于网站运行及未来新数据的维护，不要求寻找或处理历史数据；本地测试数据库和账号不得搬作生产数据。

## 准备一个隔离预发布主机

1. 安装固定Node版本、MongoDB 7.0.40、MongoDB Database Tools 100.17.0和nginx。核对官方包校验值；Node路径按unit文件统一。单节点副本集支持事务，不提供节点高可用。
2. 创建独立系统用户test1-api、test1-web、test1-jobs及mongodb；代码归root所有，只给服务用户读取/目录遍历权。版本目录放/srv/test1/releases/<代码版本>，current为当前版本链接。创建前端.next-candidate/cache，归test1-web；不得让应用写源码目录。
3. /etc/test1目录root管理；api.env、web.env、jobs.env由对应example复制后填入本次随机秘密，权限0600。JWT、内部SSR凭据、导入凭据分别生成，不复用。不要从旧.env复制未知历史秘密。生成MongoDB keyfile，归mongodb、0400；/var/lib/test1-mongodb归mongodb、0700。
4. MongoDB仅绑定127.0.0.1。按mongod.conf启动私有服务；在本机利用首次初始化流程建立test1-rs（单成员127.0.0.1:27017），建立管理员后立即验证认证有效。API和任务使用test1库的独立readWrite账号；备份使用专门backup权限账号。交互创建密码使用mongosh的passwordPrompt()，不写命令历史或Git。
5. 在版本目录按锁文件安装server/web-next依赖，执行后端测试、typecheck、lint、build。构建环境显式给INTERNAL_API_URL、NEXT_PUBLIC_SITE_URL；NEXT_PUBLIC变量改变须重新构建。infra/clean-room.mjs可在本地复制无.env的干净目录重复安装/检查/构建，报告精确文件hash。
6. 新空库也须建立模型索引。对明确的隔离目标执行`node server/migrations/inspect.js`，检查结果无冲突后，以输出的fingerprint运行`node server/migrations/inspect.js --apply --approved-fingerprint=<fingerprint>`；重复执行先重新inspect。r3-v2检查重复键、主要孤立关系、章节字段和索引差异，不自动丢弃索引。生产还必须显式传`--production-target=<MONGO_URI的SHA-256>`，且实际连接/写入已获授权；指纹只是防止选错目标，不是授权。API启动autoIndex/autoCreate关闭，不承担建索引；不使用此流程处理旧数据。
7. 安装对应unit，先MongoDB、再API、再前端。检查/health/live与/health/ready；API初始WRITE_MODE=readonly，任务RUN_JOBS=disabled，外发与索引收录关闭。服务失败自动重启有上限；达到StartLimit后先检查配置/日志，再reset-failed并重启，不能靠无限重试掩盖配置错误。
8. nginx模板中的域名/证书只在目标确认后替换；先nginx -t。只允许80/443公网入站，3000/5000/27017不得开放。API只信任loopback代理；nginx覆盖X-Forwarded-For并清空外来的内部SSR凭据。媒体入口2MB、导入10MB、其他256KB；应用内另校验具体大小。
9. 配置journald容量/14日保留与nginx logrotate；这里的journald片段影响整机日志预算，安装前须与目标现有策略核对。内存限制是候选边界，必须在目标机负载验证后定案，不能套用本机16GB机器的容量结论。

## 备份和恢复

- 目标RPO≤24小时、RTO≤2小时；当前没有生产保证。每日备份至少7份日备份、4份周备份，并复制到经用户确认的异机目标；异机位置和权限尚未配置。
- MongoDB中包含新媒体原始转码字节，数据库备份同时覆盖新媒体；旧Cloudinary等仅URL没有图片恢复保证。部署配置、证书及秘密另行加密备份，严格限制访问。
- 使用mongodump的配置文件传URI/认证（配置0600），不要把密码放命令行。持续写入时对整个专用副本集执行带--oplog的归档；若选择停写快照，须同时停任务/导入并明确写入暂停窗口，不能只停网页写入。
- 归档用--archive=<专用备份目录/时间戳.archive.gz> --gzip，完成后记录SHA-256、大小、开始/完成时间、工具版本、代码版本和索引版本。备份未完成不得覆盖上一份成功备份。
- 在另一空实例执行mongorestore --archive=<文件> --gzip；oplog归档需相应--oplogReplay。不能对当前数据库直接--drop恢复。恢复后验证集合数量、索引、书章ID、正文hash、用户/会话/书架关系和浏览器流程。
- 已完成同机合成库恢复演练：artifacts/restore-report.json。该演练不包含异机、真实旧用户或Linux服务重启，因此不能作为完整RTO/RPO验收。
- 可执行脚本为`node infra/backup.mjs /etc/test1/backup.json`，配置示例infra/systemd/backup.json.example。专用mongodump.yaml使用`uri: "mongodb://备份账号:密码@127.0.0.1:27017/?authSource=admin&replicaSet=test1-rs"`（示意，必须换成本次授权目标），权限0600；URI不选数据库，因为`--oplog`要求整个专用副本集。工具不把URI放进进程参数或日志，成功后才原子更新latest.json；失败保留上次成功归档。后台工具失败只输出通用错误码，排查时不把秘密配置贴进日志。
- test1-backup.service/timer每天02:00启动，可能随机延后10分钟；未安装到目标机。创建test1-backup系统用户，目录0750，归档和秘密只由备份用户读；latest.json允许备份组读取。监测用户加入test1-backup组，只读状态文件，无权读0600的归档。脚本目前保留全部成功归档；异机验证后才能制定清理动作，至少保留7份每日/4份每周备份。不是已完成轮转或异机复制。
- 最新真实工具验证见artifacts/backup-candidate-report.json：使用上面脚本和--oplogReplay，在空副本集恢复合成用户/书架/评论/草稿、原章节ID/hash、密码登录和索引。参考[MongoDB官方mongodump说明](https://www.mongodb.com/docs/database-tools/mongodump/)；包含oplog的归档应完整恢复后回放，不对生产库直接覆盖。

## 应用回滚和维护

首个生产版本之前没有已验证的安全旧公网版本。失败时保持只读/维护响应，禁止启动原漏洞版本或旧修库脚本。待候选通过后保存至少两套相容安全版本；回滚只切换代码版本链接并重启API/前端，保留MongoDB新增业务数据。索引和schema兼容性先在隔离副本验证。

数据库恢复属于独立的生产数据变更，可能丢失备份后的写入；必须先给出具体时间窗口、对账方案和影响，再取得授权。不得把应用回滚和破坏性数据库回退混为一谈。

## 监控与最终发布门槛

初始阈值：服务不可用≥1分钟；5分钟5xx比例>1%且有合理最小请求量；磁盘>80%；备份超过26小时。监控渠道尚未指定，没有真实告警投递验收，不宣称监控完成。观察任务未创建，不承诺自动回访。

本地采集实现为`node infra/monitor.mjs /etc/test1/monitor.json`及test1-monitor.timer（15秒）。API配置独立MONITOR_SECRET；/health/metrics同时要求回环源与专用凭据，nginx禁止公网入口。指标只含6个分钟桶、RSS/heap/CPU/就绪状态，不含用户、Cookie或正文。5xx判断采用5个完整分钟、总量至少100请求；监控规则测试包含恢复和低请求量反例。monitor.json按示例填写状态路径、MongoDB所在磁盘和备份latest.json；真实告警当前只写本地日志，不发送邮件或Webhook。没有部署/渠道实测时不能把systemd文件存在视为监控完成。

生产Cookie已在本机真实nginx TLS代理与Next生产构建上用合成库验证（production-cookie-report.json）；使用的自签名证书仅在隔离浏览器上下文忽略信任错误，没有安装到系统信任库。该结果不证明目标证书、域名或Linux开机启动。Next的API rewrite在构建时写入产物，构建与运行须使用一致INTERNAL_API_URL；改变公开站点或代理目标须重新构建并验证。

公开发布前应基于验收报告核对新空库和用户自行上传流程、端口/TLS/配置、备份/维护与具体发布动作。核心浏览器16项已通过；完整30分钟混合复测、Linux部署与外部告警仍有缺口，过载结果见最新验收报告。旧数据处理已取消，尚未请求公网发布授权。公开发布、24小时观察和7天观察分别验收。
