# 九天中文网 Android App 1.0：Goal 开工提示词

在本项目的聊天中选择 GPT-6 Astra、Ultra，然后复制以下完整提示词。此文件只是开工指令，保存它不代表开发 Goal 已启动；预算仅在用户明确指定时设置。

```text
/goal 在 F:\Website\Test1 项目中，开发并交付九天中文网的原生 Android App 1.0。第一版必须覆盖开工时线上网站 https://jiutianxiaoshuo.com 的全部网页业务功能，并完成验证和安装包交付。现在开始实际开发，持续推进到满足下列完成条件，不停在方案、骨架或功能残缺的 MVP。

一、先读取规则并固定范围
读取项目 AGENTS.md、适用的子目录规则及 docs/安卓原生App技术方案.md，检查工作区、远程 main 和线上版本。保留其他任务的未提交改动，不能把缺少线上功能的版本当作开发基线。
盘点网页移动端、桌面端以及访客、读者、作者、管理员各角色的业务能力，建立 android/FEATURE_PARITY.md。逐项记录网页入口、行为、权限、App 对应入口、接口、状态和验收证据；记录基线版本与时间，避免开发过程中追逐未明确纳入的新需求。
范围包括但不限于：首页、推荐、排行、搜索、作者、书籍详情、目录、阅读器及设置、书架、阅读历史、账号与个人资料、书评、段评、论坛文章与问答、创作空间、草稿、发布、回收站，以及网页实际提供的导入、转移和管理操作。具体以盘点结果为准，不得因为本段没有列举就遗漏。服务器部署、采集脚本和 SEO 文件不作为 App 页面照搬。
全部网页业务功能属于同一个 1.0；分阶段只是内部检查点，不得自行将功能推迟到下一版或缩减为只读客户端。

二、技术与体验
采用 Kotlin、Jetpack Compose、ViewModel/StateFlow、Coroutines、Repository、Room、DataStore，以及独立的原生阅读器模块；以技术方案为起点，开工时核对稳定依赖与工具链兼容性。安卓工程放在 android/，与网站独立构建。
页面和交互按 Android 设计，保留九天中文网的品牌风格和业务能力。不得用 WebView 打开现有网站来代替业务功能的原生实现。
阅读器重点处理中文排版、网页现有阅读模式、字体和行距、段落定位、长章节、长目录、换章、系统返回及进程恢复。同时实现离线下载和准确的跨端续读。先验证核心阅读链路，再逐步完成全部模块。

三、后端与数据
复用现有账号、书籍、章节、社区和创作数据，以及 Express、MongoDB、R2 业务服务；补齐原生认证、章内进度、必要的同步和版本化接口，保持网页及旧客户端兼容。
保留现有权限、会话撤销和网页 CSRF 保护。App 不携带服务器或 R2 凭据。同步、草稿、上传和内容修改需要处理重试、冲突及失败恢复，不破坏现有数据。

四、智能体与执行成本
主智能体保持我选择的 GPT-6 Astra Ultra。仅对适合独立分工的任务使用子智能体，同时最多 3 个，不含主智能体；不要求开满，不允许子智能体递归派生。
子智能体都使用 gpt-6-astra，按任务选择 effort：简单检索/小改动 low，常规实现/测试 medium，复杂逻辑/审查 high，困难算法或根因调查 xhigh；max/ultra 仅在明确必要时使用并说明理由。
创建时通过工具参数明确指定模型和 effort，遵循 AGENTS.md 的历史分叉限制。分清文件所有权和接口边界，避免同时改同一文件或重复工作。主智能体负责集成、复核和最终验收。
构建、测试和完整比对由脚本执行，模型主要读取摘要与异常；不要反复输出整份日志，不擅自降低验收标准。

五、持续执行与检查点
建立并维护 android/PLAN.md 和 android/PROGRESS.md，记录模块状态、设计决定、提交、验证证据、阻碍和下一步。每个可验证里程碑更新记录；上下文压缩或恢复后先读检查点，不从头重做。
常规实现选择、错误修复和已授权操作自行处理，不在每个阶段结束时等待我说“继续”。确实缺少用户才能提供的信息、设备或凭据时，列出具体缺项，同时继续不依赖它们的工作。
遇到预算或额度限制时保留恢复入口；未达到全部完成条件不能将 Goal 标记完成，不擅自设置我未指定的 token 预算。

六、后台运行、Git 与部署
严格遵循 AGENTS.md：命令、构建、测试、浏览器和模拟器默认隐藏或无头运行，不弹窗、不抢焦点；需要我操作时先提示。Node/npm 后台任务加载指定的 Windows 隐藏窗口预加载器。
临时文件、日志和测试数据放入项目指定目录，线上浏览器验收在首次导航前屏蔽 Google Analytics。
只在 main 工作，不新建分支或 worktree，不覆盖或提交其他任务的改动。完成适当检查后只提交本任务文件并推送 origin main。必要的网站/后端修改按既有授权流程兼容部署、验证和保留回滚版本。

七、完成条件
android/FEATURE_PARITY.md 中的全部首版业务功能均已实际实现并通过对应验收；页面存在、演示数据、TODO 和编译成功不能代替业务验证。
完成适当的单元测试、接口合同测试和 Android 端到端验收，覆盖角色权限、真实内容、跨端同步、离线、重启/进程恢复、长章/长目录、字体重排，以及现有网站回归。写操作使用隔离测试账号和数据，避免污染真实用户内容。
验证 release 构建和中低端设备表现；真实设备不可用时如实列为待验收，不能把模拟器结果写成真机通过。
交付可安装的签名 release APK、对应源码提交、安装/升级说明、完整功能对照表与验收报告。签名密钥独立安全保存，不提交 Git；签名或验收条件未满足时明确列出，不能假报完成。应用商店上架不包含在本次目标中。
最终报告说明哪些条件已验证、还有没有缺项，以及安装包和证据所在位置。只有目标确已全部达到才完成 Goal。
```

该提示词按 [OpenAI Goal 官方说明](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex) 组织目标、范围、验收与检查点。Goal 的持续运行仍受客户端执行条件、预算、账户额度和实际阻碍影响。
