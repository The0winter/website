# 静态资源压缩

`npm run build` 的 postbuild 会为 Next 构建目录下的 JS、CSS 生成 Brotli 文件，逐个解压比对原文后保存，原文件保持不变。不压缩图片、字体，不改组件、交互或代码加载时机。

部署时把 `infra/nginx-static-compression.conf` 内容嵌入现有 HTTPS 应用 server，使用 `# BEGIN TEST1 STATIC COMPRESSION` / `# END TEST1 STATIC COMPRESSION` 标记管理。保留其它 Nginx 配置，先备份并执行 `nginx -t`，再按既有预热、切换、验收流程发布。不要 include 指向 current 的配置文件，以保证回滚到没有该文件的旧版本时仍能重载 Nginx。

仅浏览器明确接受 `br` 时返回预压缩文件，携带正确的 JS/CSS 类型、Content-Encoding、Vary、长期缓存和原有安全响应头。其它情况由 Next 正常提供 gzip/原始响应。`br;q=0` 不启用 Brotli；带显式权重的编码也保守地回退。旧回滚版本没有 `.br` 文件时同样回退，不需要修改其构建目录。

验收检查：同一静态资源的 br、gzip、identity 解码后逐字节相同；禁用 br、缺失资源、HEAD 请求行为正常；浏览器首页预加载、详情、目录及章节交互正常。响应体减少不等于耗时按比例减少，实际耗时还受网络延迟影响。
