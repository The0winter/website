# 作品搬运

创作中心的第二个快捷入口改为“作品搬运”。登录用户填写原作者、书名，选择 TXT 后提交审核；页面的“我的提交”显示进度和退回原因。管理员在同一页面切到“搬运审核”，分段预览纯文本、核对重复作品、退回或收录。

“我的作品”的封面打开单本作品的浏览统计；私密草稿显示零浏览量。作品区保留“数据汇总”，兼容旧统计链接。投稿人不因填写原作者而获得作者账号或书籍编辑权限。

## 接收与保护

- 原始文件最大 30 MiB，仅接受 TXT。实际字节数必须与预登记大小一致；解析 UTF-8、GB18030、带 BOM 的 UTF-16，拒绝二进制控制字符、解码失败及空文件。转换后 UTF-8 不超过 60 MiB。
- 文件始终作为数据处理。独立 Worker 限制 384 MiB 堆内存和 15 秒解析时间；接收最长 90 秒，文件接收、预览和收录共最多同时一项（适配现有 API 的 768 MiB 内存上限）。正文按纯文本预览，不执行 HTML 或脚本。
- 会话、CSRF、IP 限流在读取正文前完成。每个账号滚动 24 小时最多创建三份投稿，同时最多五份未完成/待审核/正在收录投稿。限额写入数据库，重启不会重置；失败上传也计入当天次数。
- 每份先预留 60 MiB，全站投稿箱最多预留 5 GiB，事务锁避免并发绕过。限额是保护阈值，不是额外购买容量。
- 私有独立 R2 桶保存校验后的 UTF-8 文本，对象名由系统生成，回读 SHA-256 校验后才标为待审核。浏览器不接触存储凭据，不开放公开桶域名，不直接使用已有管理员导入凭据。
- 上传重试使用同一提交 ID；成功文件不可再次覆盖。书库已有同书名同作者时停止收录，不能覆盖已有书籍。

## 审核与入库

系统按常见章标题识别章节，标题原行仍保留在正文中；超长段落按 180,000 字符拆分，避免截断内容。管理员应先预览核对分章。每次收录最多 20 章，私密的中间书籍和进度一起事务保存，完整数量核验后才公开。浏览器关闭、网络中断或进程重启后，可在“搬运审核”继续收录。

只创建新书，署名关联独立 Author 资料，不绑定投稿账号。已有网站导入、编辑、正文存储和权限规则继续有效。

退回后删除投稿原文件并释放预留空间；上传超过十分钟未完成、待审核超过三十天变为已过期，已收录三十天后清理投稿文件。每十五分钟补漏，错误保留状态并重试；收录中的文件不自动清理。正式书库正文不在此清理范围。

第一版由后台“搬运审核”接收，不发送附件邮件或自动通知邮件。

## 上线配置

必须先准备独立私有 R2 桶（建议 `jiutian-submissions`），关闭 r2.dev 和公开自定义域名。建立仅该桶对象读写权限的专用凭据。不能复用封面公共桶或正文桶。

在 Git 忽略的本地配置文件中填写以下四项，然后使用 `node --require D:/Apps/Codex/home/tools/windows-hide.cjs infra/configure-transfer-r2-vps.mjs <配置文件路径>` 写入现有服务器环境；工具会备份旧环境文件并保持 0600 权限，不输出凭据，也不会自行重启。

```dotenv
TRANSFER_R2_BUCKET=jiutian-submissions
TRANSFER_R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
TRANSFER_R2_ACCESS_KEY_ID=<bucket-scoped-access-key-id>
TRANSFER_R2_SECRET_ACCESS_KEY=<bucket-scoped-secret>
```

Nginx 新增 `infra/nginx-production.conf` 中 `/api/transfers/` 的独立规则，流式代理、请求上限 30 MiB、读取及发送超时 90 秒；同时添加 `/api/transfers` 的精确规则，防止自动补斜杠的 301 重定向将登记 POST 转为 GET。其他路径保持原配置。Node 请求接收超时调到 120 秒，头部超时仍为 10 秒。

新集合 `transfersubmissions`、`transfercapacities` 在首次使用时创建并建立索引，不迁移或删除现有数据。没有配置 R2 时提交返回 503，不能将此状态当成上线成功。

按既有兼容部署流程保留线上功能，在候选版本完成构建、上传/回读/权限验证，再切换 current。真实存储验收使用明确命名的合成投稿，审核退回并确认原文件删除；不得发布测试小说。最终核对公网入口、健康检查、既有书目/目录/正文和版本标记。
