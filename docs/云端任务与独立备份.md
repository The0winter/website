# 本机、Codex 云端与远程采集

2026-09-30 用户授权：日常工作留在本机；有明确终点的长开发任务使用 Codex 云端；采集由持续运行的服务器处理。云端只准备必要环境，后续按需要补充。重要代码、程序、配置说明和数据必须有不依赖 Pro 套餐的副本。

## 保存位置

| 内容 | 主位置 | 独立恢复位置 |
| --- | --- | --- |
| 源代码、安装脚本、任务规则 | GitHub `The0winter/website` 的 main | 本机项目；`backups/codex-hybrid/source.bundle`；远程执行器代码的私有 R2 备份 |
| 云端依赖与运行时 | Codex 云端环境 | 通过 `.node-version`、四份 lockfile 和 `infra/cloud/setup.sh` 重建 |
| 远程队列、采集检查点、原始页面、结果 | `/var/lib/test1-remote-worker` | 私有 R2 的加密、去重 restic 仓库 |
| 备份解密密码 | `/etc/test1-remote-worker/backup-password` | 本机 `backups/codex-hybrid/restic-password.txt`，限制文件权限 |
| 线上数据库 | 原有 Atlas | 沿用现有 Atlas → 私有 R2 验证备份，不迁入 Codex |
| 本机原书库 | 原有 downloads 与 .novel-crawler | 沿用现有按书去重恢复快照；本次不迁移整库 |

云端任务不承担唯一数据保存职责。订阅到期后的具体保留行为不作保证；完成一个重要阶段就取回代码差异，在本机核对后提交并推送 main，不依赖云端任务直接推送或长期保留。重要文件在离开任务前应导出到上述独立位置。云端安装的工具可重建，缓存和临时构建无需保留。

本机的备份密码不能提交 Git，不能仅放在云端任务或同一个加密仓库里。私有 R2 依然依赖用户自己的 Cloudflare 账户及服务，不是 Codex 套餐提供的存储。

## 最小 Codex 环境

仓库选 `The0winter/website`，起点 main。安装命令：

```sh
bash infra/cloud/setup.sh
```

脚本安装固定 Node 22.23.2，以及 root、server、web-next、采集器的锁定依赖；使用 Python 3 和 Git。浏览器二进制不默认下载。原始小说、备份、Cookie、SSH 私钥和生产环境文件不上传到开发环境。个人技能不会自动同步，当前项目已有 `.agents/skills/novel-download` 可复用。

云端验收命令：

```sh
bash infra/cloud/run.sh node infra/cloud/capacity.mjs
bash infra/cloud/run.sh npm run typecheck
bash infra/cloud/run.sh node --require ./tools/test-env.cjs --test infra/cloud/remote-worker.test.mjs
bash infra/cloud/run.sh npm run build
bash infra/cloud/run.sh node infra/cloud/capacity.mjs
```

安装脚本也作为维护脚本；只有 lockfile、运行时版本或依赖存在状态变化时才重新安装，复用环境缓存。`run.sh` 让后续命令使用同一个固定 Node 版本。报告保存 `.runtime/task-artifacts/cloud-environment/`。目标至少留出 8 GiB 磁盘余量；不将容量目标当作已测结果。Playwright 和需要登录的浏览器功能另做实际兼容性验收。

`typecheck` 先执行 Next.js 的 `typegen`，因此全新检出也能识别图标和路由类型。Inter 字体及其开源许可随代码保存，构建不再依赖 Google 字体下载。云端运行阶段默认关闭互联网，安装和维护阶段保留环境提供的依赖安装网络。

Windows 本机运行这些命令，仍须给 Node 预加载 `D:/Apps/Codex/home/tools/windows-hide.cjs`。测试继续先加载 `tools/test-env.cjs`，临时输出仅位于 `.runtime/test-tmp/`。

## main 的交接

- 开始前先 fetch，保留本机未提交的其他任务改动。
- 同一时间由一个环境负责本任务的提交和推送；云端完成后，本机先同步再继续相关代码。
- 不建立功能分支、额外工作树或默认 PR。
- 平台若自动检出名为 `work` 的临时分支，先核对提交与所选 main 相同；修改代码前将该本地分支改名为 main，已有 main 时仅在同提交且工作区干净时切换。不要强制重置分支。
- 云端长任务需从云端环境明确启动。本机运行中的进程不会自动迁移；采集需要按检查点重新启动。
- 开发环境不持有生产数据库、R2 管理和服务器 SSH 凭据。发布继续从已有部署环境执行。

## 远程执行器

独立代码目录 `/srv/test1-remote-worker/current`，不切换网站的 `/srv/test1/current`。运行用户 `test1-remote-worker`。systemd 定时检查的是队列，不会自行把本机全部书籍加入采集。

初始边界：一次一项、每批最多 50 章、CPU 上限 60% 单核、内存上限 1 GiB、至少 8 GiB 剩余磁盘。仅支持已验证的 HTTP/文件来源；浏览器来源需单独配置并验收。只有结构检查通过的分批下载才会自动继续；内容错误、网络异常或反复进程中断保留进度并进入 `needs_attention`，不会降低质量标准。不会自动上传到生产书库。

```sh
cd /srv/test1-remote-worker/current
sudo -u test1-remote-worker /opt/node-v22.23.2-linux-x64/bin/node infra/cloud/remote-worker.mjs enqueue --spec /path/to/verified-source.json --mode probe
sudo systemctl start --no-block test1-remote-worker.service
sudo -u test1-remote-worker /opt/node-v22.23.2-linux-x64/bin/node infra/cloud/remote-worker.mjs status
# 明确继续已核对的任务，可将 probe 改为 download：
sudo -u test1-remote-worker /opt/node-v22.23.2-linux-x64/bin/node infra/cloud/remote-worker.mjs resume --id <20位任务ID> --mode download
```

服务在服务器端托管，SSH 连接断开后继续运行。每批结束或进程退出后启动独立备份。未完成上一检查点的异地备份时，下批采集暂缓，备份恢复后再续跑。定时器在重启后重新处理已排队任务；不把已完成或待核对任务无条件重跑。

入队、恢复、采集与备份共用互斥锁。新增或恢复队列也先触发备份，避免备份期间写入状态；繁忙时保留现有任务，稍后重试。

## 独立备份与恢复

restic 仓库使用现有私有 R2 桶中的 `backups/codex-hybrid/restic`，与正文和 Atlas 备份分开。去重保存代码、队列和采集数据，跳过可重新安装的依赖、Node 二进制和临时构建。不会复制本机整库作为任务备份，也不会自动 prune 历史恢复点。

备份成功后执行 `restic check --read-data`，全部通过才替换 `/var/lib/test1-remote-worker/backup-latest.json`。失败保留上次成功记录及 `backup-required.json`。日志在 `/var/log/test1-remote-worker/backup.log` 覆盖保存。

恢复操作在新的 `.runtime/test-tmp/restored-*` 目录中执行，禁止直接覆盖运行中的书库。用备份密码文件和原有私有 R2 访问凭据配置 restic，然后选择清单内的确切 snapshot ID：

```sh
restic snapshots --json
restic check --read-data
restic restore <snapshot-id> --target /srv/test1-remote-worker/current/.runtime/test-tmp/restored-worker-<date>
```

核对恢复后队列、来源配置、章节检查点、正文哈希、代码版本与运行前记录；通过后再做人工明确的接管，避免两个位置同时处理同一本书。恢复测试结果另存验收记录，不因文件存在就声称恢复成功。
