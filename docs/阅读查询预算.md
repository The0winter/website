# 阅读接口查询预算

2026-09-16：复用访问控制中已经读取的章节、书籍记录，并把目录版本的二次校验移入缓存构建过程。

## 正常公开阅读

以下为单次请求、进程内对应版本缓存已命中时的数据库查询次数，不包含浏览器另外发送的评论、进度或阅读上报请求。

| 接口 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 章节正文及前后章导航 | 5 | 2 |
| 目录窗口 | 3 | 1 |
| 目录版本 | 2 | 1 |
| 全书字数统计 | 3 | 1 |
| 章节预览分页 | 4 | 2 |

章节仍每次按主键读取一次最新记录，书籍仍每次按主键读取一次权限、删除状态及 `writeVersion`。记录仅放在服务端本次请求的 `res.locals`，不能来自请求参数，也不会跨请求共享。正文按内容哈希读取 R2；正文更新后新引用立即生效。

目录及导航索引只缓存元数据，按数据库连接和书籍版本隔离，沿用每类最多 128 本、16 MiB 的容量预算。冷启动、淘汰和发布新版本会触发构建：读取章节元数据后再次查询书籍版本，校验通过才让共享 promise 成功。期间发生更新或删除时，结果不会写入可用缓存；目录返回 409/404，导航最多尝试 3 次后返回 409，避免无限重试。

缓存命中返回的是本次权限/版本读取时对应的已验证目录快照，不再额外查询同一版本。正常写入必须在同一事务中更新章节和递增 `Book.writeVersion`；直接绕过写入服务修改章节的运维脚本也必须遵守这一约定。

私密书籍的登录、作者、管理员判断保持原有行为，可能需要额外的会话和用户查询；上述预算不适用于私密书籍。首次构建还可能包含 MongoDB `getMore` 游标批次，不能将冷启动的全书读取算作只有一次数据库操作。

- `server/tests/reading-query-budget.test.js`：在 SQL 和原生 MongoDB 两种后端统计实际读取命令，覆盖查询预算、R2 正文更新、HEAD、章节下架/恢复、私密/删除作品、构建期间并发更新/删除。
- `server/tests/reading-cache.test.js`：SQL 查询计划及连续 200 章读取，发布、章节增删、排序、字数和容量淘汰；缓存工具的连接隔离同时支持 MongoDB 测试。
- `server/tests/reading-catalog.test.js`：目录分页、分卷、统计、锚点与版本冲突。
- 服务器验收使用独立只读进程连接现有 Atlas，顺序读取相同接口，记录驱动命令、响应耗时和响应摘要；不对生产库做并发压力测试。

测试从项目根目录运行 Node 22，预加载 `--require ./tools/test-env.cjs`。原生 MongoDB 测试设置 `TEST_DATABASE_BACKEND=mongodb`；200 章 SQL 查询计划测试仅在 SQL 后端运行。

## 容量边界

减少单次请求的工作量不等于限制全站吞吐量。现有公开请求限制是每 IP 每分钟 3000 次，平均约每秒 50 次，并非严格的每秒上限。即使章节已降到两次查询，每秒 50 次读取也会占满约 100 次操作的预算，其他访问、写入、冷缓存和备份仍需要余量。

Atlas Free 的官方限制为每秒 100 次读写操作，超出后会排队、限速及冷却；这是响应延迟和超时风险。它不是触发自动付费升级的阈值。套餐及其他产品的账单应独立核实，不能用本次接口查询计数推断账单。[MongoDB 官方限制](https://www.mongodb.com/docs/atlas/reference/free-shared-limitations/)
