# Atlas 出站读取优化

2026-09-27：在保留实时权限、上下架、正文、统计和每日一致性备份的前提下，减少 MongoDB 返回的冗余资料。

## 已实施

- `fields=ranking` 在 MongoDB 查询/聚合中投影卡片字段；排序、总数、分页和响应格式保持一致。普通完整接口继续返回完整资料。
- 发现页先读取 ID、热度、评分、更新时间、分类、作者以执行原有选书算法，再按原顺序读取当前页资料；第二次读取仍包含公开/未删除过滤。每日推荐的候选池也只读取选书字段。
- 阅读、目录等权限检查只读取权限、删除标记和 `writeVersion`。评论汇总仍读取 `statisticsSeed`，保留原评分口径。
- 详情页的首尾各 30 章预览使用按 `writeVersion` 失效的有界共享缓存（128 本、估算 8 MiB）。并发请求共享加载，版本变化后重读；构建期间再次核验版本，失败不保留。权限、书籍信息、统计、私人书架和正文不进入这个缓存。
- 不改变每日备份频率、一致性快照、归档格式及 R2 SHA-256 回读。备份清单新增独立的 `sourceUsage`，统计每个集合读取的 BSON 文档字节，原有 `collections` 校验字段不变。

### 2026-09-28 阅读链路

- 章节页的服务端正文与 SEO 共用一次 `GET /api/chapters/:id?navigation=1&reader=1`，返回 `{book, chapter}`。书籍只含 ID、标题、作者、封面、分类、状态和 `writeVersion`，不读取简介、统计种子等完整详情。普通章节接口保持原格式；客户端缺少书籍资料时使用 `GET /api/books/:id?fields=reader`。
- MongoDB 在单次聚合中按章节主键读取正文引用，再按书籍主键关联实时权限、删除状态、版本和可选阅读字段。正常热章节请求从两次数据库往返减为一次。SQL/D1 适配器保留两次索引查询，避免其通用关联实现读取整张书籍表。
- 导航索引首次加载时在 MongoDB 汇总字数，按章节号每 1000 的区间返回 ID 数组，减少逐章文档字段与游标回复开销。按原章节号排序，保留缺号、软删除和准确的上下章；构建完成后仍校验版本，并发共享与更新重试规则不变。
- 阅读索引缓存上限调整为 512 本、估算 48 MiB；完整目录为 256 本、估算 32 MiB。它们仍有 LRU 淘汰和按出版版本失效，不缓存正文权限或书籍实时信息。完整目录仍只在需要时加载，正常翻页和相邻章节预加载不减少。
- 以 SQLite 全套回归和真实 MongoDB 验证内容一致、数据库投影、字节预算、并发更新、目录顺序、私密作品的作者/管理员权限、封禁、下架及删除。线上验收包含移动端与桌面端的正文、翻页、目录、刷新，并核对服务端正文及无脚本路径与基线的差异。

### 2026-10-03 论坛推荐的请求驱动缓存和增量核对

- 基线为 `4e7857723d4b5bb430c202d50c264ac534e5843d` 的轻量排序版本；此次不重复计算其候选缩减和排序优化收益。
- 公共候选特征及热度按查询维度在 API 进程内复用，60 秒有效，最多 48 个键、估算 JSON 4 MiB；同键并发只查询一次。过期不会主动刷新，下一次实际请求才读取。没有新增定时预热、跨用户缓存权限或后台补排名任务。
- 当前页在 MongoDB 内按主键关联帖子、回答及书籍，合并实时权限和内容版本核验。个人屏蔽、已读冷却、会话身份和跨页去重保持独立。SQL/D1 使用有限投影查询，避免通用关联适配器扫描整表。
- 每分钟的原有目录同步仍保留；每六小时复核先返回版本判断结果，只对新建或实际变更的内容读取正文、重新提取特征。浏览、点赞及评论计数不推进正文修改时间；书籍统计变化通过实际书籍元数据比对排除。正文整理会正常更新修改时间，发布时间保持不变。
- 手机首屏保留 5 条，下一页等读者滚动接近底部或明确点击后加载。轻触、悬停、聚焦标题和取消导航不再下载未打开正文；首页的隐藏论坛外壳不再取偏好数据。正文页面代码也在实际进入时加载。
- 新增每条推荐的帖子/回答版本和书籍元数据用于核对，属于持久存储的增加。首次上线需要一次补齐，之后不反复重建相同条目。`syncForumCatalog({reconcile:true})` 可从头核对；正常定时任务不使用此参数。
- 本机鉴权监控接口增加 `forumRecommendationCache`，仅记录缓存数量、估算字节和命中/合并次数，不记录用户信息或原文。

隔离原生 MongoDB、同一组 128 本书/512 条回答的对比：首屏数据库命令回复约 77.8 KB，冷缓存约 76.9 KB，充分命中缓存约 11.4 KB；无变化完整复核约 2.60 MB → 65 KB，写入命令 788 → 20（保留检查点）。缓存样本约 0.46 MB JSON、清空前后堆差约 0.95 MB；派生集合增加约 0.29 MB。字节按 BSON 估算，JSON 上限不等于 JavaScript 堆上限；这些是测试负载结果，不能直接当作线上账单或所有用户的固定降幅。

本次基线、原生数据库对比、浏览器请求记录及线上核验结果放在 `.runtime/task-artifacts/forum-egress-20261003/`。收益和新增负担分别统计：浏览器响应、数据库命令回复/次数、服务器 CPU/缓存堆、派生集合大小、首次补齐成本。短样本延迟不宣称为 P95，真实账单仍按业务访问量及缓存命中率判断。

## 观测口径

MongoDB API 连接通过驱动命令事件记录回复的估算 BSON 大小和命令数，按列表、详情、阅读、目录、评论、导入、个人数据、论坛等固定用途分组。只保存数字，不保存查询、正文、用户标识或凭据。

`/health/metrics` 的 `databaseUsage` 保留最近 48 个小时桶，`startedAt` 表示本次进程的起点；重启会清空内存计数。接口仍只允许携带监控密钥的本机请求。生产日志在下一小时收到数据库命令时输出上一小时的 `database-usage-hour` 汇总，便于跨重启分析。独立进程的任务不会混入 API 计数；备份使用自己的 `sourceUsage`。

这些数字用于比较同负载的读取量，不是 Atlas 账单：不含 TLS、握手、心跳、复制等，也不能重建上线前的用途占比。失败或无法测量的回复有独立计数。流量卡片仍是三节点小时速率积分的七天滚动估算，旧流量会逐小时移出，不能用上线前后的瞬时总数评价效果。

## 暂不实施的措施

- 实测当前 Atlas：同一批 336 本书，未压缩与请求 zlib 各两次，均未协商出压缩算法；每次约 572104 socket 接收字节。因此不加入无效压缩配置、不把压缩计作收益。以后集群变化可重新受控测试；[驱动压缩文档](https://www.mongodb.com/docs/drivers/node/current/connect/connection-options/network-compression/)说明只有双方支持才能协商。
- 不缓存访问权限和整页统计，不减少备份，不对正常读者或搜索引擎增加限流。

## 验收与回退

重点核对卡片字段/顺序/分页、并发预览、更新失效、私有及删除状态、评论评分、备份恢复格式。分别通过 SQLite 和真实 MongoDB 的合成数据测试，再以线上只读请求比较 BSON 回复量与完整响应。

部署复制当前已验证版本，仅替换本次提交涉及的文件，保留其他线上功能和服务器配置；涉及阅读页时在新版本目录重建前端。发布前核对基线哈希；切换失败回到前一个兼容版本并恢复服务。上线后的流量趋势应使用相同业务负载，并结合 `startedAt` 判断数据覆盖范围。
