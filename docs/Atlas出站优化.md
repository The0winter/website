# Atlas 出站读取优化

2026-09-27：在保留实时权限、上下架、正文、统计和每日一致性备份的前提下，减少 MongoDB 返回的冗余资料。

## 已实施

- `fields=ranking` 在 MongoDB 查询/聚合中投影卡片字段；排序、总数、分页和响应格式保持一致。普通完整接口继续返回完整资料。
- 发现页先读取 ID、热度、评分、更新时间、分类、作者以执行原有选书算法，再按原顺序读取当前页资料；第二次读取仍包含公开/未删除过滤。每日推荐的候选池也只读取选书字段。
- 阅读、目录等权限检查只读取权限、删除标记和 `writeVersion`。评论汇总仍读取 `statisticsSeed`，保留原评分口径。
- 详情页的首尾各 30 章预览使用按 `writeVersion` 失效的有界共享缓存（128 本、估算 8 MiB）。并发请求共享加载，版本变化后重读；构建期间再次核验版本，失败不保留。权限、书籍信息、统计、私人书架和正文不进入这个缓存。
- 不改变每日备份频率、一致性快照、归档格式及 R2 SHA-256 回读。备份清单新增独立的 `sourceUsage`，统计每个集合读取的 BSON 文档字节，原有 `collections` 校验字段不变。

## 观测口径

MongoDB API 连接通过驱动命令事件记录回复的估算 BSON 大小和命令数，按列表、详情、阅读、目录、评论、导入、个人数据、论坛等固定用途分组。只保存数字，不保存查询、正文、用户标识或凭据。

`/health/metrics` 的 `databaseUsage` 保留最近 48 个小时桶，`startedAt` 表示本次进程的起点；重启会清空内存计数。接口仍只允许携带监控密钥的本机请求。生产日志在下一小时收到数据库命令时输出上一小时的 `database-usage-hour` 汇总，便于跨重启分析。独立进程的任务不会混入 API 计数；备份使用自己的 `sourceUsage`。

这些数字用于比较同负载的读取量，不是 Atlas 账单：不含 TLS、握手、心跳、复制等，也不能重建上线前的用途占比。失败或无法测量的回复有独立计数。流量卡片仍是三节点小时速率积分的七天滚动估算，旧流量会逐小时移出，不能用上线前后的瞬时总数评价效果。

## 暂不实施的措施

- 实测当前 Atlas：同一批 336 本书，未压缩与请求 zlib 各两次，均未协商出压缩算法；每次约 572104 socket 接收字节。因此不加入无效压缩配置、不把压缩计作收益。以后集群变化可重新受控测试；[驱动压缩文档](https://www.mongodb.com/docs/drivers/node/current/connect/connection-options/network-compression/)说明只有双方支持才能协商。
- 不缓存访问权限和整页统计，不减少备份，不对正常读者或搜索引擎增加限流。

## 验收与回退

重点核对卡片字段/顺序/分页、并发预览、更新失效、私有及删除状态、评论评分、备份恢复格式。分别通过 SQLite 和真实 MongoDB 的合成数据测试，再以线上只读请求比较 BSON 回复量与完整响应。

部署复制当前已验证版本，仅替换本次提交的后端文件，保留前端构建和服务器配置。发布前核对基线哈希；切换失败回到前一个兼容版本并恢复服务。上线后的流量趋势应使用相同业务负载，并结合 `startedAt` 判断数据覆盖范围。
