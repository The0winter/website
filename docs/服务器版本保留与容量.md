# 服务器版本保留与容量

适用服务器：`jiutianxiaoshuo.com`，网站根目录 `/srv/test1`。

## 版本保留

保留当前版本和按 `activatedAt` 排序最近的两个成功版本。切回较旧版本时，仍保留最近的成功版本用于再次切换；不能仅按目录修改时间清理。回滚版本须继续兼容现有 Atlas 数据和 R2 正文、封面。

`infra/release_retention.py` 默认只生成计划；`--apply` 执行清理。它要求当前版本和两个回滚版本都具备成功标记、源码提交和构建文件，并核对服务与 HTTP 健康状态。跳过未验证、尚在构建或仍被进程工作目录、文件描述符、内存映射引用的目录；执行时再次核对当前链接、候选目录身份、进程引用和挂载点。删除使用不跟随符号链接的目录删除，不改写共享硬链接文件。

范围仅限 `/srv/test1/releases` 的直接子目录。备份、Atlas 数据、R2 对象、服务器配置和证书均不在清理范围。首次处理早期无清单的历史部署时，人工审查后可使用 `--include-legacy`；自动服务不启用此选项。

## 自动执行

- `/usr/local/lib/test1/release_retention.py` 安装已提交的脚本，避免工具随旧版本一起删除。
- `test1-release-prune.path` 观察 `/srv/test1` 的目录变更，版本链接切换后触发清理。
- 新版本必须在验收成功后写入 `deployment-manifest.json` 的 `activatedAt`；服务最多等待 180 秒，并要求成功标记至少稳定 30 秒。
- `test1-release-prune.timer` 每日及开机后补查。部署验收完成后也可执行 `sudo systemctl start test1-release-prune.service`。
- systemd 的状态目录 `/var/lib/test1-release-retention` 保存互斥锁和最近一次报告；日志可用 `journalctl -u test1-release-prune.service` 检查。
- 新构建目录尚未通过验证时保留。失败构建需要人工查明原因后单独清理，不能伪造成功标记以让自动清理处理。

安装或更新：将脚本安装为 root 所有、0644，将 `infra/systemd/test1-release-prune.{service,path,timer}` 安装到 `/etc/systemd/system`，执行 `systemd-analyze verify`、`systemctl daemon-reload` 和 `systemctl enable --now test1-release-prune.path test1-release-prune.timer`。工具更新不需要重启网站服务。

## 预览与检查

```sh
sudo python3 /usr/local/lib/test1/release_retention.py
sudo systemctl start test1-release-prune.service
sudo cat /var/lib/test1-release-retention/last-run.json
df -h /
```

预览会输出计划指纹；人工执行时可用 `--apply --expected-plan=<fingerprint>` 防止审查后状态改变。

## 容量统计口径

版本依赖存在硬链接。不要分别统计每个版本后相加；对整个 `releases` 目录一次性运行 `du`，让同一 inode 只计一次。删除某个硬链接不一定释放其文件数据，以清理前后的 `df` 为最终实际释放空间。

服务器系统盘包含 Ubuntu、Node、2 GiB 交换文件、网站的保留版本、构建临时空间、缓存和日志。数据库位于 MongoDB Atlas，导入小说正文和新封面位于 Cloudflare R2；它们的外部存储容量不包含在 VPS 系统盘统计中。容量估算必须留出新版本构建、系统更新和日志增长空间，不能把静态运行占用当作磁盘采购下限。

## 2026-09-12 执行结果

- 清理 47 个历史版本，保留 `catalog-smooth-3f47883`（当前）、`catalog-volumes-9ef1ea6`、`catalog-duration-d7d3794`。
- 实际释放 34,138,808,320 字节，约 31.79 GiB；根分区占用降至约 5.77 GiB，剩余约 31.92 GiB。
- 三个保留版本合计实际占用约 1.21 GiB，网站目录连同备份约 1.33 GiB；交换文件约 2 GiB，其余为系统、运行环境和日志等。
- 580 项保留源码、构建标识、备份和配置文件的哈希与清理前一致。API 和前端进程 PID 未变化，三个版本的 Next 入口和 R2 后端模块检查通过。
- 清理服务、path 和每日 timer 已安装；在不切换网站的情况下，通过目录变更实际触发了 path 清理并验证成功。
- 公网《情花孽》在手机和电脑视口、详情和正文入口的四组目录与阅读检查通过；目录连续展开收起无加载中断、无重复请求，正文和阅读位置恢复正常。
- 按当前架构和规模估算，10 GiB 可作为最低配置参考，建议至少 20 GiB 留出构建、依赖升级、系统更新和缓存空间；当前 40 GiB 硬盘充足。此估算不包含 Atlas 和 R2 的外部存储需求，也不是未来业务增长的固定上限。
