# 书库清洗

采集原始响应与检查点保留证据，`downloads` 保存供阅读、上传的清理版本。HTML、TXT、EPUB、阅读版续更和导入前校验共用 `shared/reading-cleanup.mjs`。纯文本清理在本机运行，不为每章增加网络请求或模型调用。

规则只删除已核实的整行广告、已核实来源的独立冒号、正文开头的重复页头及结尾导航。夹在正文中的已确认水印按精确片段删除，保留两侧文字。保留正文段落、作者附言、短章和原章序；删除比例异常或清理后为空时保留原文并报告。章节上的 `readingCleanup` 保存规则版本、原始正文哈希、阅读正文哈希和删除原因；续更核对仍使用受导出哈希保护的原文指纹。重复执行结果不再改变。

## 按网站调查与规则维护

`shared/source-noise.mjs` 保存有实据的站点模板；按每章 `link` / `sourceUrl` 判断来源，不能只看书籍目前绑定的网站。正文中保留旧站转载水印的情况也按实际采集来源限定。匹配时可折叠全角字符、空白和模板插入符，幸存正文不做这种归一化。

新增规则先跨书扫描重复短句、网址残留和章节首尾，再抽取不同书籍的首、中、末章，对照原始 HTML、分页与实际 TXT / ZIP 下载路径。原始响应保留哈希和采集时间；人机验证、历史缓存与当天实查分别记录。高频重复仅生成候选，不能自动把音效、分隔线、作者月票活动或小说中的网址当成广告。

2026-09-30 专项覆盖 21 个已配置站点、原书库 17 个实际来源。新增模板主要来自得奇、速读谷、爱下电子书、小说集、努努书坊、友友小说、四季文学及八零奇书。包括混淆域名、搜索推广、转载提示、下载版嵌入水印和残缺的广告标记。69 书吧、台湾小说网及第一版主网实时取样受人机验证限制；前两站另查留存原始页，第一版主网无可用历史正文，不能视为已完成正文实查。详细证据位于 `.runtime/task-artifacts/source-noise-audit-20260930/`。

阅读清理版本为 2，仍校验并接受版本 1 的原文指纹。二次清理延续原始 `sourceHash`，累积删除记录，逐次报告只计本轮变化。不改变原始提取规则或采集检查点，已有采集、TXT/EPUB 导出及阅读版续更通过同一入口自动使用新规则。规则在本地执行，不新增逐章请求；本次 2,580 章采样每章约 0.12 毫秒，比旧版增加约 0.05 毫秒（纯文本处理，不含磁盘和网络）。

TXT 的 `sourceSection` 转为 `volume_title` / `volume_number`。HTML 适配可显式配置 `catalog.volumeSelector`，按 DOM 顺序读取卷头；分页延续上一卷，相同卷名的独立卷头保留为不同卷组。这个选项不能与目录倒序、重排序或逐章追踪混用。需要先核实来源卷头，再更新适配与既有绑定；没有证据时不推测分卷。

## 历史本地书库

库存 JSON 为数组或 `{ "books": [{ "file": "书籍文件名.json" }] }`；只列出正式阅读版本，不包含旧源保留版和报告。

```powershell
node --require D:/Apps/Codex/home/tools/windows-hide.cjs --require ./tools/test-env.cjs tools/novel-crawler/clean-library.mjs --inventory=库存.json --report-dir=.runtime/task-artifacts/本次任务/local
# 核对逐章预览后，在同一命令末尾加 --apply。
```

写回前获得现有按书锁，创建固定保留的压缩去重快照。导出文件、对应的阅读版和续更绑定通过带校验的恢复日志一并更新。原始采集检查点不修改；正在采集、绑定不一致或文件发生并发修改时保留原版。中断后使用相同参数重试。恢复旧版使用现有 `tools/storage-snapshots.cjs` 的 restore 功能，先恢复到项目内隔离目录核对，不直接覆盖正在使用的书库。

`applied-summary.json` 与逐书报告应长期保留。分批清理同一本书时，用 `mergeCleaningReports` 合并经过连续哈希验证的报告，才能保留线上清理前的基线。不能用后一次“无变化”报告覆盖第一次修订证据。

## 修订网站现有章节

先部署修订工具与服务，再使用已执行的本地报告：

```powershell
node --require D:/Apps/Codex/home/tools/windows-hide.cjs --require ./tools/test-env.cjs infra/sync-cleaned-library.mjs --summary=本地/applied-summary.json --report-dir=.runtime/task-artifacts/本次任务/online --run-id=reading-cleanup-YYYYMMDD
# 核对预览后，在同一命令末尾加 --apply。
```

工具通过现有 SSH 身份运行服务器工作进程，不暴露新的公开写入接口。逐书核对身份，逐章核对 ID、原文哈希、卷信息与书籍版本。缺少的线上章节单列，不趁清理新增。正文先写入不可变 R2 对象并回读，再在事务中修订原记录，更新书籍内容版本，保持章节 ID、章序和发表时间。卷信息单独变化时复用正文对象。

### 维护读取量与效率

2026-09-30 起，同步前后默认只按本次报告的章号读取资料，利用现有 `(bookId, chapter_number)` 索引；核对只返回身份、原文哈希和卷信息需要的字段。遗漏、已删除、已修订和原文已变化的章节继续分别处理。单书报告超过 50,000 章时保留完整核对路径；直接调用工作进程 `inspect` 而不传 `numbers` 仍可做整本审计。

每批写入继续校验书籍版本、原文哈希和身份，先生成并回读完整恢复记录，再上传正文并回读、进入事务二次校验与批量更新。事务内只省去不参与校验的对象键等字段，恢复记录的字段不减少。最终检查必须匹配最后一个成功批次的书籍版本，并核对全部目标章的身份、正文哈希和卷信息。其他写入者改动未选中的章节也会推进书籍版本，导致本次核对停止；重试会重新查询已成功的目标章并原样跳过，不从缓存猜测成功。

工作进程为每次返回及已捕获的失败附上 `databaseUsage`，同步摘要保存该连接从启动以来的累计命令数、失败数和估算 BSON 回复字节，不能把多份累计收据相加。连接异常而未收到最终计数时标记 `incomplete`；不支持命令事件的数据库标记 `unavailable`。只记录数值，不记录正文、查询或账号。该数字不含 TLS、心跳、复制与 R2 读写，不能直接作为 Atlas 账单。

本地 MongoDB 7.0.40 副本集以同一批 2,000 章和正常结构的书籍统计资料进行三轮交替对照（R2 写入模拟，新版包含计数开销）：改 20 章的回复字节从约 1.61 MB 降至 0.026 MB，减少 98.4%；改全部 2,000 章从约 3.22 MB 降至 2.21 MB，减少 31.3%；已成功的 20 章重试减少 99.3%。中位数据库流程耗时分别从约 53/341/40 ms 变为 20/311/7 ms，没有增加命令数；最终全部章节和恢复记录与旧版一致。真实维护仍包含网络和 R2 耗时，不能把这些比例视为整站降幅。详细材料保存在 `.runtime/task-artifacts/maintenance-egress-20260930/`。

如果线上已单独改过书名，先核实来源、作者和对应作品，再配合 `--file=书籍文件名.json --online-title=已核实的线上书名` 处理单本。此选项保留现有线上书名，不修改本地命名，其他身份、章节和原文哈希保护照常执行；不能用于整库覆盖书名。

段落评论在修订前后按段落文本及标识核对；无法定位或落在删除内容上的评论会阻止该批修订。新增评论与修订使用同一个书籍写锁。书架、书签、阅读进度、章节评论继续引用原 ID。

恢复记录写入服务器 `/srv/test1/backups/reading-cleanup/<run-id>/` 并回读校验，旧 R2 对象不删除。批次收据保留恢复文件路径。回滚某批使用 `infra/sync-cleaned-library.mjs --restore=<收据中的backupFile> --apply`，先回滚较新的批次；若当前正文或评论又发生变化则停止，避免覆盖新内容。线上未成功的批次可以重试，已成功的原样跳过。

## 需独立复核的问题

章号回退、目录与页头不同、缺文、占位提示、乱码、疑似重复只进入问题清单。真实重排或补文需完整目录、链接身份及正文证据；禁止单按章号排序、删除短章、拼接不同版本或生成缺文。已确认的冒号断段不能仅凭标点推测合并。
