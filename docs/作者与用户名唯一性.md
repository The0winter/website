# 作者归并与注册 ID

导入作者与登录账号保持独立。同一规范化署名（Unicode NFKC、去除首尾空白、连续空白合一）使用同一 `Author.identityKey`，不再按每本书的来源链接拆分。未知、佚名等非实名署名仍按来源区分。来源键继续留存，作者名变更仍拒绝自动认领。

历史重复档案保留原 ID，通过 `mergedInto` 指向统一档案；旧作者链接仍显示完整作品。归并只调整书籍的作者引用，不改书籍、章节 ID，也不改变账号归属、书架和阅读进度。作者页继续过滤私密及下架作品，并先全量排序再分页。

注册用户名作为 ID 永久占用。规范化方式为 NFKC、清理空白、大小写不敏感；`UsernameReservation` 以规范化名称的 SHA-256 为主键，不设置 TTL，不随账号删除。已有大小写或全角变体账号保留原名和登录方式，但阻止未来再次注册这些 ID。注册事务同时保留 ID、创建账号并消费验证码，失败不占用新名称；并发竞争由数据库主键裁决。

上线前，停止 API/导入写入，以当前服务器配置运行：

```text
node server/migrations/identities.js
node server/migrations/identities.js --apply --backup=/srv/test1/backups/<本次目录>/identities.json
```

先预览再执行。执行前保存作者档案和书籍作者引用，建立唯一索引，在一个事务内归并作者及补齐已有用户名占用记录。重复执行不再次改写已完成的数据。备份只用于受控恢复作者归属，不能用来覆盖之后新增的业务数据；用户名占用记录始终保留。旧代码不识别作者别名和永久占用规则，回滚版本须包含这两个兼容改动，或先在停写期间核对并恢复原作者引用。

验证：`server/tests/identity.test.js` 支持 SQLite 与 `TEST_DATABASE_BACKEND=mongodb`，覆盖归并、旧链接、分页/权限、匿名署名、两个导入入口、ID 占用与并发事务。`web-next/tests/author-identity.spec.ts` 覆盖 320、390、1440 像素下作者列表与重复注册提示，线上运行自动屏蔽 GA。
