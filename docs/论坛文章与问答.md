# 论坛文章与问答

问题使用 `ForumPost(type=question)`，通过 `bookId` 关联一本书；每篇长回答使用独立的 `ForumReply`。论坛和书籍详情共用回答卡片，点击文章标题进入全文，点击问题标题进入回答列表。独立文章继续使用 `ForumPost(type=article)`，其 replies 为评论，不进入回答推荐流。

- 论坛回答流：`GET /api/forum/posts?view=answers&tab=recommend&page=1`。
- 书籍讨论：`GET /api/books/:id/discussions?page=1`，返回 `items`、`total`、`pageSize`。旧 articles 接口保留。
- 卡片 `id` 是问题或文章 ID，`entryId` 是独立卡片 ID，回答位于 `topReply`。同一个问题可以出现多篇回答，前端不得仅用问题 ID 作为列表 key。
- 回答地址：`/forum/:answerId?fromQuestion=:questionId`。回答必须属于该问题，页面 metadata 同样验证这一关系。
- 问题地址：`/forum/question/:questionId`；独立文章地址：`/forum/:postId`。

收录回答有可选 `title` 与 `source`（原题、原作者、链接、许可、许可链接、原文发布时间）。原作者显示为资料署名，不创建冒充作者的可登录账号。普通发布接口不能写入这些来源字段。文章正文继续经服务端 HTML 白名单过滤，列表使用独立的纯文本摘要。

白色主题的 CSS 限定在 `.forum-page`、`.forum-reading`、`.forum-surface`，书籍详情仅在文章讨论区域启用。不要改全局 `--home-*` 变量，以免影响精选与书架。

## 本地全文样本

2026-09-29 的五篇《三体》书评保存在 `.runtime/task-artifacts/forum-articles-20260929/articles.json`；同目录 README、原网页和正文哈希记录来源许可与完整性。素材不提交 Git、不随代码发布。

`server/dev.js` 接受可选环境变量 `FORUM_FIXTURE_FILE`，启动时向自己的隔离数据库导入该清单。默认开发数据仍可单独使用。示例环境变量：

```powershell
$env:FORUM_FIXTURE_FILE = (Resolve-Path '.runtime/task-artifacts/forum-articles-20260929/articles.json').Path
```

然后以 Node 24 运行根目录 `dev:isolated`。Windows 后台启动必须预加载 `D:/Apps/Codex/home/tools/windows-hide.cjs`，并通过隐藏进程启动 npm CLI，子进程继承同一 Node 24 PATH；测试先加载 `tools/test-env.cjs`。日志放在上述任务目录，不打开终端窗口。

本地服务为 `http://127.0.0.1:3000`，API 为 `http://127.0.0.1:5000`。测试读者：`reader@example.test / Local-test-12345`。这些账号只存在于本地隔离数据库。

导入器校验正文哈希、HTML 清理结果及来源字段，仅接受项目 `.runtime/test-tmp/` 内的 SQLite 数据库和 development/test 模式。相同清单可重复导入，不重置赞同或评论。重新启动隔离服务会创建新的测试库；原始素材清单始终保留。

生产构建也可在本地验收：先使用本地 API 地址、关闭外部服务的配置运行根目录 `build`，然后设 `LOCAL_PREVIEW_MODE=production` 启动 `dev:isolated`。这只切换本地 Next.js 启动方式，不连接生产数据库、不部署。

## 公开收录

用户明确要求发布后，另存清单，设置 `usage: public-licensed-reviews`，并将书籍简介改成面向读者的正式资料。使用 `server/migrations/forum-articles.js FILE` 在现有服务环境中预览；预览提供数据库 `target` 指纹。传入 `--apply --target=指纹 --audit=新的审计文件路径` 执行，多个管理员时用 `--admin=用户名` 指定整理人。

该入口保留本地测试导入器的隔离限制，不搬运测试账号。使用现有管理员作为资料整理人，显示原文署名和许可；书籍作者关联资料档案。同名同作者的公开书会复用，私密书、重复身份或已经改动的回答会停止导入。写入在一个事务内完成，只新增缺少的内容，重复执行保留用户点赞与评论。清单和审计文件留在运行数据目录，不提交 Git。
