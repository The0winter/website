# 论坛文章与问答

问题使用 `ForumPost(type=question)`，通过 `bookId` 关联一本书；每篇长回答使用独立的 `ForumReply`。论坛和书籍详情共用回答卡片，仅显示问题标题、回答者与正文摘要，点击进入完整回答。独立文章继续使用 `ForumPost(type=article)`，其 replies 为评论，不进入回答推荐流。

- 论坛回答流：`GET /api/forum/posts?view=answers&tab=recommend&page=1`。
- 书籍讨论：`GET /api/books/:id/discussions?page=1`，返回 `items`、`total`、`pageSize`。旧 articles 接口保留。
- 卡片 `id` 是问题或文章 ID，`entryId` 是独立卡片 ID，回答位于 `topReply`。同一个问题可以出现多篇回答，前端不得仅用问题 ID 作为列表 key。
- 回答地址：`/forum/:answerId?fromQuestion=:questionId`。回答必须属于该问题，页面 metadata 同样验证这一关系。
- 问题地址：`/forum/question/:questionId`；独立文章地址：`/forum/:postId`。

收录回答有可选 `title` 与 `source`（原题、原作者、链接、许可、许可链接、原文发布时间）。原作者显示为资料署名，不创建冒充作者的可登录账号。普通发布接口不能写入这些来源字段。文章正文继续经服务端 HTML 白名单过滤，列表使用独立的纯文本摘要。

白色主题的 CSS 限定在 `.forum-page`、`.forum-reading`、`.forum-surface`，书籍详情仅在文章讨论区域启用。不要改全局 `--home-*` 变量，以免影响精选与书架。

## 连续回答阅读

问题页与回答深链接共用 `ForumAnswerReader`：问题下直接接回答者及全文，不展示独立回答标题、书籍作者行或正文前的赞同统计。深链接选中的回答置顶，其余回答沿用接口的赞同顺序，每页 20 条向下追加并按回答 ID 去重；加载失败保留已读内容并提供重试。

移动端默认正文 18px、1.75 倍行高、16px 横向留白。底栏的赞同、评论与分享绑定当前阅读的回答；评论浮层关闭后保持位置。阅读进度按入口保存在会话中，返回或刷新时恢复已加载页及回答内位置；写回答只填写正文，草稿按用户及问题暂存。全部回答面板提供作者、摘要、问题补充及相关书籍入口。桌面保留独立导航侧栏与适合长文的阅读宽度。

原回答 `title` 与 `source` 数据保留，来源与许可显示在每篇正文末尾。独立文章仍沿用原有文章页面。写入接口返回存储文档，读取接口返回展示字段，前端发布后按当前登录作者转换，不能直接将写入结果当成展示 DTO。

新增浏览器验证：`forum-continuous.spec.ts`，覆盖 320/390/1440px、连续全文、当前回答操作、主题与字号、阅读恢复、超过 20 条的分页去重与失败重试、无标题编辑器和草稿。生产只运行该文件的三个只读布局用例，设置 `QA_TEST_BASE=https://jiutianxiaoshuo.com`；统计脚本及问答阅读计数均在导航前隔离。

## 公开收录

用户明确要求发布后，另存清单，设置 `usage: public-licensed-reviews`，并将书籍简介改成面向读者的正式资料。使用 `server/migrations/forum-articles.js FILE` 在现有服务环境中预览；预览提供数据库 `target` 指纹。传入 `--apply --target=指纹 --audit=新的审计文件路径` 执行，多个管理员时用 `--admin=用户名` 指定整理人。

该入口保留本地测试导入器的隔离限制，不搬运测试账号。使用现有管理员作为资料整理人，显示原文署名和许可；书籍作者关联资料档案。同名同作者的公开书会复用，私密书、重复身份或已经改动的回答会停止导入。写入在一个事务内完成，只新增缺少的内容，重复执行保留用户点赞与评论。清单和审计文件留在运行数据目录，不提交 Git。

用户提供并要求公开的采集书评使用 `usage: public-collected-reviews`。须先按书名和作者核对已有公开作品，在 `book.id` 写入该作品编号；导入器同时核对编号、书名和作者，不会为未匹配项自动新建书籍。保留原文、原作者和原文链接；资料没有许可或发布日期时省略对应字段，不编造许可或时间。已有许可收录流程仍要求原许可完整。两种清单都沿用正文哈希、事务、审计和重复执行保护。

## 本地书评清理与上传

书评整理先复用本地原文和已保存的线上快照，在本地生成清理版与逐条差异；上传前只核对目标记录的身份和正文指纹。原始采集批次保留，清理版发布后更新本地发布索引。原文、网页取证、清单及回滚审计都是运行数据，不提交 Git。

- `tools/review-cleanup.mjs` 提供按来源清理及安全排版；`shared/review-quality.mjs` 检查错误页、脚本、标签残片、页面操作、未解码实体、核验备注及疑似定长截断。遇到完整正文恰好等于常见截断长度且句末无标点时，须核实并提供 `evidence.complete: true`，或改为节选；不自动补写。导入器同时检查本批次与该书已有收录中的重复正文和来源。
- 采集导入必须设置 `source.kind`：`original` 为原文、`excerpt` 为节选、`guide` 为整理者导读。导读显示整理者署名，原作者保留在参考来源；核验片段不能作为完整原文。
- `server/services/forum-cleanup.js` 只接受已在本地准备的清理清单。默认预览，应用前检查全部目标身份与原文指纹，并写入逐条原文备份；分批事务内再次检查，失败可依据同一清单续跑。更新仅涉及正文、来源及整理状态，不改 ID、时间、点赞、评论和书籍关联。
- `curation.status=withheld` 暂停正常展示，直接链接显示待核对提示；`duplicate` 只从推荐及普通回答列表移除，原链接与互动记录仍可访问。主条目保留其他来源署名和链接。撤下和重复项不进入回答计数。
- 原文恢复必须来自已核验的本地资料或精确的来源正文节点；无法核实的内容保留为节选、导读或待核对项。清理脚本不得把核验备注或访问错误页当成正文，也不得编造缺失内容。
