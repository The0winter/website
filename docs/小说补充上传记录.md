## 2026-10-02 · 批量上传经验

本次新增 104 本书、补齐 128 张封面，原有 413 张封面保持不变。从批量脚本启动到最终核验约 61 分钟（前期盘点另计），其中书籍上传及修复约 36 分钟，封面及收尾约 25 分钟。主要额外耗时：长章节修复漏测实际批量入口，造成两次部署；封面逐本预览、执行反复建立 SSH 连接，初始并发偏低。

下次执行要点：

1. **先统一预检。** 一次取得本地与线上清单，按书籍身份、作者、历史别名和来源去重；检查最长章节字符数、UTF-8 字节数、分批体积、图片格式与比例，保存固定任务清单及原始线上基线。
2. **测到实际入口。** 长章节检查覆盖 `missingOnly` 使用的 `server/routes/library-import.js`、普通导入、模型校验和 R2 读写；限额以 `shared/chapter-limits.mjs` 为准。合成数据测试通过后集中发布，再核验线上实际路径，避免只改到一个入口。
3. **复用通用工具与连接。** 书籍复用 `infra/library-sync-session.mjs` 持久会话；封面统一用 `infra/upload-cover.mjs --missing-only`，比例不符时按需加 `--fit=contain`。封面 CLI 当前仍是单书命令，批量预览及连接、进程复用属于后续通用工具优化，尚未实现。
4. **并发和续跑提前安排。** 根据内存、负载与错误率小批试跑后确定有界并发（本次封面后期为 4），使用互不重叠的任务分配与共享检查点；只重试失败项，返回结果不明时先核对线上绑定及哈希，避免重复写入。
5. **完整校验只做必要次数。** 脚本保存章节编号、标题、正文哈希、封面绑定与公网核验结果；同一内容及版本已有有效证据就复用，收尾统一核对缺项和原有数据保护情况。模型只处理摘要及异常，不以提速省略质量检查。
6. **按变更范围收尾。** 常规补书、补封面沿用现有接口；纯数据操作和本地上传工具改动无需部署网站。确需修复服务端时集中修改、测试和发布，保留兼容回滚版本，避免无关构建与重复部署。
