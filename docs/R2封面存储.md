# R2 书籍封面

## 使用

进入网站的创作中心，打开作品的「管理」→「书籍信息设置」，点击封面区域选择图片。管理员可以在全站作品列表搜索并管理导入的书籍。

支持 8 MB 以内的 JPG、PNG、WebP，裁剪框固定 3:4。点击「确定」后自动上传并保存；新建作品时，先上传预览，再点击「立即创建」。更换失败时原封面保持不变。移除或更换后，旧封面无引用满 7 天会自动从 R2 删除。

Cloudflare 控制台手动上传的图片不会自动关联书籍。使用网站上传或下面的统一运维命令，可自动完成压缩、建立归属和保存地址。

## 统一上传命令

后续所有封面共用 `infra/upload-cover.mjs`，不要再按书名新建上传、绑定或 SSH 脚本。

```powershell
# 预览：核对书名、作者、现有封面和压缩尺寸，不写数据库或 R2
node infra/upload-cover.mjs --book=妖颜 --author=江阔云低 --image="F:/Website/Cover/妖颜.png"

# 上传、绑定并验收；同图重复执行会校验后跳过写入
node infra/upload-cover.mjs --book=妖颜 --author=江阔云低 --image="F:/Website/Cover/妖颜.png" --apply
```

也可使用 `--book-id=书籍ID` 代替 `--book`。同名作品必须用作者或 ID 消歧；存在多个管理员时用 `--admin=用户名` 指定现有管理员。图片需为 8 MB 以内的静态 JPG、PNG 或 WebP、3:4 比例；命令保留构图，不自动裁切。

默认连接现有 VPS 和网站；`--host`、`--identity`、`--site` 可显式指定目标。命令通过 SSH 标准输入执行，在当前线上版本中复用 `prepareCover`、R2 存储服务、`lockBook` 和 `claimMedia`。MongoDB 与 R2 凭据从服务器环境文件加载，不下载至本地，不创建新管理员或会话。

命令会检查维护状态，先验证上传后的公网图片，再用数据库事务登记媒体归属和绑定书籍。书籍身份或封面发生并发变化时停止绑定；失败上传的对象位置保留在审计记录中。更换成功后，已无引用的旧封面开始 7 天保留期。同一张图已绑定时不会再次上传或增加书籍版本。

每次只生成 `.runtime/cover-uploads/*.json` 结果记录；实际更换另在服务器 `/srv/test1/import-runs/cover-*.json` 保存前后地址及校验值。没有任何逐封面生成的脚本。此工具从本地运行，不需要发布或重启网站服务。

## 存储与加载

- `POST /api/upload/cover?purpose=book`：原有会话认证和 CSRF 校验，限制每分钟 10 次、最多同时处理两张图片。
- 浏览器裁剪并缩小至最多 1400 像素宽；服务端验证图片字节、静态格式和 1600 万像素上限，再生成 240 与 480 像素宽的 WebP。原始大图不保存到数据库或 R2。
- 图片写入专用桶 `jiutian-covers` 的 `covers/<唯一媒体ID>/240.webp`、`480.webp`；每次更换使用新 ID。写入后读取并校验 SHA-256，再向客户端返回成功。
- 公共地址以 `https://img.jiutianxiaoshuo.com` 开头，设置 `Cache-Control: public, max-age=31536000, immutable`。列表与详情使用 `srcset` 选择尺寸，重点封面优先加载，其余懒加载；失败时显示占位图。
- MongoDB 的 Media 记录只保留归属、地址、尺寸和校验值。书籍只接受当前用户拥有的完整已登记地址，管理员可为任意书籍上传自己的新封面。旧 MongoDB 封面和头像仍可使用。
- 移除图片会检查所有书籍和头像引用。书籍解除或更换封面与 `unreferencedSince` 时间一起事务提交，不依赖浏览器补发删除请求。重新绑定会清空计时；最后一个引用解除后重新计满 7 天。已下架但可恢复的书籍也算引用。
- 每小时清理一次：无引用满 7 天后，在下一轮执行中删除该媒体 ID 的 `240.webp` 和 `480.webp`，并通过 R2 `HEAD` 核验对象不存在。删除事务先锁定媒体并提交禁止再绑定的标记，避免并发误删；网络错误保留待清理状态，下次重试，不误报完成。
- 上线前已有、缺少无引用时间的媒体，从清理程序首次检查时开始计满 7 天，不使用创建或修改时间倒推。没有 Media 记录的未知 R2 对象不自动删除，仍需根据上传审计单独核实。MongoDB 媒体记录保留为审计信息，不物理删除书籍或头像数据。
- R2 文件删除不等于立即清除浏览器或 Cloudflare 已缓存的图片；网站立即解除封面显示，存储释放以 R2 对象检查为准。

## 自动清理运维

`infra/clean-unused-covers.mjs` 默认只预览；`--apply` 才登记保留期和执行到期清理。仅操作已登记在当前专用封面桶的对象，不碰章节桶或未登记对象。实际执行要求当前版本已验收、API 健康且 `WRITE_MODE=readwrite`。

安装 `infra/systemd/test1-cover-cleanup.{service,timer}` 至 `/etc/systemd/system`，执行 `systemd-analyze verify`、`systemctl daemon-reload` 和 `systemctl enable --now test1-cover-cleanup.timer`。服务使用 `test1-api` 账户和服务器现有环境配置，以文件锁避免重叠运行；每小时执行，最多随机延迟 5 分钟。回滚到不包含清理工具的旧版本会自动跳过。

```sh
# 只读预览
sudo /opt/node-v22.23.2-linux-x64/bin/node --env-file=/etc/test1/api.env /srv/test1/current/infra/clean-unused-covers.mjs
# 执行一轮；首次上线将历史残留登记为等待 7 天
sudo systemctl start test1-cover-cleanup.service
sudo cat /var/lib/test1-cover-cleanup/last-run.json
journalctl -u test1-cover-cleanup.service
```

每轮最多处理 500 条需要检查的记录；报告的 `hasMore` 表示尚有待处理记录。R2 失败会令服务失败并留下失败 ID 和待重试标记，下轮仍会检查引用再重试。

R2 多个桶共享同一账户的免费额度，单独建桶用于隔离封面和章节，不会额外获得一份 R2 免费额度。

## 服务器配置

配置项见 `infra/systemd/api.env.example` 的 `COVER_*`。凭据只授予封面桶的对象读写权限，不复用正文桶凭据，禁止放入 `NEXT_PUBLIC_*` 或 Git。

将真实值保存到 Git 忽略的本地 env 文件，设置 `COVER_STORAGE=r2`，运行：

```powershell
node infra/configure-cover-r2-vps.mjs .runtime/cover-r2.env
```

脚本通过 SSH 标准输入写入 `/etc/test1/api.env`，备份旧配置并保留章节和其他设置，文件权限为 0600；不会打印凭据或重启服务。随已验证的新版本部署后重启 API。Nginx 封面上传位置需要 9 MB 请求上限和 90 秒读取超时，应用仍限制文件为 8 MB。

回滚应保留新增配置和 R2 对象，使用仍支持 R2 封面 URL 的兼容版本；移除数据库数据不属于常规代码回滚。

## 验证

```powershell
node --test server/tests/cover-retention.test.js server/tests/upload-cover.test.js server/tests/cover-storage.test.js server/tests/security.test.js
cd web-next
npm run typecheck
npx playwright test covers.spec.ts
```

浏览器测试默认使用合成开发站点 `http://127.0.0.1:3000`，可用 `COVER_TEST_BASE_URL` 指定其他本地端口。它不会操作生产数据库；测试 R2 时需另行在合成开发 API 环境配置专用封面桶。

Cloudflare 参考：[公开桶及缓存](https://developers.cloudflare.com/r2/buckets/public-buckets/)、[免费额度与计费](https://developers.cloudflare.com/r2/pricing/)。
