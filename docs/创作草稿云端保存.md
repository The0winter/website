# 创作草稿云端保存

创作中心以账号的云端草稿为正式版本。正文使用现有私有 R2 正文桶中的 `drafts/<owner>/<uuid>.txt`，Atlas 的 `writerdrafts` 仅保存归属、作品、章节编号、版本、字数、对象引用和校验摘要。草稿箱先获取元数据，打开章节时再读取正文，避免每次打开草稿箱下载所有正文。

## 保存与恢复

- 页面打开期间每 60 秒同步有改动的草稿；无变化不发保存请求。手动保存、返回草稿箱、页面转入后台和发布前立即同步。
- 每 2 秒在浏览器暂存未同步文字用于断网恢复，这一步不访问云存储。只有服务器确认保存后显示“已保存到线上”。同步失败保留文字并提示，不能假报成功。
- 已有本地草稿在对应作品打开后逐批同步，每分钟最多处理 10 份历史待同步草稿；进入章节点保存可立即同步。尚未同步的旧草稿仍依赖原浏览器，不能提前清除网站数据。
- 按账号与作品隔离。多标签页保留本地版本检查，多设备增加服务器版本检查；旧版本冲突时保留当前输入并提示下载备份核对，不覆盖云端新版本。
- 已发布正文也通过 R2 适配器写入内容摘要路径，Atlas 保留索引。现有内联正文继续兼容读取。

## 每日新增额度

使用账号的 `uploadDay`、`daily_upload_words`，北京时间每日零点划分日期。草稿新增限制对所有创作账号生效，包括管理员；原有导入接口的行为不在此修改范围。

服务器比较上次接受的正文，按 Unicode 码点累计新增的字符；标点、空白也计入。原文不变记 0，删除记 0 且不退已用额度，等长替换按插入部分计入。所有作品与设备共享每天 100,000 字额度。打开已发布章节修改时以原正文为基准，避免重复计算已有正文。差异比较有时间上限，极大范围且复杂的修改会提示分段保存，不能静默按错误字数扣费。

保存和额度更新在同一数据库事务中完成；账号写锁串行化并发请求。相同内容的重试不重复扣额或写 R2，发布已计额草稿不重复扣额。删除草稿或未发布作品都不会返还当天额度。

## 文件生命周期

每个新草稿版本使用独立对象路径，上传失败、数据库冲突和事务回滚不会改写原文件。`writerblobs` 是持久化回收队列，不能使用 TTL 直接删除回收记录。

成功保存后旧对象延迟 5 分钟回收；未提交上传延迟 1 小时处理。API 每分钟领取最多 200 条到期记录，删除前再次确认没有草稿引用。失败留在队列重试，重启后继续处理。发布使用独立的正式章节路径，回收草稿对象不会删除已发布正文。此流程不承诺长期历史版本或额外独立备份。

## 发布检查

新增集合上线前使用 `createIndexes` 创建 `_id` 和声明的查询索引，不执行 `syncIndexes`，不删除现有索引或业务记录。沿用当前已上线的 R2 章节读取适配、配置和兼容版本，再启用新 API 与前端。

`server/tests/writing-workspace.test.js` 覆盖权限、版本、累计额度、删除不退款、并发、跨日、对象故障和发布回收；`server/tests/writing-r2-live.mjs` 使用一次性本地数据库和唯一 R2 测试对象核对真实读写，结束清理。浏览器检查包含一分钟定时、空闲无写入、旧稿迁移、多设备恢复/冲突和移动端原生返回回归。
