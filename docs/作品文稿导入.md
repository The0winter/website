# 创建作品与文稿导入

新建作品以现成文稿为主要入口：填写书名（15 个 Unicode 字符以内）、简介（300 字符以内），可选封面与分类，再上传文稿、直接粘贴或直接码字。资料不完整时可保存草稿；提交需有简介与完整章节，并确认检查过预览。草稿仅本人可见，可在作品管理继续整理或删除。

## 文稿格式

- 接受 TXT、DOC、DOCX，单个文件不超过 10 MB；TXT 自动识别 UTF-8、带 BOM 的 UTF-16，以及 GB18030/GBK，并允许手动选择编码。
- 章标题须单独成行，如 `第一章 初遇`、`第2章 来信`；保持原稿顺序，提示重复、跳号与倒序，不自动改排正文。首章前文字保留为前言，未识别到标题时保留为一章。
- Word 提取普通正文；字体、图片、页眉页脚、文本框与自动编号不作为正文导入。示例和下载入口在表单中。
- 单次最多 200 万字符、2000 章；章节标题最多 100 字符、正文最多 60000 字符。可在预览中修改、删除和添加章节。
- 沿用原有普通账户每日 10 万字符提交额度；草稿不扣额度，超过余额时显示原因。管理员沿用原有豁免规则。

## 保存与提交

`/api/manuscripts/parse` 仅解析，不创建公开作品。`/api/manuscripts` 列出本人作品草稿及剩余额度；`/:key` 读取、保存或删除草稿。所有入口要求登录，写操作沿用同源与 CSRF 校验。

正文通过限制大小的 multipart 字段传递。DOC/DOCX 在有内存限制与超时的 Worker 中提取，最多同时解析两份文稿。保存采用版本号检查，重复请求复用结果；提交在同一 MongoDB 事务中创建书籍和全部章节、扣额度并保存回执，失败不留下半本作品。作品草稿封面计入现有封面引用保护。

部署需为 `Manuscript` 新集合建立索引，并在现有 nginx 配置中仅增加 `/api/manuscripts` 的 11 MB 请求上限与 90 秒代理超时，保留其他线上配置。无需改写已有书籍、章节或数据库数据。

## 验证

- `node --test server/tests/manuscript.test.js server/tests/manuscript-routes.test.js`：真实 DOC/DOCX、中文编码、格式异常、权限、版本冲突、封面引用、限额、事务与并发重试。
- `web-next/tests/manuscript-creator.spec.ts`：连接隔离的测试 API 与测试账号，验证 320/390/1440 像素下的导入、预览修正、草稿恢复、发布与失败重试。
- `web-next/tests/mobile-creation.spec.ts`：原有创作中心、弹层、返回和保留页面的回归检查。
