# 评分与文字评论

每位登录读者对每本书保留一条 `Review`，`book + user` 唯一。内部评分为 1–5 整数星，前端显示 2–10 分。短评可为空；修改评分更新原记录，不增加人数。提交时省略 `content` 保留原短评，显式传空字符串清除本人短评、保留评分。

`Book.numRatings` 是真实评分人数，`Book.numReviews` 是非空文字评论数。评论分页只返回带文字的记录，所有真实评分参与平均分。个人评分接口能取回没有文字的评分，不会在公共评论列表制造空白评论。

评分写入和汇总在同一事务内锁定书籍、按真实记录重算。综合评分为 `(基础评分总星数 + 真实评分总星数) / (基础样本数 + 真实评分人数)`；分母为零时返回 0，页面显示“暂无评分”。接口 `X-Rating-Summary` 提供两类总分、数量及综合结果，`X-Total-Count` 仅代表文字评论总数。真实评分人数不限制为 50。

## 基础评分样本

`infra/seed-rating-samples.mjs` 为当前公开在架书籍生成 1–50 份整数星样本，存放在 `statisticsSeed.ratingSample`，不会创建虚假账号或 `Review`，也不生成文字评论。详情页按用户 2026-09-25 的最新要求显示“xx人评分”，数量仍为基础样本数 + 真实评分人数，评分算法和数据不变；说明文字继续区分初始化样本和真实读者评分。新书上传会按[书籍基础数据](书籍基础数据.md)自动生成样本，已有样本不重新生成。

数量公式为 `round(4 + 40 × 浏览量 / 本批最大浏览量 + [-7, 7) 扰动)`，截取到 1–50。扰动由书籍 ID 稳定生成，整体随浏览量增加，局部可以交错；同一快照重跑结果一致。逐份星数围绕已有基础分分配，总分取最接近的整数；没有既有评分时以内部 4.5 星为目标。后续浏览增长不会反复增加样本。

样本的 `votes` 保存每份分数；`ratingWeight` 同步为样本数、`rating` 同步为其均值，使旧版汇总算法仍能正确处理。原基础浏览、收藏、真实评分及评论不变。重跑跳过已经初始化的书，新增书可在下一次显式运行时补齐。

## 执行与恢复

使用现有服务器配置和新版本代码，先预览，再应用：

```sh
node --env-file=/etc/test1/api.env infra/seed-rating-samples.mjs /srv/test1/backups/rating-samples
node --env-file=/etc/test1/api.env infra/seed-rating-samples.mjs /srv/test1/backups/rating-samples --apply
```

应用要求 `WRITE_MODE=readwrite`。每本书在事务内写入，写前把旧评分字段、目标样本与汇总写入 JSONL 并刷盘；日志写失败则该书事务回滚，部分失败可重新执行。计划、审计与验收记录保留在备份目录，不加入 Git。

需要撤销时，按运行编号只恢复该次审计中的 `statisticsSeed.rating`、`ratingWeight` 和 `ratingSample`，然后依据当前真实评分重算 `rating`、`numRatings`、`numReviews`；不得回填整书旧快照或覆盖后来提交的读者记录。旧版本可按同步的基础均分和权重读取、计算现有评分，数据结构向后兼容；旧界面不区分仅评分记录，回滚时应保留本次评分界面或尽快恢复修复版本。
