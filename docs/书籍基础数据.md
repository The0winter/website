# 书籍基础数据初始化

`infra/seed-book-statistics.mjs` 为现有公开作品一次性补充浏览、收藏和基础评分。真实账号、书架关系、书评、章节与按日阅读记录保持原样；这不是读者行为采集。

## 规则

- 输入带来源 URL、采集时间、书名、作者和排名的起点月票榜 JSON（`source`、`observedAt`、`rows: [{title, author, rank}]`），仅支持前 500 名。书名和作者共同匹配，兼容全半角及空白差异。
- 浏览目标 2,000–50,000；收藏目标 100–2,000；十分制基础评分 8.9–9.9。排名越靠前总体越高，各指标采用可复现的小幅独立扰动；未匹配作品取中上区间。
- 已有真实浏览或收藏高于目标时保留原值。`statisticsSeed.views` 记录加入总浏览的增量，`statisticsSeed.favorites` 是真实收藏之外的基础值。后续浏览和收藏按原流程累加、取消。
- 基础评分内部仍为五分制，权重为目标收藏的 8%，至少 30。综合评分按基础权重和真实评价加权；真实评价数量与列表不虚增。详情页显示“综合评分”，不再将这部分数据标作全部来自真实用户。
- 总榜使用补充后的总浏览。一次性初始化不分配历史阅读日期；后续每日基础热度见下文。基础数据达到的里程碑不编造达成日期。

## 执行与审计

在当前版本目录、使用目标环境配置运行。默认预览；确认实际目标和数据范围后加 `--apply`，目标须为 `WRITE_MODE=readwrite`。

```sh
node --env-file=/etc/test1/api.env infra/seed-book-statistics.mjs /path/ranking.json /srv/test1/backups/book-statistics
node --env-file=/etc/test1/api.env infra/seed-book-statistics.mjs /path/ranking.json /srv/test1/backups/book-statistics --apply
```

每次输出独立计划和操作编号；写入前将该书原数据、真实统计及拟添加基础值写入 JSONL 并刷盘。每书事务独立提交，失败可重跑，已存在 `statisticsSeed` 的作品始终跳过，不能重复叠加。运行目录及榜单快照属于运维数据，不提交 Git。

恢复时依据同一操作编号的审计记录，仅移除该次基础浏览增量和 `statisticsSeed`，用现有真实评价重算评分；不能整书覆盖或恢复旧书架，以免丢失初始化之后的读者行为。先预览拟恢复的数据再执行。代码回滚也应选择支持 `statisticsSeed` 的兼容版本，或先按上述方式撤销基础值。

## 每日基础热度

`server/jobs/daily-popularity.js` 为全部公开在架作品生成每日 2,000–50,000 的浏览目标。已核对的 `statisticsSeed.qidianRank` 贡献 70% 权重，其余 30% 按书籍 ID 和北京时间日期稳定随机；未匹配作品维持中上区间并增加日间波动。当天重试保持同一结果，次日重新抽取。此任务不抓取起点实时榜单，也不更改评分和收藏。

当日已有真实浏览先计入目标，只补差额，已经超过目标的真实数据不降低。`ReadDaily.views` 保存总值，`baselineViews` 保存补充量，`baselineTargetViews`、`baselineQidianRank`、`baselineVersion`、`baselineGeneratedAt`、`baselinePriorTotal` 用于审计。真实浏览可由总值减去基础值获得；不会创建阅读用户或阅读回执。

每日记录与 `Book.views` 在同一事务中增加，`dailyPopularityThrough` 保存逐书检查点。同一天重复执行、并发调用及失败重试不会重复加量。任务恢复时补齐启用日期之后的漏日，不早于书籍创建日期，也不写未来日期；单次每本最多补 31 天，后续运行继续。配置启用日期必须固定，不随部署改变。

日榜按北京时间当天统计，周榜为周一至今，月榜为当月 1 日至今，总榜持续累加。原始每日记录保留；换周、换月仅改变查询区间。缓存的日、周、月字段也会刷新，且不会将统计变动写成书籍更新时间。

部署 `infra/systemd/test1-daily-popularity.service` 和 `.timer`，在 `/etc/test1/daily-popularity.env` 设置 `DAILY_POPULARITY_START=启用日期`。使用原有 `/etc/test1/api.env` 数据库配置与服务账户。每天北京时间 00:05 生成新一天数据，每小时检查补漏、新上架作品及缓存，开机后也会恢复检查。无需模型、浏览器或 Codex 定时任务。

```sh
node --env-file=/etc/test1/api.env --env-file=/etc/test1/daily-popularity.env server/jobs/daily-popularity.js
node --env-file=/etc/test1/api.env --env-file=/etc/test1/daily-popularity.env server/jobs/daily-popularity.js --apply
sudo systemctl enable --now test1-daily-popularity.timer
sudo systemctl start test1-daily-popularity.service
```

默认仅预览，`--apply` 要求写入模式。systemd 日志只输出汇总与通用错误类型，不输出凭据。需要撤销时先停用 timer，再依据每日记录的 `baselineViews` 同时减去对应每日/总浏览基础值，保留其后的真实浏览，并刷新周期汇总；不要整库回退。
