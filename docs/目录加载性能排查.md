# 目录加载性能排查（2026-09-10）

用户反馈书籍详情和阅读弹窗的目录都慢。初始排查核对了 VPS 运行代码，并对网站、VPS 到 Atlas 的查询做只读测量；随后按用户授权部署，结果见文末。没有修改生产数据。

## 原因与测量

- 前端 `catalogPages` 每次取 200 章，逐页串行获取；详情和阅读器均等全部加载完成才更新列表。《从水猴子开始成神》当前 1,238 章需要 7 页。
- 详情页已有服务端目录，挂载后又把它隐藏并重新获取全部章节；登录用户的会话恢复还能触发一轮目录加载。
- 阅读器随章节路由重建，缺少目录缓存，每次翻章又重新读取整本目录。
- 后端每页依次执行作品检查、章节查询、章节总数统计。数据库远程往返约 210 毫秒，游标分批读取又增加往返。

| 只读采样 | 耗时/结果 |
| --- | --- |
| VPS 本机健康检查 | 2 毫秒 |
| VPS 本机旧目录接口，200 章 | 1,088 毫秒 |
| 数据库 ping / 作品检查 / 总数统计 | 各约 210 毫秒 |
| 旧默认游标读取 200 章 | 632–637 毫秒 |
| 单批读取相同 200 章 | 217 毫秒 |
| 三项查询并行、目录单批读取，连接预热后 | 211 毫秒 |
| 同一并行方案，新连接池首次/第二次 | 1,842 / 416 毫秒 |
| 查询执行计划 | 命中 `bookId_1_chapter_number_1`，扫描 200 条返回 200 条，数据库执行时间 0 毫秒（毫秒精度） |

服务器负载接近 0，可用内存约 3.1 GB，未使用交换空间。目录只查询 MongoDB 章节元数据，不读取 R2 正文。因此本次瓶颈主要是串行网络等待和重复加载。

以上是少量诊断采样，不是压力测试或用户端加载承诺。连接池冷启动仍有额外成本，用户到网站的网络耗时也未包含在数据库对比中。

## 修复

- 后端三个独立读取并行执行；目录使用单批有界查询，保持每页上限 200，只返回章节元数据，查询均有 3 秒服务端执行上限。
- 前端取得首批即可展示，剩余页最多 3 个并发，始终按连续页顺序更新，避免漏页时跳章。
- 详情页读取并复用新鲜的首批 200 章及总数，不因会话变化重新加载，也不再隐藏已有目录。
- 阅读器复用完整目录：最多 3 本、每本最多 10,000 章、最长 60 秒。服务端返回的 `writeVersion`（兼容回退 `updatedAt`）改变时重新加载，不缓存失败或不完整结果。
- 同时进行的相同分页请求共享读取；失败会显示可重试状态。读取深处章节时，在目录未加载到当前位置前使用后端提供的上下章 ID。

## 后续修正：按展示方向加载，固定可点击章节

用户发现详情页默认倒序，但原先先取前 200 章，再补齐后续页；每批数据到达都会把新的章节插到当前列表前面，改变读者准备点击的章节。

- 详情页服务端首批和浏览器续页均使用 `order=desc`，先显示最新 200 章，旧章节只追加到列表后方。
- 加载中切换正序时，改为从最早章节分页，并停止旧排序继续发布结果和请求后续页；完整目录加载后切换排序直接复用已有数据。
- “开始阅读”的首章 ID 由独立的 `order=asc&limit=1` 查询确定，不取尚未加载完整的倒序列表中的最小编号。首章暂不可用时不会生成错误的阅读链接。
- 分页单元测试、四项目录浏览器回归、TypeScript 和 ESLint 检查通过；服务器生产构建通过。
- 提交 `c66216e` 于 2026-09-10 15:57 UTC 部署至 `/srv/test1/releases/catalog-c66216e`，基于上一个目录版本，仅覆盖三个前端运行文件、重启前端。API 和 R2 兼容代码保持原版本，前后端均 active。
- 公网浏览器人为延迟后续页，确认首批已经显示最新章；随后补齐第 2–7 页，最新章链接不变。完整目录切换排序未增加请求，点击最新章及“开始阅读”均进入正确章节；无异常 HTTP 响应。既有 React 418 水合警告仍按上节记录。
