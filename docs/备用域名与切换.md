## 正式切换时执行

仅在用户明确要求启用新主域名后执行，沿用 main 提交、推送、保留兼容线上功能及预热部署流程。

1. 核对当时的线上版本、主域名健康状态、注册邮箱验证、DNS、Cloudflare 边缘和源站证书。备份 Nginx、环境配置及需要改动的业务引用；不要回退数据库或整站覆盖旧代码。
2. 将新根域名 Nginx 配置改为当前已验证的业务代理规则，保留全部上传大小、超时、安全头和健康检查限制；Host 转发与网站新主地址一致，www 统一跳转新根域名。移除备用入口上的 noindex 和旧站临时跳转。
3. 将 `/etc/test1/web.env` 中 `NEXT_PUBLIC_SITE_URL` 改为 `https://jiutianzw.com`，重建并预热前端。核对 canonical、Open Graph、结构化数据、robots、所有 sitemap 以及邮件中可能包含的站点链接。
4. 将 API 的 `ALLOWED_ORIGINS` 加入新主地址，并按切换安排保留必要的旧来源。跨域登录 Cookie 不能直接转移，用户可能需要在新域名重新登录；验证注册、登录、CSRF、书架、阅读进度、评论与上传。
5. 将 `COVER_PUBLIC_BASE_URL` 切换为 `https://img.jiutianzw.com`。已有 Book / User / Media 中保存的完整图片地址及媒体归属、删除逻辑必须一起核对；只改环境变量不会自动更新已有封面引用。应采用已验证的兼容映射或备份后精确迁移，不能盲目全库替换字符串。
6. 核对仍包含旧域名的 SEO 提交入口：`infra/submit-indexnow.mjs`、`server/utils/indexNow.js`、`server/baidu_push.js` 及验证文件。更新搜索平台站点、sitemap、GA4 数据流地址，保留既有统计衡量 ID，是否执行旧站永久跳转按用户当时的要求决定。
7. 在公网验收新域名首页、书库、真实书籍目录、章节正文、图片及登录写入；再执行切换后的旧域名跳转并检查无循环。若旧域名存在访问风险，必须确认新站正文、静态资源、图片和邮件链接均不再依赖旧域名。

新域名目前没有配置邮件路由；现有收发邮件继续使用原配置。将来若要使用 `@jiutianzw.com` 邮箱，另行配置对应的收信路由、发信服务验证及 SPF/DKIM/DMARC，不直接复制旧域名的 DKIM。
