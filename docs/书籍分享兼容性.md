# 书籍分享兼容性

详情页按当前浏览器实际开放的能力选择分享方式，不把浏览器名称或模拟 User-Agent 当成真机支持证明。

| 浏览器 | 调用与回退 |
| --- | --- |
| Safari（含 iPhone/iPad） | Web Share；完整参数不支持时依次尝试标题 + 链接、仅链接；不可用时显示 Safari 分享入口指引和复制操作。 |
| 小米浏览器 | Web Share 和上述参数兼容；未核实到可供任意网页使用的专用公开接口，不猜测调用私有桥接；不可用时指引浏览器菜单分享并保留复制。 |
| UC 浏览器 | 优先 Web Share；其次探测浏览器实际注入的安卓 `ucweb.startRequest('shell.page_share', …)` 或 iOS `ucbrowser.web_shareEX` / `web_share`；桥接缺失、拒绝或抛错时回退复制。 |
| Chrome | Web Share、参数兼容与菜单/复制回退。 |
| Edge | Web Share、参数兼容与菜单/复制回退。 |
| QQ 浏览器 | 保留 Web Share、安卓 QQ 官方 SDK 和复制回退；SDK 只在独立安卓 QQ 浏览器中按需加载。 |

分享调用必须直接发生在点击或触摸事件中，不在调用前等待网络、SDK 或剪贴板请求。参数校验失败或切换接口需要第二次点击，不自动复用已消耗的用户手势。用户取消不作为错误处理。UC/QQ 桥接返回不能证明消息已发出，界面不显示虚假的“分享成功”；不指定目标联系人或自动发送。

UC 仅在对应浏览器及操作系统中且方法真实存在时调用。微信、QQ 内置网页不使用独立浏览器的桥接。UC 调用约定核对自 [NativeShare 安卓源码](https://github.com/fa-ge/NativeShare/blob/master/src/UCAndroidBrowser.js) 和 [iOS 源码](https://github.com/fa-ge/NativeShare/blob/master/src/UCIosBrowser.js)，属于历史接口兼容，仍需要新版本真机验证。标准接口参考 [Safari/WebKit](https://webkit.org/blog/8718/new-webkit-features-in-safari-12-1/)、[Edge](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/how-to/share) 和 [Web Share 标准](https://w3c.github.io/web-share/)。

验证入口：`npm run test:browser -- --config web-next/playwright.share.config.ts`。用 `PLAYWRIGHT_JSON_OUTPUT_FILE` 把报告保存到本次 `.runtime/task-artifacts/` 目录，避免并行任务覆盖报告。`book-share-browsers.spec.ts` 是五类浏览器能力与桥接的模拟验证；`book-share-real.spec.ts` 检查真正运行的浏览器页面和复制功能。Windows 上的 WebKit 不是 iPhone Safari，改变 User-Agent 也不是安卓 UC/小米真机；这两种测试都不能替代手机系统分享面板验收。
