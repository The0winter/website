# 创作章节回收站

草稿箱、已发布和回收站平分标签栏。章节菜单提供发布与删除；已发布章节的发布项不可重复执行。回收站菜单提供复原，也支持长按多选复原。删除和发布仍需确认。移动端保留底部固定的新建章节按钮。

## 保存、删除与复原

- 未同步的本地草稿先完整保存，再通过独立接口移入回收站；已存在的云草稿删除时不读取或清空 R2 正文。删除失败时保留原列表项目。
- WriterDraft 保留原正文引用，写入 deletedAt、trashUntil，并增加 revision。复原通过专用接口完成，不允许普通旧设备同步请求直接撤销删除。
- 已发布 Chapter 保留正文、章节编号和 ID，删除后读者不能读取。复原恢复原来的发布状态。重复删除不会延长恢复期限。
- 每次删除后的七天（7 × 24 小时）内可复原，到期即拒绝复原。旧的已下架章节若尚无期限，迁移时给予从上线起计算的完整七天窗口。

## 到期清理

API 服务在可写模式下每分钟扫描一次，单轮分别处理最多 100 个过期草稿及已发布章节。清理与复原都在事务中重新核对状态，避免清理已经复原的章节。数据库故障会保留记录并在后续轮次重试。

过期草稿从 WriterDraft 删除，原导入文稿中对应的正文也会清除，但保留数组位置以免其他章节编号变化。其专用 R2 草稿对象交由既有 WriterBlob 清理机制回收。WriterDiscard 仅保存账号、作品、草稿 ID 和删除时间，不保存书名、章节名或正文，用于阻止离线设备把过期草稿重新上传；浏览器刷新时也移除对应本地副本。

过期已发布章节从 Chapter 删除，并清理关联段评、单章阅读统计、旧版已发布草稿以及阅读记录中的失效章节引用。原始导入正文和发布后的 WriterDraft 副本也会清除。已有不含正文的发布回执保留，以拦截迟到的重复发布请求。内容寻址的 R2 正文对象可能被其他章节共用，不在此事务中直接删除；正文访问始终需要有效的 Chapter 记录。

## 部署与回滚

在现有 API 环境中运行 `node server/migrations/writing-trash.js` 预览，再加 `--apply` 创建专用同步回执集合及期限索引，接入旧的已下架章节。迁移不清除正文。

回滚版本须包含本次后端的软删除、复原和过期同步拦截代码，可保留其原有前端构建。不能在已经产生过期清理记录后退回忽略 WriterDiscard 的旧后端。部署仍采用新版本目录、健康检查、公网验收和当前版本加两个兼容回滚版本的保留流程。

验证覆盖真实数据库事务与 R2 适配器、真实浏览器到隔离 API 的删除／复原／发布流程、三栏手势切换、菜单及多选动画、云同步回归和过期后防止旧设备复活。
