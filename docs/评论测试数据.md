# 评论功能测试数据

使用 `infra/review-test-data.mjs` 在指定书籍下创建可识别、可清理的功能测试评论。计划 JSON 和操作记录放在任务目录，不提交账号或运行数据。

计划包含 `batch`、`bookId`、`title`、`author` 和 `drafts`；每条草稿包含 `id`、`displayName`、`rating`、`content`。同一批次最多 50 条。工具会给昵称添加“（测试）”、正文添加“【测试】”，加上标记后正文仍须不超过 140 字。

在已有服务器运行环境中执行：

```sh
node infra/review-test-data.mjs PLAN_JSON AUDIT_DIRECTORY
node infra/review-test-data.mjs PLAN_JSON AUDIT_DIRECTORY --apply
node infra/review-test-data.mjs PLAN_JSON AUDIT_DIRECTORY --cleanup
```

默认只预览；写入或清理需要 `WRITE_MODE=readwrite`。Windows 运行时先加载后台隐藏窗口工具，按项目约定执行。

测试评论参与列表分页和赞踩功能，公开显示测试标记，但不计入本书正式评分或真人评分人数。公开主页展示“测试账号”，不返回邮箱；展示账号禁止登录，不保留可用密码，也不发送邮件。

同一批次重复写入不会新增重复账号或评论。清理只处理该批次精确匹配的测试记录，按当前真实评论重新统计，不回写旧评分快照。若测试内容被另外修改、出现记录冲突或账号有其他评论，工具保留数据并报错，避免误删。执行前后记录追加到审计文件。
