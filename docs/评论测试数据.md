# 评论功能测试数据

使用 `infra/review-test-data.mjs` 在指定书籍下创建可识别、可清理的功能测试评论。计划 JSON 和操作记录放在任务目录，不提交账号或运行数据。

计划包含 `batch`、`bookId`、`title`、`author` 和 `drafts`；每条草稿包含 `id`、`displayName`、`rating`、`content`。同一批次最多 50 条。工具会给昵称添加“（测试）”、正文添加“【测试】”，加上标记后正文仍须不超过 140 字。

在已有服务器运行环境中执行：

```sh
node infra/review-test-data.mjs PLAN_JSON AUDIT_DIRECTORY
node infra/review-test-data.mjs PLAN_JSON AUDIT_DIRECTORY --apply
node infra/review-test-data.mjs PLAN_JSON AUDIT_DIRECTORY --cleanup
node infra/review-test-data.mjs REPLACEMENT_JSON AUDIT_DIRECTORY --replace
```

默认只预览；写入或清理需要 `WRITE_MODE=readwrite`。Windows 运行时先加载后台隐藏窗口工具，按项目约定执行。

测试评论参与列表分页和赞踩功能，不计入本书正式评分或真人评分人数。列表隐藏测试昵称后缀、正文前缀和导入标签；公开主页展示“测试账号”和评论来源，不返回邮箱。数据库仍保留测试标记；展示账号禁止登录，不保留可用密码，也不发送邮件。

同一批次重复写入不会新增重复账号或评论。清理只处理该批次精确匹配的测试记录，按当前真实评论重新统计，不回写旧评分快照。若测试内容被另外修改、出现记录冲突或账号有其他评论，工具保留数据并报错，避免误删。执行前后记录追加到审计文件。

缩减数量或修改测试措辞时，用同一 `batch`，在 `drafts` 中放保留的条目和新文案，在 `previousDrafts` 中放当前批次的完整旧草稿，再执行 `--replace`。只允许保留现有身份，保留条目的赞踩和创建时间不变；删除的账号必须仍属于本测试批次。旧记录写入审计后，缩减和替换在同一事务内完成。重复执行不会继续削减数量。此操作不限制或删除真实用户评论。

修改测试昵称也使用 `--replace`：保留草稿的 `id`，只调整 `displayName`。账号 ID、个人主页地址、评论关联和测试标记保持不变；若昵称已被其他账号占用，整次更新会中止。旧昵称随原账号记录写入审计，可据此回退。
# 站外短摘录

测试计划可附 `sourceExcerpt: {platform, author, url, publishedAt?, kind?}`，必须是已核实的公开来源和 HTTPS 原文链接。`kind` 为 `excerpt`（默认，原文短摘录）或 `paraphrase`（参考改写）。短摘录保留原文，删节用省略号表示；改写不得冒称原作者原话。测试账号仍为导入者；点击头像进入个人主页查看出处及星级说明。星级按测试用例配置，不是原作者评分，且不计入本站评分。普通评论接口不接受来源字段。替换和清理核对全部来源字段，防止覆盖外部修改。

## 扩展到多本书

1. 从本站 API 保存书籍 ID、书名、作者、显示评分人数及现有评论快照；分母为详情页显示的评分人数，包含已有基础评分人数。
2. 查阅对应书籍的公开书评、论坛讨论和书单，保存页面证据、原作者、原文及链接。优先采用真实短评或忠实短摘录，保留原有措辞，删节不能改变原意；不能把同一人的一篇书评扩写成多个账号的评论。登录或访问失败时记录并换源；不使用无关作品、求资源帖或辱骂填充。
3. 每本独立批次，真实评论不删不改。用户于 2026-09-26 修正数量优先级：采集不到足够真实评论时允许减少数量，不为达到此前评分人数约 25%–35% 的目标生成填充。自行生成、参考改写均算生成评论，每本及整批生成占比不得超过 10%，能全部采用真实原文时取 0%。好评总体更多，各书数量和好坏比例不固定；每条不超过 140 字。新增数量用新批次，已有批次修改用 `--replace`。
4. 写入前运行预览和计划校验，持久保存审计；批次重复执行不得增加重复记录。写入后核对真实评论、评分和评分人数未改变，检查分页、主页隐私及每本覆盖率。
5. 展示昵称只对对应原作者的公开 ID 作小幅调整，保留原有风格；不批量套用“英文数字_中文”、书签、翻页等后缀，不用包含邮箱的 ID。账号仍保留测试身份，主页明确列出真实原作者及出处；站内展示账号不代表原作者入驻。

默认文字头像按账号稳定分配 16 种配色；用户在本人主页可更换颜色，上传头像优先显示，颜色用于默认头像及图片加载失败后的回退。
