# 拾页 · 小说采集窗口

在项目根目录双击 **拾页小说采集.vbs**。程序使用本机 Chrome / Edge 的独立应用窗口，隐藏启动终端；下载和检查由本地 Node 程序执行，无需 Codex 保持运行，也无需模型 API Key。当前是依托本项目环境的本地程序，不是可脱离项目单独复制的 EXE。

桌面可使用带书本图标的 **拾页** 快捷方式。重建快捷方式运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/novel-crawler/desktop/create-shortcut.ps1`；它指向项目内启动器，无需复制启动文件。图标由同目录 `icon.svg` 生成，更新图形后运行 `node tools/novel-crawler/desktop/build-icon.mjs`，得到包含 16–256 像素多尺寸图像的 `icon.ico`。

## 使用

1. 填网站首页（支持省略 `https://`）和完整书名。作者选填；同名结果请核对作者。也可在网站栏直接粘贴书籍详情页。
2. 点击“查找书籍”，选择匹配项，点击“试采并下载”。勾选“仅试采”时只生成抽样报告。
3. 试采没有严重错误才继续下载整本。窗口显示章节进度，完整结果存入项目 `downloads/`，格式仍为网站导入 JSON。可以打开下载文件夹和报告目录。
4. 暂停会等待正在处理的章节结束，保存后停止。继续时重新查找该书并开始，自动复用已完成章节。关闭窗口也会保存后退出；最后一页请求及重试可能仍需等待一段时间。

网站在输入完成、点击左侧列表或查找时记忆，去重后长期保存，**不再限制数量**；再次启动恢复最近的网站。左侧“我的网站”合并历史网站和已适配来源，最近使用的排在最上面，未使用过的已适配来源接在后面，并标记“已适配 / 待适配”。网站多时列表独立滚动。记忆保存网站的根地址，详情页地址不会成为下一本书的默认页面。已有历史记录会继续保留。

已适配网站会显示在左栏并可直接点选，新增配置自动加载。尚未适配的域名会显示“待适配”，不会猜测正文提取规则。现在内置 `ixdzs8.com`（爱下电子书）：支持站内按书名搜索、可选作者过滤、详情页输入、公开 JSON 目录及正常浏览器渲染的正文。搜索在最多 8 页内寻找匹配项；找不到时可使用详情页地址。同名结果来自第一个出现精确匹配的结果页。

`twkan.com`（台灣小說網）支持首页地址（包括 `/?t=1`）、书籍详情页 `/book/数字.html`、站内搜索与作者筛选。简体或繁体书名均可匹配；下载保留源站原始繁体标题和正文。搜索可能返回列表，也可能直接跳到唯一结果的详情页，两种情况都会核对书名、作者。目录通过网页实际使用的公开完整目录入口获取，不把初始显示的 36 章当作全书；按来源 `data-num` 排序，保留通知、番外等条目。

该站使用正常 Chrome / Edge 窗口请求，窗口平时尽量最小化，请求间隔从 3 秒调为 **8 秒**；每个新采集阶段的首次请求也会等待，避免连续启动搜索、详情读取和采集时集中请求。普通 HTTP 429 或临时服务错误会按 `Retry-After` 有限重试；服务器要求等待超过一分钟时停止并保留进度。减慢速度能减少触发机会，但不能保证不会出现验证。

遇到 Cloudflare 人机验证时，程序显示采集浏览器，并在拾页进度区提示。**请在弹出的采集浏览器中手动完成验证**，程序只等待验证页面跳转，不点击验证码；完成后自动继续。最长等待 3 分钟，超时或关闭验证窗口会停止并保留进度。采集中可点“暂停采集”，或关闭拾页以取消等待；稍后重新查找同一本书即可续传。

抽样检查和完整检查都使用确定性程序，检测缺失、重复、编码异常等。它们不能判断源站的语义删文或任意段落错序，警告需结合报告理解。

## 运行环境与数据

- 优先使用 `.runtime/node-v22.23.2-win-x64/node.exe`，没有则使用 PATH 中的 Node。依赖复用项目 `node_modules`，缺失时在项目根运行 `npm install`。
- 繁简名称匹配使用本地 OpenCC 字典；另进入 `tools/novel-crawler/` 目录运行 `npm install` 安装专用依赖。它只用于作品身份比较，不自动转换正文。
- Chrome / Edge 必须可用；可通过环境变量 `NOVEL_CRAWLER_BROWSER` 指定浏览器程序。TXT ZIP / EPUB 来源还需要 Python 3，见原采集文档。
- 若系统禁用了 VBS，可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/novel-crawler/desktop/launch.ps1`，或 `node tools/novel-crawler/desktop/main.mjs`。快捷方式须指向原项目中的启动文件，不要只把启动文件复制到别处。
- 设置：`.novel-crawler/desktop-settings.json`；上次任务：`desktop-last-task.json`；启动日志：`desktop-*.log`；窗口独立浏览器配置：`desktop-browser/`，均在 `.novel-crawler/` 内，不提交 Git。
- 程序只监听随机端口的 `127.0.0.1`，API 使用每次启动的随机凭据并验证 Host / Origin，不提供远程访问或任意本地文件打开接口。双击第二次会唤起现有窗口。
- 完整 JSON 名称沿用 `书名--作者--8位任务标识.json`，尾部用于避免不同来源互相覆盖。输出标题按“第1章 章名”分隔；原始标题在必要时另外保留。
- 窗口不会上传小说或连接生产数据库，因此本工具修改不需要部署网站。

## 站点配置

站点配置放在 `tools/novel-crawler/sites/*.json`，不要与 `.novel-crawler/candidates/` 中的单本书配置混淆。可参照现有 `ixdzs8.json`。

| 字段 | 用途 |
| --- | --- |
| `version` | 站点配置格式，目前为 1 |
| `id` / `name` | 唯一英文标识、窗口中文名称 |
| `home` / `hosts` | 首页 URL、精确支持的域名列表，不使用通配符 |
| `search.url` | 搜索 URL，`${query}` 为 URL 编码后的书名 |
| `search.items` | 每个书籍结果卡片的 CSS 选择器 |
| `search.title` / `author` | 卡片内部唯一的提取规则，支持选择器字符串或 `{selector, attribute, pattern}`；pattern 取第一捕获组 |
| `search.link` | 卡片内书籍详情链接的 CSS 选择器 |
| `search.next` / `maxPages` | 下一页链接选择器和搜索上限，最多 20 页；没有更多结果时停止 |
| `search.transport` / `readySelector` | 可指定 `browser` 并等待页面完成；无结果页也应能匹配 readySelector |
| `book.urlPattern` | 匹配详情 URL 的 pathname，例如 `^/book/(?<bookId>[0-9]+)/?$`，命名捕获可用于模板 |
| `book.metadata` | 详情页唯一的 `title`、`author` 提取规则 |
| `spec` | 原采集器完整来源配置模板；见 `docs/智能找书与采集.md` |

`search` 可省略，此时只支持详情页输入。网站首页模式只接受 `/` 路径。非首页路径需匹配书籍详情页规则，不自动把栏目页或章节页当作书籍。

`spec` 支持 `${title}`、`${author}`、`${sourceUrl}` 和 `book.urlPattern` 的命名捕获。JSON 目录中的 `{ordernum}` 等逐章字段不带美元符，保留给目录解析器，不会在书籍模板阶段替换。`allowedHosts` 还需显式包含独立目录或下载域名，浏览器正文只加载配置允许的域名。

`spec.transport: "browser"` 对作品详情、HTML 目录和正文启用浏览器请求；搜索和详情页配置也继承它。`browser.headless: false` 使用普通浏览器，`minimized: true` 尽量最小化；`responseMode: "source"` 读取浏览器收到的原始响应，以免站点随后转换 DOM 导致标题或正文在续传时变化。默认仍使用渲染后的 DOM。`identityNormalization: "chinese-simplified"` 仅在比较书名、作者时将繁体折叠为简体，不改变下载数据。

`browser.manualVerificationMs` 启用等待用户验证，取值 1000–600000 毫秒；配合 `headless: false` 使用。通过 Cloudflare 的 [`cf-mitigated: challenge` 响应标记](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/)识别验证页，避免把验证页当成空搜索结果或小说正文。验证等待时间、限速间隔属于运行参数，调整它们不会使已有章节检查点失效。

`spec.variant` 应包含站点规则版本，例如 `desktop-example-v1`。影响提取的规则变化时更新为 v2，自动生成独立任务，保留旧数据。默认使用当前站点模板，不自动套用旧的单本文件下载规则；代码中 `resolveBook({reuseSaved:true})` 仅供明确需要复用历史已验证单本规则的工具使用。

不要固定示例书 ID、标题、作者或 `expectedCount`，也不要将某一本 TXT 的特殊标题正则当作全站通用规则。资源型来源应另行验证分章结构。

## 验证适配

在项目根运行以下 JavaScript（替换网址、书名、作者和独立状态目录）：

```js
import {searchBooks, resolveBook} from './tools/novel-crawler/desktop/sources.mjs';
import {acquire} from './tools/novel-crawler/core.mjs';
const stateDir = '.novel-crawler/adapter-checks/example';
const books = await searchBooks({website: 'https://example.org/', title: '书名', author: '作者', stateDir});
console.log(books); // 只有书名、作者和链接，不输出正文
// 有多个同名结果时，先核实，不能盲选。
const spec = await resolveBook({...books[0], stateDir});
const report = await acquire(spec, {mode: 'probe', stateDir});
console.log({pass: report.structuralPass, errors: report.errors, warnings: report.warnings, report: report.reportFile});
```

回归检查：

```powershell
node --test tools/novel-crawler/tests/desktop.test.mjs tools/novel-crawler/tests/crawler.test.mjs
```

测试使用本地模拟网页验证实际搜索选择、后台采集、导出、暂停续传、重启记忆和窗口响应布局；联网适配应另行试采，不把离线测试通过当作站点仍然可用。
