# 拾页 · 小说采集窗口

在项目根目录双击 **拾页小说采集.vbs**。程序使用本机 Chrome / Edge 的独立应用窗口，隐藏启动终端；下载和检查由本地 Node 程序执行，无需 Codex 保持运行，也无需模型 API Key。当前是依托本项目环境的本地程序，不是可脱离项目单独复制的 EXE。

桌面可使用带书本图标的 **拾页** 快捷方式。重建快捷方式运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/novel-crawler/desktop/create-shortcut.ps1`；它指向项目内启动器，无需复制启动文件。图标由同目录 `icon.svg` 生成，更新图形后运行 `node tools/novel-crawler/desktop/build-icon.mjs`，得到包含 16–256 像素多尺寸图像的 `icon.ico`。

## 界面与书籍简介（2026-09-11）

拾页沿用网站桌面主页的灰白背景、蓝色强调色和深色文字；正文及操作标签以 14px 为主，删除宣传口号、重复提示和底部说明，收紧表单与进度区。窄窗口的网站列表横向滚动；登录、验证、停止、续传和质量报告入口继续保留。

五个内置来源均配置了 `book.metadata.description` 和 `spec.metadata.description`。读取详情时一并获取简介，采集时随已有详情请求再次核对，不增加逐章请求。简介保留段落，移除展开控件、网站关键词及重复的移动版副本。进度区的 **书籍简介** 可展开预览，完整导出 JSON 包含 `description`，现有分批上传和网站导入接口会同步保存该字段。

已下载的书重新查找后点击 **检查更新**，可以补上或更新简介；已校验章节继续复用。没有取到新简介时保留本地已保存简介；从未取得时省略 `description` 并显示“未获取”，上传不会把网站原有简介清空。简介超过网站上限时截取前 5000 字符，界面及报告明确标记。被用户修改过的导出文件仍拒绝覆盖。

仅简介字段和简介选择器从章节兼容性哈希中排除，本次保持原有 `spec.variant`，因为目录和正文提取没有变化。真正修改目录或正文规则仍须更新版本，不能借简介兼容处理混用旧章节。TXT / EPUB 的详情页也可配置同一可选简介规则；不会把未经识别的 TXT 前言自动当作简介。

验证覆盖五站简介容器、缺失与多匹配、段落与长度边界、旧下载补简介、无正文重复请求、导出保护，以及上传时更新简介、缺字段保留和冲突回滚。真实页面结构检查使用本机已保存的五站详情响应，另对爱下电子书重新联网读取一页验证；没有为这次修改整本下载或发布书籍。运行和视觉检查产物保存在已忽略的 `.novel-crawler/interface-*`。

## 使用

1. 填网站首页（支持省略 `https://`）和完整书名。作者选填；同名结果请核对作者。也可在网站栏直接粘贴书籍详情页。
2. 点击“查找书籍”，选择匹配项，点击“试采并下载”。勾选“仅试采”时只生成抽样报告。
3. 试采没有严重错误才继续下载整本。窗口显示章节进度，完整结果存入项目 `downloads/`，格式仍为网站导入 JSON。点击“打开下载目录”查看下载结果，也可打开报告目录。
4. “采集进度”右侧的 **停止** 按钮可在查找、读取详情、采集、重试或等待验证时使用：中断当前请求并关闭该任务的采集浏览器，保留已保存章节，拾页主窗口继续可用。“暂停采集”保留原来的温和暂停方式；关闭拾页主窗口也会停止请求、保留进度并退出。

搜索结果会显示本地状态，帮助区分新书和已有下载：

- **已保存 X / Y 章**：按钮显示“继续采集”。从同一网站重新查找并开始，会先核对目录及已有章节，补齐缺少的章节；刚中断而尚未保存的那一章会重试。试采是分散抽样，因此续传补的是所有缺项，不一定从某个连续章号开始。
- **已下载完成**：按钮显示“检查更新”。目录没有变化时复用已有正文和导出文件，并提示“没有重复下载正文”；目录末尾新增章节时只补新增部分，再更新完整导出文件。
- **导出文件已被修改**：程序拒绝覆盖，保留原文件。目录发生删除、插入或改名时，也会停止续传，避免把两个版本混在一起。

续传依赖本机 `.novel-crawler/` 中的章节和来源记录，请保留这个目录；不同网站或不同提取规则版本分别保存，不自动合并。重复采集仍会重新请求作品详情、目录和必要的检查页面，但不会重复请求已校验通过的章节正文。

网站在输入完成、点击左侧列表或查找时记忆，去重后长期保存，**不再限制数量**；再次启动恢复最近的网站。左侧“我的网站”合并历史网站和已适配来源，最近使用的排在最上面，未使用过的已适配来源接在后面，并标记“已适配 / 待适配”。网站多时列表独立滚动。记忆保存网站的根地址，详情页地址不会成为下一本书的默认页面。已有历史记录会继续保留。

已适配网站会显示在左栏并可直接点选，新增配置自动加载。尚未适配的域名会显示“待适配”，不会猜测正文提取规则。现在内置 `ixdzs8.com`（爱下电子书）：支持站内按书名搜索、可选作者过滤、详情页输入、公开 JSON 目录及正常浏览器渲染的正文。搜索在最多 8 页内寻找匹配项；找不到时可使用详情页地址。同名结果来自第一个出现精确匹配的结果页。

`twkan.com`（台灣小說網）支持首页地址（包括 `/?t=1`）、书籍详情页 `/book/数字.html`、站内搜索与作者筛选。简体或繁体书名均可匹配；下载保留源站原始繁体标题和正文。搜索可能返回列表，也可能直接跳到唯一结果的详情页，两种情况都会核对书名、作者。目录通过网页实际使用的公开完整目录入口获取，不把初始显示的 36 章当作全书；按来源 `data-num` 排序，保留通知、番外等条目。

该站使用正常 Chrome / Edge 窗口请求，窗口平时尽量最小化，请求间隔为 **8 秒**；每个新采集阶段的首次请求也会等待，避免连续启动搜索、详情读取和采集时集中请求。首次等待结束才启动采集浏览器，之后复用同一个标签页，并关闭采集浏览器中的额外弹窗，避免每页请求都弹出 `about:blank`。普通 HTTP 429 或临时服务错误会按 `Retry-After` 有限重试；服务器要求等待超过一分钟时停止并保留进度。减慢速度能减少触发机会，但不能保证不会出现验证。

遇到 Cloudflare 人机验证时，程序显示采集浏览器，并在拾页进度区提示。**请在弹出的采集浏览器中手动完成验证**，程序只等待验证页面跳转，不点击验证码；完成后自动继续，并按配置恢复最小化。最长等待 3 分钟，超时或关闭验证窗口会停止并保留进度。采集中可点“停止”取消等待并关闭采集页面；稍后重新查找同一本书即可续传。

抽样检查和完整检查都使用确定性程序，检测缺失、重复、编码异常等。它们不能判断源站的语义删文或任意段落错序，警告需结合报告理解。

遇到限制框中的登录入口时，拾页会恢复采集浏览器窗口、打开网站登录表单，并显示 **等待登录**，最长等待 **10 分钟**。账号密码由用户在该网站窗口自行输入；采集器不代填、不提交登录，也不自动解验证码。网站登录成功会自动刷新章节；若未刷新，可手动回到原章节并刷新。程序确认原章节的新响应已解除登录限制后继续，不能只靠隐藏遮罩就把预览当作正文。仍需其他阅读权限的页面继续拒绝提取。

登录脚本使用的 `cdn.banshanren.com` 通过 `browser.resourceHosts` 放行；这只允许网页子资源，不允许把该域名当作书籍或章节来源。等待人工操作期间允许已配置域名内的图片等资源，以便网站自己的登录验证界面正常使用。试采和正式下载复用同一采集浏览器会话，任务结束或停止后关闭窗口；登录状态会按下面的规则在本机保留。

### 保持登录与切换账号

浏览器来源现在默认按网站保存登录状态。**查找、读取详情、试采、下载、换书和重新打开拾页** 使用同一份网站浏览器资料；不同网站分别保存，`www` 与不带 `www` 的同站地址共用。任务结束仍关闭采集窗口，下一次任务恢复登录信息，不需要让窗口一直开着。

此前每个任务使用临时浏览器，关闭时就丢弃了登录信息，因此即使只隔一分钟，也可能再次要求登录。旧版已丢失的信息无法恢复；升级后第一次遇到登录要求时手动登录一次，之后即可复用。网站使登录过期、撤销登录或再次要求验证码时，仍会提示用户操作，不能保证网站永久保持登录。

网站栏下方显示“已启用登录记忆”，并提供 **清除本站登录**。要换账号时，在任务结束后选择对应网站再点击该按钮，下一次需要登录时使用新账号。清除只影响所选网站在拾页里的浏览器资料，不删除章节、报告或其他网站的登录，也不操作平常 Chrome 的账号。

资料保存于 `.novel-crawler/browser-sessions/`，由网站域名生成独立目录，不随书名或提取规则版本变化。普通持久 Cookie 的有效期、localStorage 和 IndexedDB 由浏览器管理；普通 Chrome 会在退出时清理部分会话 Cookie，因此程序额外保存当前会话 Cookie，并在再次启动时恢复，不修改持久 Cookie 的到期时间。Windows 下该补充记录使用当前 Windows 用户的 DPAPI 加密，其他平台使用仅当前用户可读写的文件。程序不会把登录信息写进来源配置、章节、报告或 Git，也不代填或提交账号密码。

同一网站的浏览器资料同时只允许一个采集进程使用；停止任务会等待浏览器保存并关闭，然后释放占用。登录记录损坏或无法保存时显示具体处理建议；清除登录可以重建资料，已保存章节保留。普通 HTTP 来源仍按原有请求方式运行，不显示浏览器登录记忆入口。

### 中断原因与人工处理

搬山人还有一种独立于 Cloudflare 的站内验证码：页面提示“系统检测到您访问异常，输入验证码后可继续访问”，入口是 `toggleCode()`。拾页现在会识别这个入口，显示 **等待验证**，恢复采集浏览器并打开验证码表单，最多等待 10 分钟。验证码由用户自行完成，程序只打开表单并观察原章节的新响应；验证后若未自动跳转，请手动刷新原章节。登录后又出现验证码时，会在同一窗口继续等待处理。

等待期间进度区显示操作提示和剩余时间，可点击 **显示采集窗口** 将后台的窗口重新唤起，也可以停止任务。超时、关闭采集窗口或无法识别的阅读限制会停止采集并保留成功章节。未知限制在首个失败页面停止，避免继续请求后续章节。

任务中断时会自动弹出原因说明；关闭弹窗后，**失败详情** 仍留在进度区，包含目录位置、章节标题、具体错误、失败来源页链接和下一步建议。每次中断只自动弹一次，不会随每秒刷新反复打断操作。报告中保留同样的诊断信息，旧版桌面记录也会从原质量报告补回失败章节；旧报告本身没有记录的原因不会被当作已知事实补造。

登录、站内验证码及其他命中正文拒绝规则的受限页面都不会作为成功响应缓存；继续采集遇到旧受限缓存时重新访问来源。人工等待配置不改变正文提取规则，保持 `desktop-banshanren-v2`，不会废弃已有成功章节。

### 自己调整采集速度

用记事本打开 `tools/novel-crawler/sites/shudugu.json`，修改 `spec` 中的 `"delayMs": 2000`，保存即可。单位是毫秒：`1000` 为 1 秒，`2000` 为 2 秒，`5000` 为 5 秒；数值越小，请求间隔越短。这是每个网页请求的间隔，不是每章的间隔，一章多页时每页都按此设置请求。实际速度还受网络响应时间影响。

## 站点配置

站点配置放在 `tools/novel-crawler/sites/*.json`，不要与 `.novel-crawler/candidates/` 中的单本书配置混淆。可参照现有 `ixdzs8.json`。

| 字段 | 用途 |
| --- | --- |
| `version` | 站点配置格式，目前为 1 |
| `id` / `name` | 唯一英文标识、窗口中文名称 |
| `home` / `hosts` | 首页 URL、精确支持的域名列表，不使用通配符 |
| `search.url` | 搜索 URL，`${query}` 为 URL 编码后的书名 |
| `search.items` | 每个书籍结果卡片的 CSS 选择器 |
| `search.title` / `author` | 卡片内部唯一的提取规则，支持选择器字符串或 `{selector, attribute, pattern}`；pattern 取第一捕获组 |
| `search.link` | 卡片内书籍详情链接的 CSS 选择器 |
| `search.next` / `maxPages` | 下一页链接选择器和搜索上限，最多 20 页；没有更多结果时停止 |
| `search.transport` / `readySelector` | 可指定 `browser` 并等待页面完成；无结果页也应能匹配 readySelector |
| `book.urlPattern` | 匹配详情 URL 的 pathname，例如 `^/book/(?<bookId>[0-9]+)/?$`，命名捕获可用于模板 |
| `book.metadata` | 详情页唯一的 `title`、`author` 提取规则 |
| `spec` | 原采集器完整来源配置模板；见 `docs/智能找书与采集.md` |

`search` 可省略，此时只支持详情页输入。网站首页模式只接受 `/` 路径。非首页路径需匹配书籍详情页规则，不自动把栏目页或章节页当作书籍。

`spec` 支持 `${title}`、`${author}`、`${sourceUrl}` 和 `book.urlPattern` 的命名捕获。JSON 目录中的 `{ordernum}` 等逐章字段不带美元符，保留给目录解析器，不会在书籍模板阶段替换。`allowedHosts` 还需显式包含独立目录或下载域名，浏览器正文只加载配置允许的域名。

`spec.transport: "browser"` 对作品详情、HTML 目录和正文启用浏览器请求；搜索和详情页配置也继承它。`browser.headless: false` 使用普通浏览器，`minimized: true` 尽量最小化；`responseMode: "source"` 读取浏览器收到的原始响应，以免站点随后转换 DOM 导致标题或正文在续传时变化。默认仍使用渲染后的 DOM。`identityNormalization: "chinese-simplified"` 仅在比较书名、作者时将繁体折叠为简体，不改变下载数据。

`browser.manualVerificationMs` 启用等待用户验证，取值 1000–600000 毫秒；配合 `headless: false` 使用。通过 Cloudflare 的 [`cf-mitigated: challenge` 响应标记](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/)识别验证页，避免把验证页当成空搜索结果或小说正文。验证等待时间、限速间隔属于运行参数，调整它们不会使已有章节检查点失效。

`browser.manualLogin` 可为已核实的登录限制配置 `selector`、可选的 `openSelector`（只打开表单）和 `timeoutMs`（1000–600000 毫秒）；真实使用须配合 `headless: false`。程序显示窗口并等待用户完成登录，只有回到同一请求地址的新成功响应不再匹配限制标记时才继续。`browser.resourceHosts` 为此类交互列出确切的静态资源域名，不放宽顶层页面和章节 URL 的域名校验。登录等待和子资源配置属于请求方式，修改不会废弃已保存的章节；实际提取规则变化仍须更新 `variant`。

`browser.manualCaptcha` 使用与 `manualLogin` 相同的 `selector`、`openSelector` 和 `timeoutMs` 字段，适用于已核实的站内验证码入口；只打开输入表单，不自动求解或提交验证码。它与 `manualVerificationMs` 的 Cloudflare 响应检测独立，均不改变检查点版本。

`spec.variant` 应包含站点规则版本，例如 `desktop-example-v1`。影响提取的规则变化时更新为 v2，自动生成独立任务，保留旧数据。默认使用当前站点模板，不自动套用旧的单本文件下载规则；代码中 `resolveBook({reuseSaved:true})` 仅供明确需要复用历史已验证单本规则的工具使用。

不要固定示例书 ID、标题、作者或 `expectedCount`，也不要将某一本 TXT 的特殊标题正则当作全站通用规则。资源型来源应另行验证分章结构。
