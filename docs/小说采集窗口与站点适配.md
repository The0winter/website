# 拾页 · 小说采集窗口

在项目根目录双击 **拾页小说采集.vbs**。程序使用本机 Chrome / Edge 的独立应用窗口，隐藏启动终端；下载和检查由本地 Node 程序执行，无需 Codex 保持运行，也无需模型 API Key。当前是依托本项目环境的本地程序，不是可脱离项目单独复制的 EXE。

桌面可使用带书本图标的 **拾页** 快捷方式。重建快捷方式运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/novel-crawler/desktop/create-shortcut.ps1`；它指向项目内启动器，无需复制启动文件。图标由同目录 `icon.svg` 生成，更新图形后运行 `node tools/novel-crawler/desktop/build-icon.mjs`，得到包含 16–256 像素多尺寸图像的 `icon.ico`。

## 界面与书籍简介（2026-09-11）

拾页沿用网站桌面主页的灰白背景、蓝色强调色和深色文字；正文及操作标签以 14px 为主，删除宣传口号、重复提示和底部说明，收紧表单与进度区。窄窗口的网站列表横向滚动；登录、验证、停止和续传操作继续保留。按界面精简要求，进度区不再显示书籍简介及“打开下载目录 / 查看质量报告”一排入口，打开目录时不再显示状态与路径横幅；左侧下载目录入口仍可使用，操作失败时仍提示原因。

五个内置来源均配置了 `book.metadata.description` 和 `spec.metadata.description`。读取详情时一并获取简介，采集时随已有详情请求再次核对，不增加逐章请求。简介保留段落，移除展开控件、网站关键词及重复的移动版副本。完整导出 JSON 包含 `description`，现有分批上传和网站导入接口会同步保存该字段。

已下载的书重新查找后点击 **检查更新**，可以补上或更新简介；已校验章节继续复用。没有取到新简介时保留本地已保存简介；从未取得时省略 `description` 并在报告中标记，上传不会把网站原有简介清空。简介超过网站上限时截取前 5000 字符，报告明确标记。被用户修改过的导出文件仍拒绝覆盖。

仅简介字段和简介选择器从章节兼容性哈希中排除，本次保持原有 `spec.variant`，因为目录和正文提取没有变化。真正修改目录或正文规则仍须更新版本，不能借简介兼容处理混用旧章节。TXT / EPUB 的详情页也可配置同一可选简介规则；不会把未经识别的 TXT 前言自动当作简介。

验证覆盖五站简介容器、缺失与多匹配、段落与长度边界、旧下载补简介、无正文重复请求、导出保护，以及上传时更新简介、缺字段保留和冲突回滚。真实页面结构检查使用本机已保存的五站详情响应，另对爱下电子书重新联网读取一页验证；没有为这次修改整本下载或发布书籍。运行和视觉检查产物保存在已忽略的 `.novel-crawler/interface-*`。

## 连载状态（2026-09-11）

五个内置来源均配置 `book.metadata.status` 和 `spec.metadata.status`。读取书籍详情时提取作品自身的状态字段，将“全本／完本／已完结／已完結”等统一为导入字段 `status: "完结"`，将“连载中／連載”等统一为 `status: "连载"`。进度区显示“作品状态”，导出 JSON、质量报告和现有分批上传接口均传递该状态。不会把下载完成、章节名含“大结局”、推荐区的“完结小说”当作判定依据。

点击“检查更新”会重新读取状态，复用已校验正文。来源没有明确状态时显示“未识别”，从未取得时省略导出字段；已有状态则保留。多个明确状态字段互相矛盾时记录冲突。已保存完结而来源仍标连载时保留完结，并提示来源冲突，避免镜像旧标签导致状态倒退。来源证据包含具体容器、原始值、URL、响应哈希和采集时间。

已经人工交叉核实的完结作品可记录在本机 `.novel-crawler/book-statuses.json` 的 `books` 数组中。每项包含完整 `title`、`author`、详情页 `sourceUrl`、`status: "完结"`，以及带 `url` 和 `checkedAt` 的 `evidence`；按来源、书名、作者同时匹配。该记录会用于查找和采集，避免重新建任务时丢失核实结果；运行数据不提交 Git。取消误判时需同时更正此记录及对应保存配置，不能自动以旧来源标签撤销已核实结论。

本次只新增书籍状态元数据，不改变目录／正文提取，沿用简介的兼容处理：状态值、状态证据及状态选择器不参与章节兼容性哈希，保持现有 `variant`，旧下载不会因此变成新任务。实际改变目录或正文规则仍须更新 `variant`。TXT / EPUB 来源详情也支持状态读取。

验证包含五站状态选择器、繁简体与未知值、冲突处理、旧下载补状态、无正文重复请求、导出保护、分批传递和实际拾页窗口显示。2026-09-11 对线上 47 本的原来源详情逐本联网读取并核对书名作者，再对滞后标注交叉核实；网站数据同步见《书籍连载状态同步记录》。

## 使用

### 后台采集，不打断当前工作（2026-09-13）

采集浏览器现在默认无头运行，不创建可见窗口。原来的“启动后最小化”仍可能抢焦点，已不再用于自动采集。登录或验证码只在拾页进度区提示，只有主动点击 **显示采集窗口** 才以同一来源的浏览器资料打开可见窗口，并重新读取原请求、再次检查限制；会话 Cookie 和网站存储继续保留。搜索、详情读取和下载阶段都可使用该按钮。明确设置 `headless: true` 的自动检查始终不显示窗口。

显示窗口不会放宽编码、目录、正文或阅读权限检查。停止、超时和跳过继续保留已有章节；在验证或自动重试期间直接跳过时，也会在结果中保留当时的来源和原因。来源提取规则与检查点版本不变，关闭并重新打开拾页后生效。

同日实跑17本书库发现5本因JSON缩进或键顺序变化被误报为“已更新”，字段和章节实际完全相同。普通导出现在先验证已记录的文件字节哈希，再深比较书籍数据；数据相同则复用原文件及修改时间，未记录的外部修改仍拒绝覆盖。5本恢复原始字节后重新访问来源，均报告 `reusedExport: true`。本轮最终为8本无更新、9本因69书吧人机验证受阻而按用户指示跳过，新增0章。18份文件（包含原始版和绑定阅读版）均通过导入格式校验，已有章节哈希全部不变。运行证据见已忽略的 `.runtime/library-refresh-20260913/`。

### 一键更新本地书库（2026-09-13）

点击窗口右上角深蓝色的 **更新书库**，程序自动扫描 `downloads/` 中已下载的书籍，逐本连接原来源，核对目录并补齐新增章节，无需重新输入书名或逐本查找。报告、来源映射等附属 JSON 不作为书籍；已完结作品也会检查，以接收番外和来源状态变化。本操作只更新本地文件。

已换源的作品优先使用 `.novel-crawler/continuations/` 中的当前绑定来源；有阅读版绑定时只更新已整理的阅读版，保留原始采集版和来源映射。普通采集记录会复用已校验章节。没有兼容采集记录的旧下载会先核对末尾三个连续正文章节的标题和完整正文，衔接通过后沿用原文件追加后续章节；无法确认衔接时保留原书并显示原因，不自动另选来源或重新下载整本覆盖。

进度区显示已处理本数、更新本数、新增章节数和逐本结果。无变化显示“已是最新”。批量更新遇到临时网络错误、HTTP 429 / 5xx 或浏览器导航超时，单次页面读取最多自动重试 **2 次**（含首次共 3 次），显示重试次数并逐步等待；沿用来源请求间隔，尊重 `Retry-After`。服务器要求等待超过一分钟时直接请求人工处理。身份不符、正文或目录异常、文件被修改、规则不兼容、重复版本等问题直接请求核对，不用重复请求掩盖内容问题。

仍不能读取时，窗口显示 **等待你处理**，列出书名、失败章节／来源链接及处理建议，关闭本次采集浏览器后等待，**不会自动更新下一本，也不会因等待超时自行跳过**。处理完成点击 **处理好了，重试这本**，复用已保存章节并重新核对当前文件；无法处理则点击 **跳过，更新下一本**。手动跳过的原因保留在本轮列表中，下次点击“更新书库”仍会重新检查。等待期间刷新窗口保留当前状态。单本采集和书库更新互斥，重复点击不会创建第二个更新任务。

可点击“停止”中断请求，或点击“暂停采集”保存当前章节后暂停。已完成更新保留；下次再次点击“更新书库”会重新检查书库，复用已有检查点。刷新窗口继续显示当前任务，关闭程序后重新打开会显示上次结果和中断状态。需要登录或验证时沿用原来的人工操作提示及“显示采集窗口”，完成后继续；超时转入“等待你处理”。采集、自动重试和等待登录／验证码时，也可直接点击“跳过，更新下一本”，中断当前书的请求并保留检查点。停止整个书库更新与跳过单本是两个独立操作。

更新应用代码后，关闭已打开的拾页窗口，再从原快捷方式重新打开即可加载新按钮。验证命令：`node --test --test-concurrency=1 tools/novel-crawler/tests/library.test.mjs tools/novel-crawler/tests/desktop.test.mjs tools/novel-crawler/tests/crawler.test.mjs tools/novel-crawler/tests/continuation.test.mjs tools/novel-crawler/tests/reading-edition.test.mjs`。批量测试使用隔离的合成来源，覆盖新增、无更新、旧书衔接、换源绑定、阅读版、错误隔离、文件保护、停止续传及 320–1180 像素窗口。

### 一键上传书库（2026-09-15）

窗口右上角“更新书库”旁新增绿色的 **上传书库**，把本地 `downloads/` 中的新书、新章节同步到 `https://jiutianxiaoshuo.com`。更新代码后关闭拾页，再从原快捷方式重新打开即可使用。更新书库负责采集到本地，上传书库负责同步到网站；操作互斥，不会同时读写正在采集的文件。

上传复用当前已绑定的续更文件或阅读版，不重新请求采集来源，也不需要为每本书写上传规则。普通导出会核对保存的文件哈希；重复版本、未完成的绑定更新、排队后发生的文件改动会显示原因。报告与映射附属文件不作为书籍。

每本书先按稳定 `sourceUrl` 核对网站身份和全部已有章节摘要，只上传缺少的章节；相同章节不重复传输正文。缺失的章节来源链接以及明确提供的简介、分类、连载状态也会补充。网站多出的章节保留，同号异文、已下架书章、其他来源的同名同作者版本不会自动覆盖或重复建书。封面沿用独立的 `infra/upload-cover.mjs` 流程，书库上传不改动网站封面。

沿用现有 SSH 连接与服务器私有环境配置，数据库、R2 和导入密钥不离开 VPS。增量内容先完整预检查，再按每批最多 200 章、JSON 不超过 4 MiB 调用现有导入接口，写入后回读核验。窗口显示新书数、新增章节数、逐本结果和失败原因；单本冲突继续处理其他书。网络故障、网站配置不可用或 D1 额度耗尽会停止本轮，恢复后再次点击上传即可重新核对、续传成功批次之后的内容。

#### 上传提速（2026-09-15）

- 网站已有书先逐章核对章号、标题及正文摘要，只传网站缺少的章节，包括中间缺章和末尾新章；不因已有章缺少来源链接重传正文。已有内容冲突仍停止该书，不自动覆盖。简介、分类及完结状态可以独立同步。
- 批次从 20 章提高到最多 200 章，并按实际 UTF-8 JSON 字节拆分超长正文，避免超过接口 10 MiB 请求限制。整本质量检查在一次上传中复用，不再为规划和最终核验重复执行。
- 预检查最多 4 批并行，全部通过后才开始正式写入。同一本书的数据库事务按批顺序提交；每批用一次章节查询和批量插入代替逐章查询、逐章写库。
- `missingOnly: true` 使用独立的增量处理器；原导入方式与封面管理保持兼容。服务器先检查冲突，再仅将缺失正文写入 R2，最多 32 路并行，所有增量请求共用这一上限。每章仍保留写入后的完整读回及 SHA-256 校验，事务提交前再次核对，失败或重试不覆盖旧章。
- 只有真实回环连接、无浏览器 Origin/Cookie、且导入密钥正确的上传／核对请求，才能豁免普通接口每 15 分钟 500 次的限制；公网、错误凭据和其他写入接口仍沿用现有限流。
- 在当前 VPS 到 R2 的真实链路测量，每组 48 份合成正文均执行写入和完整读回：串行 20.828 秒；4 路 5.448 秒；8 路 2.660 秒；16 路两轮 1.491／1.484 秒；32 路两轮 1.031／0.983 秒，全部校验通过。因此采用 32 路。此结果仅代表正文存储阶段，不等于整本端到端提速倍数。336 个测试对象均使用独立 `_connection-check/` 命名空间，测试后已清理，没有写入书籍数据库。详细测量保存在本地 `.runtime/test-tmp/upload-speed/r2-benchmark.jsonl`。
- 提速包含网站服务端改动，需部署本次版本。拾页上传工作进程在点击上传时载入新代码；正在进行的上传沿用原进程，下一次上传自动使用新流程。

刷新窗口保留进度，停止或关闭程序保留已上传的内容；再次上传以网站实际数据为准，不依赖本机“已上传”标记。完成报告保存在 `.novel-crawler/uploads/`，实时状态沿用 `desktop-last-task.json`。停止时已经到达网站的单个批次仍可能完成，下次核对会识别它。

Windows 下替换进度文件可能因其他程序短暂占用而返回 `EPERM`、`EACCES` 或 `EBUSY`。原子写入会有限重试，期间保留旧文件；上传批次的进度摘要最多每秒落盘一次，结束状态立即尝试保存。如果摘要仍无法保存，窗口提示“本地进度暂未保存”并自动重试最新状态，上传与停止操作继续可用，保存恢复后提示消失。此摘要不决定续传位置，重试上传仍核对网站实际章节。修改拾页主程序后需关闭并从原快捷方式重新打开生效；此修复仅涉及本地程序，无需部署网站。

### 上传前批量核对与增量检查（2026-09-16）

- 一轮上传共用一个隐藏的 SSH 连接和一个数据库连接；每批读取最多 200 本的轻量版本摘要，不再每本重新连接。首次、网站版本变化或缓存失效时才读取完整章节摘要。
- 本地索引记录文件身份、大小、纳秒修改／变更时间和已计算的 SHA-256。文件未变化时不再解析整本 JSON；来源绑定、未完成更新和重复版本检查仍每轮执行。文件变化后重新读取并执行完整的内容质量校验，不只看章数或末章。
- 成功核验后保存本地文件哈希、网站版本和目录摘要。每次仍实时批量查询网站版本；两边均未变化才显示“本地与网站版本均未变化，已快速核对”。本地新增而网站版本未变时，复用已核实目录，只传中间缺章或末尾新章，保留网站旧正文。
- 网站导入返回事务前后版本，连续批次的版本必须衔接。只有确认期间没有其他写入，回读才限定在本次上传的章号；其他情况自动完整核对。目录读取前后也复核版本，避免把并发修改中的混合目录保存为检查点。章节永久清除同样推进作品版本。
- 缓存位于 `.novel-crawler/library-upload-cache/`，与正文、采集绑定分开。损坏、过期（30 天）、数据库配置变化和服务器版本切换均退回完整核对；缓存写入失败不会阻止上传。维护时可调用 `uploadLibrary({..., forceFull: true})` 强制重建，也可在拾页空闲时移除该缓存目录。直接修库／恢复旧备份后，必须更换服务器私有配置的 `LIBRARY_SYNC_EPOCH` 并重启服务，或清除本地核对缓存；正常网站写入通过同一事务更新 `Book.writeVersion`，不能在新维护工具中绕过这一约定。
- 报告增加 `metrics`：版本查询批次、快速跳过本数、复用目录本数、完整／增量回读次数。快速处理时窗口通知最多每 200 毫秒发送一次，结束状态完整保留；每 20 本让出执行机会，保持停止响应。

本次回归包含 1,000 本模拟书库：建立核验记录后的重复运行只发 5 次版本查询、0 次章节查询、0 次正文 JSON 读取。此项验证查询规模，不代表真实网络耗时；首次仍需完整建立记录。

### 保持登录与切换账号

浏览器来源现在默认按网站保存登录状态。**查找、读取详情、试采、下载、换书和重新打开拾页** 使用同一份网站浏览器资料；不同网站分别保存，`www` 与不带 `www` 的同站地址共用。任务结束仍关闭采集窗口，下一次任务恢复登录信息，不需要让窗口一直开着。

此前每个任务使用临时浏览器，关闭时就丢弃了登录信息，因此即使只隔一分钟，也可能再次要求登录。旧版已丢失的信息无法恢复；升级后第一次遇到登录要求时手动登录一次，之后即可复用。网站使登录过期、撤销登录或再次要求验证码时，仍会提示用户操作，不能保证网站永久保持登录。

网站栏下方显示“已启用登录记忆”，并提供 **清除本站登录**。要换账号时，在任务结束后选择对应网站再点击该按钮，下一次需要登录时使用新账号。清除只影响所选网站在拾页里的浏览器资料，不删除章节、报告或其他网站的登录，也不操作平常 Chrome 的账号。

资料保存于 `.novel-crawler/browser-sessions/`，由网站域名生成独立目录，不随书名或提取规则版本变化。普通持久 Cookie 的有效期、localStorage 和 IndexedDB 由浏览器管理；普通 Chrome 会在退出时清理部分会话 Cookie，因此程序额外保存当前会话 Cookie，并在再次启动时恢复，不修改持久 Cookie 的到期时间。Windows 下该补充记录使用当前 Windows 用户的 DPAPI 加密，其他平台使用仅当前用户可读写的文件。程序不会把登录信息写进来源配置、章节、报告或 Git，也不代填或提交账号密码。

### 自己调整采集速度

用记事本打开 `tools/novel-crawler/sites/shudugu.json`，修改 `spec` 中的 `"delayMs": 2000`，保存即可。单位是毫秒：`1000` 为 1 秒，`2000` 为 2 秒，`5000` 为 5 秒；数值越小，请求间隔越短。这是每个网页请求的间隔，不是每章的间隔，一章多页时每页都按此设置请求。实际速度还受网络响应时间影响。

正在运行的任务先点“暂停采集”并等它显示“已暂停”，再修改配置、重新点击“继续采集”；已暂停时直接修改后继续即可，无需重启拾页。新任务会加载最新配置，已保存章节仍可复用。只调整速度时不要改 `variant`，也不要改 `.novel-crawler/jobs/` 内的单本记录。其他网站在同目录各自的 JSON 中调整，互不影响。若出现 HTTP 429 或反复验证，可暂停并将间隔调回 `5000` 或 `8000`。

### 配置字段

站点配置放在 `tools/novel-crawler/sites/*.json`，不要与 `.novel-crawler/candidates/` 中的单本书配置混淆。可参照现有 `ixdzs8.json`。

| 字段 | 用途 |
| --- | --- |
| `version` | 站点配置格式，目前为 1 |
| `id` / `name` | 唯一英文标识、窗口中文名称 |
| `home` / `hosts` | 首页 URL、精确支持的域名列表，不使用通配符 |
| `search.url` | 搜索 URL，`${query}` 为 URL 编码后的书名 |
| `search.items` | 每个书籍结果卡片的 CSS 选择器 |
| `search.title` / `author` | 卡片内部唯一的提取规则，支持选择器字符串或 `{selector, attribute, pattern}`；pattern 取第一捕获组 |
| `search.link` | 卡片内书籍详情链接的 CSS 选择器 |
| `search.next` / `maxPages` | 下一页链接选择器和搜索上限，最多 20 页；没有更多结果时停止 |
| `search.delayMs` | 可单独设置搜索请求间隔（200–60000 毫秒）；省略时沿用采集间隔，用于搜索限速更严格的站点 |
| `search.transport` / `readySelector` | 可指定 `browser` 并等待页面完成；无结果页也应能匹配 readySelector |
| `search.form` | 浏览器搜索表单的 `input`、`submit` 选择器；正常输入关键词并提交，由网页自己的处理器生成动态参数，`readySelector` 匹配结果页 |
| `book.urlPattern` | 匹配详情 URL 的 pathname，例如 `^/book/(?<bookId>[0-9]+)/?$`，命名捕获可用于模板 |
| `book.metadata` | 详情页唯一的 `title`、`author` 提取规则 |
| `spec` | 原采集器完整来源配置模板；见 `docs/智能找书与采集.md` |

`search` 可省略，此时只支持详情页输入。网站首页模式只接受 `/` 路径。非首页路径需匹配书籍详情页规则，不自动把栏目页或章节页当作书籍。

`search.link` 也可使用 `{selector, attribute, pattern, base64QueryParameter?}`：从卡片中读取链接属性，提取正则首个捕获组；可选地解码指定查询参数中的 Base64 目标 URL。不会执行 `onclick`，解码后仍须通过站点域名、详情页路径及作品身份检查。独立搜索域名只放入 `spec.allowedHosts`，不当作书籍来源加入 `hosts`。

`spec` 支持 `${title}`、`${author}`、`${sourceUrl}` 和 `book.urlPattern` 的命名捕获。JSON 目录中的 `{ordernum}` 等逐章字段不带美元符，保留给目录解析器，不会在书籍模板阶段替换。`allowedHosts` 还需显式包含独立目录或下载域名，浏览器正文只加载配置允许的域名。

`spec.transport: "browser"` 对作品详情、HTML 目录和正文启用浏览器请求；搜索和详情页配置也继承它。采集默认无头运行；`browser.headless: false` 允许用户在需要人工操作时主动显示普通浏览器，`minimized: true` 在操作完成后恢复最小化，不再用于启动时抢先显示窗口。`responseMode: "source"` 读取浏览器收到的原始响应，以免站点随后转换 DOM 导致标题或正文在续传时变化。默认仍使用渲染后的 DOM。`identityNormalization: "chinese-simplified"` 仅在比较书名、作者时将繁体折叠为简体，不改变下载数据。

`browser.manualVerificationMs` 启用等待用户验证，取值 1000–600000 毫秒；配合 `headless: false` 使用。通过 Cloudflare 的 [`cf-mitigated: challenge` 响应标记](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/)识别验证页，避免把验证页当成空搜索结果或小说正文。验证等待时间、限速间隔属于运行参数，调整它们不会使已有章节检查点失效。

`browser.manualLogin` 可为已核实的登录限制配置 `selector`、可选的 `openSelector`（只打开表单）和 `timeoutMs`（1000–600000 毫秒）；真实使用须配合 `headless: false`。程序显示窗口并等待用户完成登录，只有回到同一请求地址的新成功响应不再匹配限制标记时才继续。`browser.resourceHosts` 为此类交互列出确切的静态资源域名，不放宽顶层页面和章节 URL 的域名校验。登录等待和子资源配置属于请求方式，修改不会废弃已保存的章节；实际提取规则变化仍须更新 `variant`。

`browser.manualCaptcha` 使用与 `manualLogin` 相同的 `selector`、`openSelector` 和 `timeoutMs` 字段，适用于已核实的站内验证码入口；只打开输入表单，不自动求解或提交验证码。它与 `manualVerificationMs` 的 Cloudflare 响应检测独立，均不改变检查点版本。

`spec.variant` 应包含站点规则版本，例如 `desktop-example-v1`。影响提取的规则变化时更新为 v2，自动生成独立任务，保留旧数据。默认使用当前站点模板，不自动套用旧的单本文件下载规则；代码中 `resolveBook({reuseSaved:true})` 仅供明确需要复用历史已验证单本规则的工具使用。

不要固定示例书 ID、标题、作者或 `expectedCount`，也不要将某一本 TXT 的特殊标题正则当作全站通用规则。资源型来源应另行验证分章结构。

## 换源续更（2026-09-13）

关闭后重新打开拾页，选择新网站，输入书名及作者并查找。若下载目录中已有同名同作者的书，结果会显示本地文件名、已有条目数和 **换源续更** 按钮；点击后先检查衔接，再更新原来的 JSON。完成后记住新来源，同一来源的按钮改为 **检查更新**。未完成、被停止或发生冲突时不改原文件，成功采集的新来源检查点可供重试复用。勾选“仅试采”时按钮为 **检查衔接**，只做抽样，不切换绑定或改动原文件。

支持已有普通导出 JSON 和已绑定的阅读版。书名、作者按完整身份比较，兼容标点、空格和繁简体；不靠相似书名认领文件。多个匹配文件时优先使用已明确绑定的阅读版；仍有多个候选则显示文件名并停止，用户可把不使用的版本移到下载目录之外后重新查找。已有文件的原章序、正文、来源链接和作品级 `sourceUrl` 保持稳定，历史顺序号缺口也保留，新条目从原最大顺序号之后追加；作者映射和封面不随采集来源切换。稳定的作品级来源供后续导入继续识别原书，新增章节另保存实际新站链接、来源目录序号和书籍地址。

首次换源核对原书末尾三个连续正文章节：新站章号和标题须对应（允许有明确共同前缀的截短标题），完整正文比较须一致。同一衔接章有重复目录项时，按目录顺序比较最多八个候选的完整正文，采用与旧章一致的条目。比较兼容繁简体、标点和空白差异，允许正文首行重复章标题或末尾“本章完”；不会按相似度接受缺段文字，也不会改写原正文。只读取衔接候选和后续内容，不重新下载新站全部旧正文。抽样通常检查衔接及紧接其后的三个目录项；完整续更仍须通过全部待追加条目的目录与正文检查，抽样通过不代表完整更新通过。

新增正文章号必须连续。同章号且标题对应、完整正文比较一致的重复条目可自动跳过，包括重复的一组章节；同名且完整正文相同的公告也不重复追加，比较范围包括原书和本次已接受的内容。若目录章号写错，但正文页标题名称对应、页内章号恰好接续上一章，可沿用正文页标题，另外保留 `catalogTitle`。每项自动处理保存两边链接、位置、正文哈希及处理原因，成功绑定累积保存 `resolutions`；被跳过的原始正文仍保留在来源检查点，窗口显示本次自动处理数量。

相似但文字不同的版本、无法对应标题的重复正文、乱码、未确认的拆章/合章、缺章、无可靠证据的编号重置、无法识别的无章号标题、衔接正文差异或已绑定来源目录的删除/插入/改名仍会阻止更新原书。衔接检查通过后，完整正文的单章冲突不再中断整个下载：先保存正文检查点并继续采集本批其他章节，结束时集中列出失败条目，全部解决后才写入原文件。网络或访问失败、损坏检查点、暂停、停止和数量上限仍结束当前批次，不继续向故障网站请求整本后续页面。更早的来源目录历史重号不参与换源衔接判定，旧文件内容不被重排。当前换源要求新站提供可读取的完整 HTML 目录；仅靠“下一章”遍历补全目录的来源、TXT 和 EPUB 暂不支持此操作。

无法自动判定的重复版本可在逐项核对后使用通用工具保存选择：`node tools/novel-crawler/continuation-review.mjs --spec 来源.json --first 第一版链接 --second 第二版链接 --keep 保留版链接 --reason 核对理由`。命令读取同一来源已保存的完整检查点，只允许同章号且标题对应的章节或同名公告，并使用作品锁防止与采集同时修改记录。`reviews.json` 记录书名作者、来源、提取规则、两个版本的链接与正文哈希、保留版本和理由；续传及拾页窗口自动沿用。只替换本次待追加内容，不替换原书章节，不生成或拼接缺失句子；未选版本的原始正文继续保存。任一正文改变或记录损坏，旧选择不再生效，仍需重新核对。这是对明确版本选择的记忆，不是按高相似度判断哪个版本正确。

衔接章存在逐项核实的版本文字差异时，可用同一工具的 `--anchor-file 下载目录内文件名 --old-number 原章顺序号 --new-link 新章链接 --old-hash 旧正文SHA256 --new-hash 新正文SHA256 --reason 具体核对依据` 保存对应关系；可另传 `--output-dir`。必须是原书末尾三个正文章节之一，双方章号和标题对应，且完整正文与操作者核对时的两个哈希一致。记录绑定原书来源、文件名、旧顺序号、新旧链接、标题、正文哈希和提取规则。只确认接续位置，旧章不被新版本替换；正文、标题或规则变化会令旧记录失效。默认仍要求全文比较一致，不按相似度自动创建核对记录。

对于“第五册预告”等不能从标题确定的无章号公告，读取完整内容后可用 `--notice-link 链接 --new-hash 正文SHA256 --reason 核对依据` 保存明确分类，后续按原标题和完整正文追加。带章号正文不能借此绕过连续性检查，正文变化需要重审；同名但内容不同的独立公告也只有明确核对后才允许保留，整本重复检查继续生效。

用户明确接受上下拆章后，可用 `--chapter-parts paired --reason 具体依据` 为当前作品及当前来源规则保存配对策略。只识别明确的标题后缀：空格后的“上／下”、括号中的“上／下”、`【上】／【下】`、`(1)／(2)`、`(1/2)／(2/2)`。两篇必须章号、基础标题和标记类型相同，且按上篇、下篇顺序接续；公告可夹在中间。下篇缺失、孤立下篇、混用标记或跳到下一章会阻止改写原书。新增上下篇分别保留原标题、完整正文和来源链接，不把下篇当成重复版本删除；同一篇的重复版本仍按完整正文或已核对哈希处理。默认策略不变，其他作品不会自动接受拆章。

原书完整一章可与新站目录中相邻的完整上下篇共同核对衔接，边界落在下篇之后；比较时分别归一化两篇并按顺序组合，旧章保持原样。需要明确核对差异时，在 `--anchor-file` 模式中用两组按顺序的 `--part-link 链接 --part-hash 正文SHA256` 代替单章的 `--new-link`、`--new-hash`。记录绑定两篇的链接、标题及完整正文哈希，不能用半篇登记整章对应关系。试采通常检查三个新目录项；第三项为上篇时会额外检查下一项，防止把半对拆章视为检查通过。接受拆章并不自动接受缺文或内容损坏，仍须核对并说明实际来源问题。

绑定、当前来源目录、正文比较证据和独立检查点存于 `.novel-crawler/continuations/<作品标识>/`。首次更新保留 `original.json`；文件变化时保留上一份 `previous.json`。`pending.json` 记录文件与绑定的同一次更新，异常退出后仅在文件仍为本次前/后版本时恢复。新旧来源的采集共用作品锁；人工修改文件、移动文件、改变输出目录或提取规则会停止。此操作不会上传或发布网站书籍。
