# 智能找书与采集

项目 Skill 位于 `.agents/skills/novel-download/SKILL.md`。在 Codex 中说“下载《书名》，作者某某，优先使用已验证来源”，由 Codex 完成搜索和适配，再运行本地程序。`sources` 命令本身只生成检索计划；搜索仍需实际调用可用搜索工具或浏览器。新增站点可能需要第一次编写提取规则。

程序不调用模型 API，不需要 OpenAI API Key。正文只在本地处理，终端默认不显示正文；搜索和报告解释仍使用 Codex token。

手动使用可双击项目根的 `拾页小说采集.vbs`，在窗口填写网站和书名。窗口长期记忆网站，不限制数量，左侧按最近使用排序，并恢复上次选择。用 `novel-source-adapter` Skill 添加网站，详见 [小说采集窗口与站点适配](./小说采集窗口与站点适配.md)。

## 长期选源规则

用户于 2026-09-14 明确将此规则用于今后由 Codex 协助的新书采集、换源和续更。它是持续有效的执行偏好；用户对具体书籍的新指示优先，已经明确跳过的书籍不因此自动恢复。本节不改变手动窗口的暂停、选书或换源行为。

1. **以这本书的实际质量选源，先保质再保量。** 不固定使用速读谷、友友小说或其他单一网站。复用已验证配置、同书试采证据和失败记录，但某网站以前采集成功不代表它的每本书都合格。先核对书名、作者和版本，再比较正文可读性、完整度、目录顺序；续更还要核对新旧章节衔接，其次考虑更新范围与访问稳定性。找不到最新章节很正常，质量更好的来源更新较慢可以接受；目录更新、更大章号或更多章节都不证明正文更好。比较候选时重点抽查最新几章，甄别字数异常少、正文残缺、乱码和密集错字；短章需先核实全部分页、拆章、通知等情况，并结合相邻章或同章其他来源比较，不能仅按固定字数判坏。只有低质量版本提供新章时，优先保留较好的版本或停在已验证的可读章节，不为追平更新牺牲正文质量。
2. **先查拾页已有网站。** 当前候选质量不足时，实际查找当前已配置或记忆的适用站点，试采有希望的版本，选出足够好的来源。站点范围从当前配置与站点库发现，不把某次任务的网站名单写成永久白名单。已有可靠证据的失败入口不必重复检查，检索计划不能当作搜索结果。
3. **再作有界的外部搜索。** 已有网站没有足够好的版本时，搜索其他来源；有希望的新站按站点适配流程验证。外部比较通常以每本约 10–15 分钟作为起始预算，有具体改善线索可以适度延长，用户另设时间则遵从。不要无限追求完美，也不要在同一失败入口反复消耗时间。正常获取或验证码处理有限尝试仍失败时，记录原因并换源或保留进度跳过；只有确实需要用户提供信息或操作才能推进时才询问。
4. **合理比较后继续采集。** 找不到完美版本时，选择现有候选中质量相对高的可用版本。零星错字、局部缺文或缺章、拆章合章、重编号、番外缺失或更新滞后等来源问题，默认记录并继续，不逐项反复请求确认。接受有限瑕疵不意味着为了追新接受严重残缺、乱码或密集错字的新章。作品身份错误、无法确定正文顺序、验证页面被提取成正文等不能当作可接受的来源瑕疵；应先修复或换源。没有可用候选时保留进度并说明实际阻碍。
5. **接受来源瑕疵仍须真实采集和验收。** 保留旧章、来源目录顺序、原始响应及哈希，不用 AI 补写缺文，不因标题数字重排，不随意把不同版本的章节混装。程序拦截已核实且符合上述偏好的来源缺陷时，使用现有的、限定具体章节与证据的验收机制；能力不足则补足针对性处理与检查，不能篡改成功标记或关闭全局保护。缺章提示或占位条目不能算作完整正文。
6. **报告只简短列出绑定网站和章节问题。** 按用户最新要求，面向用户的报告只写“书名 + 绑定的网站 + 缺失章节或有问题的章节及其简短问题”，例如“《书名》：绑定速读谷；第 123 章缺失；第 456 章末尾缺文”。网站名称以实际保存的绑定为准；未绑定或无法确认时如实标明，不把候选网站当作已绑定。优先使用用户能在书内定位的章号或标题；连续问题可合并为章节范围，无法精确定位时如实简述已知范围，不猜章号。没有已知问题的书也列出绑定网站，问题部分简写“未发现章节问题”。除非用户另问，不附选源理由、采集数量、采集终点、检查过程、技术字段等其他信息。

详细选源证据、实际完成量与验收结果仍保留在本地运行记录中，供排查使用，不默认附给用户。完成指所选来源的预定可采集范围已采集并通过相应验收，不代表所有版本无缺文、无错字或已追平作者最新进度；抽样未发现问题也不能报告为整本无瑕疵。

## 监督更新与 token 成本控制

用户于 2026-09-20 要求将以下原则作为后续监督更新的默认做法。质量与稳定性要求不变，重点减少反复读取、推理和输出造成的模型开销；脚本运行或等待时长不等于模型 token 用量。

1. **脚本执行，模型处理异常。** 复用批量更新入口、检查点和质量验收程序。成功项由程序汇总，不逐本交给模型审读；完整正文比对、哈希检查和统计在本地完成。
2. **先摘要，再按需取证。** 状态输出默认控制在一屏内，仅包含进度、活动任务和异常摘要。异常先看书名、错误类型、相关章节或链接、字数与哈希、差异数量及证据路径，再按需读取具体差异或局部上下文。完整目录、正文、警告列表和差异写入本地文件，不直接全部输出；出现截断后必须缩小查询范围。
3. **同类问题集中处理。** 按错误类型归并异常，复用已有工具与仍有效的核对证据；一个原因影响多本书时先修复共性原因，再针对受影响条目复核。避免为相似情况重复写一次性脚本或反复加载整套上下文。
4. **控制调查范围。** 常规可解决的代码问题自主修复；需要大量调查的来源问题，有限核对后保留原版、记录并继续其余书籍，随后说明额外工作的范围。常规监督不默认扩展成大规模重采或数据修复；遵从用户后续明确指示，不把暂缓更新描述为完成续更。
5. **按改动验证。** 修复期间优先运行相关检查与必要的针对性回归，交付前运行要求的完整检查；只有新改动、失败或未解决疑点才重复或扩大验证。日志留本地，只读取失败摘要和最终结果；仅修改文档时检查差异、格式和链接，不启动采集或运行无关测试。
6. **保持记录与沟通简短。** 进度说明聚焦新发现、处理决定和剩余阻碍。详细证据留在本地，最终逐书报告继续遵守上述简短格式。减少 token 消耗不能通过省略完整分页、作品身份、顺序、正文质量或绑定校验来实现，也不能关闭全局保护。
7. **监督进程与桌面窗口分别管理。** 无窗口的监督服务使用任务目录内的独立实例记录，不写入 `.novel-crawler/desktop-instance.json` 冒充已打开的拾页窗口。监督结束后关闭自己创建的服务，只清理仍属于该进程的记录；复用用户已有窗口时不关闭窗口。启动器须核实窗口确实响应显示请求，后台服务返回成功不能代替窗口已显示；后台仍有采集任务时保留进度，不并发启动第二个任务。
8. **复用按书压缩快照，不复制整库。** 正式书库更新入口自动保存即将处理的书及其恢复元数据，相同内容按哈希复用压缩对象。监督脚本不得再 `cpSync`/`copytree` 整个 downloads、jobs 或 continuations。历史备份按 [本地容量与清理](本地容量与清理.md) 明确归档、验证恢复后统一清理；原始证据、未完成任务和唯一恢复副本继续保留。

## 环境与命令

在项目根目录使用 Node 22（Windows 本项目自带 `.runtime/node-v22.23.2-win-x64/node.exe`）。复用现有 `axios`、`cheerio`、`iconv-lite`。TXT ZIP / EPUB 需要 Python 3 标准库；解释器默认 `python`，可设置 `NOVEL_CRAWLER_PYTHON`。

安装采集器专用依赖：进入 `tools/novel-crawler/` 目录运行 `npm install`，其中 `opencc-js` 用于繁简书名匹配。来源配置可设置 `transport: "browser"`；普通浏览器及原始响应模式见 [窗口与站点适配说明](./小说采集窗口与站点适配.md)。

```powershell
node tools/novel-crawler/cli.mjs sources --title "书名" --author "作者"
node tools/novel-crawler/cli.mjs probe --spec .novel-crawler/candidates/book.json
node tools/novel-crawler/cli.mjs download --spec .novel-crawler/candidates/book.json
node tools/novel-crawler/cli.mjs report --job 报告中的任务ID
node tools/novel-crawler/cli.mjs validate --file "downloads/导出的文件.json"
node --test tools/novel-crawler/tests/crawler.test.mjs
```

`download --max-new 50` 每次最多新处理50章，重复执行续传。未完成下载或存在严重异常时退出码为2，参数/运行错误为1；试采通过或完整下载通过为0。中断前已落盘的章节保留。`--refresh` 重取正文和响应，目录及作品元数据每次重新获取。程序不依靠上次对话的记忆。

同一来源再次下载时校验并复用已保存章节，目录末尾新增的章节才需要补采。完整导出内容没有变化时不重写文件，报告中的 `reusedExport` 为 `true`。输出文件若被手动修改则拒绝覆盖；目录发生删除、插入或改名也会停止续传。拾页窗口新增“停止”，可中断网络请求、关闭采集页面并保留已保存章节；搜索结果会显示本地进度，并提供“继续采集”或“检查更新”。

## HTML 来源配置

配置文件由 Codex 核实网页结构后编写，不从网页加载可执行代码。示例域名仅说明格式，需要替换为实际检查过的地址。

```json
{
  "version": 1,
  "kind": "html",
  "title": "书名",
  "author": "作者",
  "sourceUrl": "https://example.org/book/123/",
  "category": "玄幻",
  "delayMs": 1200,
  "retries": 2,
  "metadata": {
    "title": "h1",
    "author": {"selector": ".author", "pattern": "^作者[：:]\\s*(.*)$"}
  },
  "catalog": {
    "links": "#catalog li a",
    "next": "a.catalog-next"
  },
  "chapter": {
    "title": "h1",
    "content": "#content",
    "remove": [".ad", ".chapter-nav"],
    "next": "a.page-next"
  }
}
```

- `metadata.title`、`metadata.author` 和 `chapter.title` 可以用选择器字符串，或 `{selector, attribute, pattern}`。`attribute` 读取如 `content` 的属性；`pattern` 使用第一个捕获组。元数据必须唯一匹配，书名、作者必须匹配请求。需要简繁体/署名别名时在根配置显式添加 `titleAliases`、`authorAliases`，先核实再使用。
- `catalog.url` 可指定独立完整目录地址；省略时使用书籍页。`links` 必须只覆盖完整目录，不能混入“最新章节”。默认保留文档顺序；明确倒序的目录使用 `reverse: true`。有显式序号时用 `orderAttribute`，必要时用 `orderAncestor` 指定序号所在祖先，例如 `data-num` 和 `li`。不按标题数字、日期或 URL ID 排序。
- 完整目录地址无法从书籍ID推算时，可用 `catalog.link` 从已核对的详情页读取唯一入口链接。字符串表示链接CSS选择器，也可使用带 `selector`、`attribute` 的提取规则；链接仍经过允许域名和HTTP地址检查，缺失或多匹配会停止。它不能与固定 `catalog.url`、JSON、下拉或顺序目录模式混用；进入完整目录后仍可用 `catalog.next` 翻页。
- `catalog.next` 和 `chapter.next` 各自表示“下一页”，不能把“下一章”当下一页。无分页时省略。检测循环、重复目录、跳到另一章和跨域跳转。目录默认最多100页，章节最多20页，可设置各自 `maxPages`；全书最多20000项。
- HTML 目录可用 `catalog.titlePattern` 的第一个捕获组提取原章名，适用于网站在标题外额外加上目录序号的情况。只配置已核实的包装格式；不匹配、缺少捕获组或捕获为空时停止。完整页面标签另存 `sourceCatalogTitle`，链接和目录顺序不变；正文页仍须独立核对标题。修改此规则时也要更新 `variant`。
- `catalog.expectedCount` 是从独立证据核实的目录数量，可选。不能为了使测试通过把它随意改为解析出的数量。
- `chapter.rejectSelectors` 可列出已确认代表订阅/验证/段落混淆的标记。正文中的“广告”“作者”等普通词语不做全局删除。
- `chapter.removeText` 可列出已核实的正文噪声正则表达式，在 HTML 实体解码、移除节点后以 `gu` 标志逐条删除完整匹配。只配置完整噪声签名，不按普通词语或整段含词删除；空匹配规则会被拒绝。规则仅对该来源生效，修改时更新 `variant`。
- 对只有 JavaScript 下拉框的目录，可配置 `catalog.selectPages: {selector, content, maxPages, responseUrl?}`。程序在正常浏览器中依下拉选项顺序翻页，等章节容器实际变化后合并；重复、超时、跳转和超限均停止。`responseUrl` 只观察已核实目录接口的失败状态，不直接伪造接口请求。`catalog.count` 可用与元数据相同的提取规则读取详情页声明总数，再核对完整目录。下拉分页不能与 `catalog.next` 或 JSON 目录混用。
- 目录翻页失效、正文仍有正常导航的来源，可配置 `catalog.walk: {next, bookLink, chapterPattern, recentLinks, recentReverse?}`，并提供 `catalog.count`。此时 `catalog.links` 只读取开头连续目录，下载从第一章沿真实“下一章”扩展；`chapter.next` 仍只拼接同一章的“下一页”。`chapterPattern` 使用命名捕获 `chapterId`，可选 `page` 表示同章页码；导航必须属于同一来源和同一本书。缺失目录逐章保存，不推算 URL 或标题，不把首屏当作全书。
- 顺序采集遇到已核实的最新列表首项时，检查交集的链接、标题及位置，再接入列表尾部；必须与详情页总数一致。后续更新先用最新列表与保存目录的交集定位，只取新增正文；没有交集时刷新已保存末章的最后一页导航，沿下一章补齐缺口。循环、错书、提前结束、数量冲突或损坏检查点均停止并保留进度。该模式不能与其他目录分页混用；试采只取开头连续样本，报告独立列出来源总数、已知目录及尚未发现的条目数。
- `encoding` 可明确 HTML 编码，如 `gb18030`；默认使用响应/HTML声明，再回退 UTF-8。出现替换字符时停止，不默默替换乱码。
- `allowedHosts` 显式添加实际用到的下载域名或子域名，默认允许 `sourceUrl` 域名。重定向逐次核对，不能自动访问任意页面提供的域名。
- `searchUrl` 可保存站内搜索入口，用 `{query}` 作为 URL 编码后的检索词占位符。

目录也支持公开的 JSON 接口，配置示例：

```json
{
  "catalog": {
    "url": "https://example.org/catalog/",
    "request": {"method": "POST", "form": {"bookId": "123"}},
    "json": {
      "items": "data",
      "title": "title",
      "order": "position",
      "linkTemplate": "/book/123/{id}.html",
      "skip": {"field": "type", "equals": "volume-heading"}
    }
  }
}
```

`request` 省略时使用 GET；POST 只用于已经核实用途的公开目录读取接口，不用于账户或业务写操作。`items/title/order` 支持点分隔字段路径；目录链接字段必须实际存在。`skip` 仅排除已确认不是章节的卷标题，不能用于隐藏下载失败章节。

普通请求拿不到章节但正常浏览器能显示时，可设置 `chapter.transport: "browser"`。使用现有 Puppeteer、独立无头浏览器会话及正文选择器等待，结束后关闭会话；不加载用户 Cookie，不使用隐身插件，不自动解验证码。可用 `NOVEL_CRAWLER_BROWSER` 指定 Chrome/Edge，默认检查 Puppeteer 浏览器及 Windows 常见安装位置。浏览器只放行配置域名，图像/媒体/字体不加载。仍失败时换源；不能声称任意动态网站都能通用适配。

## TXT、ZIP 和 EPUB

保留上面的书名、作者、来源页、元数据规则，改为 `kind: "txt"` 或 `kind: "epub"`，添加：

```json
{
  "resource": {
    "url": "https://example.org/download/book.zip",
    "compression": "zip",
    "encoding": "gb18030",
    "headingPattern": "^\\s*(第[0-9零〇一二三四五六七八九十百千万两]+[章节回][^\\n]{0,90})\\s*$"
  }
}
```

- 纯 TXT 省略 `compression`；EPUB 不设置 `compression`。`resource.url` 和 `resource.link` 选一个，后者是来源页唯一下载链接的 CSS 选择器。
- TXT ZIP 只读取压缩包里唯一的 TXT；有多个时必须用 `entry` 明确文件名。不展开写入磁盘，不执行包内内容，限制解压大小。正文文件和页面编码分别配置。
- TXT 的 `headingPattern` 默认识别“第X章/节/回”。原始顺序保留；分章前的非空文字保存为“前言”。可用已经核实的 `startAfter` / `endBefore` 文本标记指定正文边界，未找到标记会报错，不猜测删除正文。
- 文件标题比在线目录额外转义了一层 HTML 实体时，可显式设置 `resource.decodeTitleEntities: true`。只解码标题的一层实体，保留字面尖括号、原始 `sourceTitle/sourceCatalogTitle` 和正文；解码后仍须通过原有目录核对，不用于容忍不匹配的章节。
- TXT 正文有已核实的 HTML 实体或广告整句时，可分别配置 `resource.decodeContentEntities: true` 和 `resource.removeText: ["精确噪声正则"]`。默认不清理；先按原文件分章，再只解码一层实体并移除完整匹配，字面尖括号和普通正文保留。禁止按“德”“旗”等单字或普通词删文；空匹配停止。新增规则须更换 `variant` 并重新试采，原始响应及哈希仍保留，目录、正文质量与导出保护照常验收。
- 若文件头明确是书名、作者和简介，可设置 `preamble: "metadata"`，原文另存 `source-preamble.txt`。如果文件同时有站点生成的章节标题和正文原始标题，应利用已核实的缩进/数字格式区分，配置 `headingPattern`；可选 `innerHeadingPattern` 只提取每章正文第一行的原始标题，保留 `catalogTitle`，不动后续正文或顺序。
- `resource.expectedCount` 可校验已经核实的分章数量。只有分章数量一致不足以证明内容正确，还需要核对目录标题/通知/附录的差异。
- EPUB 验证内置书名、作者，按 OPF spine 顺序读 XHTML 并按 h1/h2 分章，保留段落。加密 EPUB、复杂无法确定分章的格式会停止，需要其他来源或明确适配，不绕过加密。
- 资源哈希变化时不能复用旧章节，防止不同版本混装。超过60000字符的单章只报错，不截断。

资源来源也可以同时配置 `catalog` 与 `chapter`：先逐项精确比对文件标题和在线目录的前缀，只允许已核实为同一作品、同一来源的补采。正文保留文件原始标题，链接绑定在线目录位置；文件缺少的末尾目录项按章节规则下载。任一中间项不匹配就停止，不能按近似标题拼接。核对记录保存在 `resource-catalog-check.json`。

已确认 TXT 末段与网页版目录存在差异时，可配置 `resource.catalogPrefix: {"count": 已逐项核实的连续前缀数量, "reason": "具体差异及核对记录"}`。完整文件仍须通过分章数量校验并保留原始响应及哈希；只有指定前缀参与在线目录逐项比对，其后的所有目录项都从同站网页重新采集。前缀不匹配、文件变短、剩余章节获取失败或正文异常仍会停止导出，不能用此设置跳过缺章或混用别站正文。更改配置时更换 `variant`。

来源顺序验收中若有已核实的目录旧名与正文页标题差异，可在 `sourceOrderReview.titleMappings` 逐项保存 `position/link/title/catalogTitle/contentHash/reason/evidence`（证据含 `url/checkedAt/detail`）。仅接受保留章节上已检测的标题差异，原有两个标题及正文均不改写；未记录的差异、变化的检查点或新章问题仍阻止阅读版更新。这不是自动接受错章，必须先核实作品身份和真实正文顺序。

同一来源提供多个按目录顺序排列的纯 TXT 文件时，可用 `resource.parts: [{"url": "已核实的首段地址", "expectedCount": 500}, {"url": "已核实的后段地址", "expectedCount": 290}]` 代替 `resource.url/link`。必须配置在线 `catalog`，逐段校验独立核实的章节数，并逐项核对合并后的目录前缀；保留每段原始响应哈希、章节来源及元数据前言。分章和正文边界规则对每个文件分别应用。最多 40 段、总计 64 MiB 和 20000 项，不与 ZIP/EPUB 混用；任一段变化、顺序错误、缺章或重复内容仍按原有保护停止，不手动拼成无法追溯的新资源。

书库更新会沿用已有 TXT 导出或阅读版保存的来源配置，保留文件分段、清理规则和检查点，不将其替换成网站的普通 HTML 模板。来源 URL 仍须与当前适配匹配；同站新增目录项可按保存的章节规则补采，旧资源变化、输出文件被修改和映射损坏仍会停止。

## 输出和质量报告

以下是程序保留的本地运行记录；给用户的报告按“长期选源规则”只简短列出书名、绑定网站和章节问题，不直接附完整运行摘要。

```text
.novel-crawler/
  sources.json                       站点及各书最近验证记录
  candidates/                        本书候选配置
  cache/                             原始响应、来源及 SHA-256
  jobs/<id>/
    spec.json / catalog.json         来源规则和完整目录
    chapters/                        原子写入的章节检查点
    rejected/                        未通过正文校验的内容及原因
    partial.json                     不完整结果
    probe-report.json                最近试采报告
    download-report.json             最近下载报告
    download-report.md               可直接阅读的报告摘要
    history/                         各次运行报告
    export.json                      输出文件哈希，防止覆盖人工修改
downloads/书名--作者--来源ID.json      完整且结构检查通过的结果
```

站点库只在本地积累并在新任务中复用。记录整本成功与仅试采成功的区别，随时间降低优先级；同一站点的不同书独立验证，同书的试验版本只统计最近结果。失败来源仍记录原因和状态，不能因为域名曾成功就跳过试采。`--state-dir` 可隔离试验；新目录有独立站点库。已产生章节后改变提取规则需换新状态目录，或在来源配置添加新的 `variant` 标签以创建独立任务；旧结果保留，不能混用正文。

`completeAgainstSource` 仅表示完整下载当前来源目录；不保证该来源等于原作者完整版本。`structuralPass` 表示无空章、乱码、重复正文等已检测的严重问题。`warnings` 提示标题不一致、短章、高相似正文、自定义字体等疑点；只有数字/中文章号不同而题名一致的情况单独列为 `information`，仍保留两个标题。任何语义判断、隐蔽删文和段落错序都不在可靠检测范围内，程序不宣称“无错版”。

质量报告除检查 Unicode 替换字符外，也检测正文密集出现的 UTF-8/GBK 二次乱码特征：至少 20 个标记、3 类标记且占正文长度至少 1%，记为 `mojibake` 严重问题。少量引用或孤立生僻字不因此报错；检查只标记并阻止常规完整导出，不猜测还原或删除原文，也不妨碍先保存原始章节供核对。没有此类特征仍不代表正文语义或所有编码情况已验证。

正文保持原样，已识别的广告/脚本节点及正文边界的重复标题、导航独立行会移除。通知、番外和短章保留。严重问题阻止完整导出；可疑内容保留在检查点和报告中。普通完整结果仍可能带警告；交付时只将需要用户知道的章节问题转成简短说明。

阅读版续更支持数字章号紧接中文标题，例如 `641研判（4K）`，不要求来源额外添加空格。原始标题与正文保持不变，仍须接续上一正文章号；跳号或重号不能通过公告验收绕过。`6月总结` 等原有月度总结仍按公告保留，不占用正文章号。

续更中的非标准标题公告可先通过 `--notice-link` 对双方完整正文分别验收，再用版本核对入口选择同名公告的保留版本。两个链接都必须具有仍匹配正文哈希的公告核对记录；只核实一方、正文已变化、标题不同或带正文章号时仍拒绝，不能借此跳过新章。

同标题的近似重复也会阻止导出和整本上传：正文至少 100 字符、长度比不低于 80%，逐位置 16 字符片段的 Jaccard 相似度不低于 80% 时记为 `duplicate-title-body` 严重问题。逐位置比较避免少量插字或标点改动使旧的稀疏采样失效。重复链接和完全重复正文同样拦截；不同正文的同名通知不因此删除。`infra/import-plan.mjs` 在拆分上传批次前重新检查整本，旧文件即使已通过历史质量报告也不能跳过。疑似重复必须核对，程序不自动挑选保留版本。

经逐项核对，采用原目录顺序、仅移出确定重复项的阅读版，可通过 `reading-edition-cli.mjs --spec 原任务/spec.json --file 阅读版.json --source-order-review 核对.json` 绑定。核对文件包含原目录的 `catalogHash`、说明已知编号瑕疵的 `reason`，以及 `pairs: [{omit, keep, omitHash, keepHash, reason}]`；位置均为原目录一基序号，哈希为完整正文哈希。程序必须重新确认重复关系，核对阅读版全文、标题、来源、连续顺序号及原目录次序；除此之外不得遗漏任何目录项。此方式不重排、不改原章号、不补文，历史缺文和编号瑕疵仍须报告。原始目录和两份正文均保留，绑定持续记录验收；新增重复、乱码、章号跳转仍暂停更新。普通阅读版绑定继续使用原来的连续章号检查。

已检测为 `similar-body`、仅有少量字形差异的错贴重复章，须人工逐字核实后，在对应 `pair.glyphReview` 保存 `differences: [{offset, omit, keep}]` 和 `evidence: {url, checkedAt, detail}`。`offset` 是 `normalizedText` 归一化后的 Unicode 字符数组零基位置；必须完整、依序列出所有不同字符。两篇正文须等长且至少 1000 字，差异不超过 32 字及全文的 1%，原文哈希仍须匹配。此记录只准移出这一条已核实的重复项，不修改任何正文，也不放行未检测的相似关系、缺段、长短不同、其他警告或后来新增的异常。

网站目录只接受明确的 `volume_title` / `volume_number` 元数据、带章号的卷名前缀或独立的“第X卷”标记。没有明确分卷的书直接显示连续章节列表，不显示“正文”或“番外”分组、卷标题和折叠按钮。章节标题中的“正文”“番外”和“第一卷 结束以及请假”等通知不改变后续章节归属；有名称的独立卷标题须携带分卷元数据。确有分卷的书保留卷名、折叠与阅读位置恢复；分卷前的序言直接显示，章节 ID、顺序和正文均不因此改变。

导出字段兼容 `infra/import-plan.mjs`：书籍 `title/author/sourceUrl/chapters`，章节 `title/content/chapter_number/link`；额外保存来源和采集证据。使用既有导入验证器，不改数据库、阅读进度或 R2。已有书更换 `sourceUrl` 可能被识别为另一本书，上传前必须核对身份映射。

导出时为 `title` 和 `catalogTitle` 中明确的“第X章/节/回/卷”与章名补齐一个空格，例如 `第1章陨落的天才` → `第1章 陨落的天才`。不改变数字写法、章名内部空格或已有冒号等分隔符；只有章号、通知或番外等标题保持原样。发生格式调整时，用 `sourceTitle` / `sourceCatalogTitle` 保留来源原值；原始检查点不修改，续传导出也会应用相同格式。

下载不自动上传线上。此次本地工具修改不需要切换网站服务版本；只有修改线上运行代码时才按项目部署约定发布。

已核实的来源编号错误可用 `continuation-review.mjs --spec 来源.json --source-defect 核对.json` 记录相邻三项的链接、完整正文哈希和独立证据，保留来源原题原文。错误恰好发生在旧书末章与新增首章之间时，核对文件还须包含 `boundary: {file, exportHash, chapterHash}`：下载目录内的旧书文件名、原文件字节哈希、末章完整对象哈希。程序核实同书同作者、末章题名及完整正文与来源三项中的第一项一致，并将旧书整体绑定到这次验收；旧书或任一核对项变化均拒绝续更。没有这份边界核对记录，普通编号验收不能放行旧书接续处的跳号；不得凭编号猜测缺失正文。

已确认接续边界实际缺少 1–3 章时，可用 `continuation-review.mjs --spec 来源.json --source-gap 核对.json` 明确保留缺口后接续。核对文件包含 `file/exportHash`、缺口后相邻两章的 `links/hashes`、`reason`，以及独立目录 `reference: {url, bodyFile, hash, chapters: [{title, link}]}`。独立页面必须唯一、连续列出同书同作者的旧末章、全部缺章及后续两章；当前来源目录中确实没有缺失条目，不能借此跳过已有正文。旧书整体、后续两章完整正文及证据原页均锁定哈希，任何变化或缺少后续核对章仍会暂停。缺章记录持续写入绑定和 `sourceGaps`，不补写正文；`completeAgainstSource` 保持 `false`，导出验收用 `completeSelectedScope` 表示。

绑定阅读版的新增三项内出现重号或跳号时，可用 `reading-edition-cli.mjs --spec 原始任务/spec.json --numbering-review 核对.json` 保留来源编号接续。记录须包含 `exportHash`、相邻三项的 `links`、完整正文 `hashes`、`reason`，以及 `reference: {url, bodyFile, hash, chapters}`；`chapters` 是独立目录的三个完整标题。独立页面必须包含同书同作者和连续章号的同名三章，默认三个来源条目全部尚未收录、内部只有一处编号不连续（可在最新一章）。错误恰好发生在旧末章与新增首章之间时，另传 `boundary: {chapterHash}`，只允许原书最后一个完整章节及紧随其后的两个新章；旧末章必须也是已接受来源目录的最后一项，完整章节对象、题名和正文均须匹配，不能跨过缺文或公告。完整正文与目录仍须通过质量检查。程序保存独立原页并锁定三个正文指纹；原书、新章或证据改变时拒绝放行。原题、正文、旧映射都不改写，也不能用它略过旧书边界的真实缺章。

已通过上述逐项验收的末章编号后来被源站修正时，可用 `--catalog-number-review 核对.json`，提供 `exportHash/link/title/reason`（`title` 为当前来源标题）。程序重新获取完整目录与同章全部分页，限定原位置、原链接、同一题名、编号只变动一位且接续前章、正文逐字一致的末章；其他目录项不能改变。保存原始响应证据，保留旧书原题、正文和检查点，只按已核实的新编号检查后续章节。正文修订、插章、其他改名、损坏证据和未验收的跳号仍然暂停，不能用此入口接受作者重写。

已有续更绑定的旧文件因历史重复项阻止更新时，先逐项比对双方完整正文，再用 `continuation-review.mjs --spec 来源.json --repair-duplicates 核对.json` 显式修复。核对文件包含 `exportHash`、`reason` 和 `pairs: [{omit, keep, omitHash, keepHash, reason}]`；序号取原文件的 `chapter_number`，双方哈希对应完整章节对象。只接受检测为同题重复的条目，禁止移出保留项或末尾三个衔接章；剩余整本仍须通过导入校验。所有保留对象及编号不变，完整原文件、旧绑定和核对理由备份至对应续更目录的 `repairs/原文件哈希/`，文件与绑定通过已有恢复日志一起更新。常规更新不自动移除历史重复项，也不因此豁免新增正文检查。

阅读版的 `sourceOrderReview.gaps` 可逐项记录已核实的缺文提示或残缺章节，原始正文仍完整保留在检查点。每项必须保存 `position/link/contentHash/kind/reason` 及 `evidence.url/checkedAt/detail`；`placeholder` 仅接受已识别的独立缺文提示，`truncated` 另需与原文一致的 `actualCharacters` 和独立来源的 `expectedCharacters`，实际字数须少于预期的八成。先核实完整分页、正常拆章及其他来源，不能仅凭短章自动认定缺文或删章。阅读版仅移出这些具体核对项，保留其余全部来源顺序及正文。存在缺文时报告 `completeAgainstSource: false`，通过所选范围验收单独记为 `completeSelectedScope: true` 并附 `sourceGaps`，不能把缺文算成完整正文。新的缺文提示仍阻止完整导出。旧末章之后已有 1–3 个连续章号的缺文验收时，原映射、正文哈希和证据均未变化才可沿用这些具体缺口接续；中间已收录的公告必须完整保留，未验收的缺口仍暂停。

阅读版迁移到同一网站的 HTML 接续时，末尾三章之间已有的缺口仅在完整旧书哈希、原阅读版状态、来源位置与目录标题、缺文正文检查点及既有证据全部吻合时沿用原核对。三章正文仍须分别对齐，新增章节仍须连续；此机制不跨网站继承缺口、不补写或替换旧章。缺口随续更绑定持续保留在 `sourceGaps` 和警告中，`completeAgainstSource` 仍为 `false`，不能声称已经补齐。

文件来源中的空目录项仍保存原始链接、资源哈希和检查点，质量报告继续以 `empty` 阻止完整导出，不会填充正文。逐项验收可用 `gaps.kind: "empty"`，只接受实际空文本；`garbled` 只接受正文至少出现 10 个、且至少 3 种私用区异常字形的条目。两者仍须绑定原目录位置、正文哈希及具体取证说明，仅将该条目从阅读版移出；完整原文保留，报告标明缺口。它们不豁免其他章节、验证页面、解码错误或新增缺陷。

续更绑定末尾的已收录公告被源站加上“第X章”前缀时，可用 `continuation-review.mjs --spec 来源.json --catalog-notice-review 核对.json` 验收。核对文件含 `exportHash/link/title/reason`，`title` 为当前目录标题。入口重新读取完整目录和同章全部分页，只接受其余旧目录完全不变、原无章号公告仅增加章号、正文逐字相同的情况；原书和原始检查点不改写。后续更新沿用已核对的公告原标签，不把新加的章号占作正文章号。原书、检查点或核对证据损坏，以及其他改名、正文修订和目录重排仍会暂停。此入口须先核对具体公告，不自动放行任意标题变化。

章号解析支持“一零二五”“一〇二五”等逐位中文数字，按 1025 处理；“一千零二十五”等带单位写法保持原规则。它只修复章号识别，不修改来源标题，也不放行真正的跳号。

书库工作进程退出前会等待已发送的进度与完成消息写入 IPC 通道；桌面端在通道关闭后再判定异常退出，避免大型书库已完成却误显示“进程停止”。回归用大结果消息复现旧版本误报，并验证完成状态在退出后保持稳定。
