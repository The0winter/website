# 智能找书与采集

项目 Skill 位于 `.agents/skills/novel-download/SKILL.md`。在 Codex 中说“下载《书名》，作者某某，优先使用已验证来源”，由 Codex 完成搜索和适配，再运行本地程序。`sources` 命令本身只生成检索计划；搜索仍需实际调用可用搜索工具或浏览器。新增站点可能需要第一次编写提取规则。

程序不调用模型 API，不需要 OpenAI API Key。正文只在本地处理，终端默认不显示正文；搜索和报告解释仍使用 Codex token。

手动使用可双击项目根的 `拾页小说采集.vbs`，在窗口填写网站和书名。窗口长期记忆网站，不限制数量，左侧按最近使用排序，并恢复上次选择。用 `novel-source-adapter` Skill 添加网站，详见 [小说采集窗口与站点适配](./小说采集窗口与站点适配.md)。

## 环境与命令

在项目根目录使用 Node 22（Windows 本项目自带 `.runtime/node-v22.23.2-win-x64/node.exe`）。复用现有 `axios`、`cheerio`、`iconv-lite`。TXT ZIP / EPUB 需要 Python 3 标准库；解释器默认 `python`，可设置 `NOVEL_CRAWLER_PYTHON`。

安装采集器专用依赖：进入 `tools/novel-crawler/` 目录运行 `npm install`，其中 `opencc-js` 用于繁简书名匹配。来源配置可设置 `transport: "browser"`；普通浏览器及原始响应模式见 [窗口与站点适配说明](./小说采集窗口与站点适配.md)。

```powershell
node tools/novel-crawler/cli.mjs sources --title "书名" --author "作者"
node tools/novel-crawler/cli.mjs probe --spec .novel-crawler/candidates/book.json
node tools/novel-crawler/cli.mjs download --spec .novel-crawler/candidates/book.json
node tools/novel-crawler/cli.mjs report --job 报告中的任务ID
node tools/novel-crawler/cli.mjs validate --file "downloads/导出的文件.json"
node --test tools/novel-crawler/tests/crawler.test.mjs
```

`download --max-new 50` 每次最多新处理50章，重复执行续传。未完成下载或存在严重异常时退出码为2，参数/运行错误为1；试采通过或完整下载通过为0。中断前已落盘的章节保留。`--refresh` 重取正文和响应，目录及作品元数据每次重新获取。程序不依靠上次对话的记忆。

同一来源再次下载时校验并复用已保存章节，目录末尾新增的章节才需要补采。完整导出内容没有变化时不重写文件，报告中的 `reusedExport` 为 `true`。输出文件若被手动修改则拒绝覆盖；目录发生删除、插入或改名也会停止续传。拾页窗口新增“停止”，可中断网络请求、关闭采集页面并保留已保存章节；搜索结果会显示本地进度，并提供“继续采集”或“检查更新”。

## HTML 来源配置

配置文件由 Codex 核实网页结构后编写，不从网页加载可执行代码。示例域名仅说明格式，需要替换为实际检查过的地址。

```json
{
  "version": 1,
  "kind": "html",
  "title": "书名",
  "author": "作者",
  "sourceUrl": "https://example.org/book/123/",
  "category": "玄幻",
  "delayMs": 1200,
  "retries": 2,
  "metadata": {
    "title": "h1",
    "author": {"selector": ".author", "pattern": "^作者[：:]\\s*(.*)$"}
  },
  "catalog": {
    "links": "#catalog li a",
    "next": "a.catalog-next"
  },
  "chapter": {
    "title": "h1",
    "content": "#content",
    "remove": [".ad", ".chapter-nav"],
    "next": "a.page-next"
  }
}
```

- `metadata.title`、`metadata.author` 和 `chapter.title` 可以用选择器字符串，或 `{selector, attribute, pattern}`。`attribute` 读取如 `content` 的属性；`pattern` 使用第一个捕获组。元数据必须唯一匹配，书名、作者必须匹配请求。需要简繁体/署名别名时在根配置显式添加 `titleAliases`、`authorAliases`，先核实再使用。
- `catalog.url` 可指定独立完整目录地址；省略时使用书籍页。`links` 必须只覆盖完整目录，不能混入“最新章节”。默认保留文档顺序；明确倒序的目录使用 `reverse: true`。有显式序号时用 `orderAttribute`，必要时用 `orderAncestor` 指定序号所在祖先，例如 `data-num` 和 `li`。不按标题数字、日期或 URL ID 排序。
- `catalog.next` 和 `chapter.next` 各自表示“下一页”，不能把“下一章”当下一页。无分页时省略。检测循环、重复目录、跳到另一章和跨域跳转。目录默认最多100页，章节最多20页，可设置各自 `maxPages`；全书最多20000项。
- `catalog.expectedCount` 是从独立证据核实的目录数量，可选。不能为了使测试通过把它随意改为解析出的数量。
- `chapter.rejectSelectors` 可列出已确认代表订阅/验证/段落混淆的标记。正文中的“广告”“作者”等普通词语不做全局删除。
- `encoding` 可明确 HTML 编码，如 `gb18030`；默认使用响应/HTML声明，再回退 UTF-8。出现替换字符时停止，不默默替换乱码。
- `allowedHosts` 显式添加实际用到的下载域名或子域名，默认允许 `sourceUrl` 域名。重定向逐次核对，不能自动访问任意页面提供的域名。
- `searchUrl` 可保存站内搜索入口，用 `{query}` 作为 URL 编码后的检索词占位符。

目录也支持公开的 JSON 接口，配置示例：

```json
{
  "catalog": {
    "url": "https://example.org/catalog/",
    "request": {"method": "POST", "form": {"bookId": "123"}},
    "json": {
      "items": "data",
      "title": "title",
      "order": "position",
      "linkTemplate": "/book/123/{id}.html",
      "skip": {"field": "type", "equals": "volume-heading"}
    }
  }
}
```

`request` 省略时使用 GET；POST 只用于已经核实用途的公开目录读取接口，不用于账户或业务写操作。`items/title/order` 支持点分隔字段路径；目录链接字段必须实际存在。`skip` 仅排除已确认不是章节的卷标题，不能用于隐藏下载失败章节。

普通请求拿不到章节但正常浏览器能显示时，可设置 `chapter.transport: "browser"`。使用现有 Puppeteer、独立无头浏览器会话及正文选择器等待，结束后关闭会话；不加载用户 Cookie，不使用隐身插件，不自动解验证码。可用 `NOVEL_CRAWLER_BROWSER` 指定 Chrome/Edge，默认检查 Puppeteer 浏览器及 Windows 常见安装位置。浏览器只放行配置域名，图像/媒体/字体不加载。仍失败时换源；不能声称任意动态网站都能通用适配。

## TXT、ZIP 和 EPUB

保留上面的书名、作者、来源页、元数据规则，改为 `kind: "txt"` 或 `kind: "epub"`，添加：

```json
{
  "resource": {
    "url": "https://example.org/download/book.zip",
    "compression": "zip",
    "encoding": "gb18030",
    "headingPattern": "^\\s*(第[0-9零〇一二三四五六七八九十百千万两]+[章节回][^\\n]{0,90})\\s*$"
  }
}
```

- 纯 TXT 省略 `compression`；EPUB 不设置 `compression`。`resource.url` 和 `resource.link` 选一个，后者是来源页唯一下载链接的 CSS 选择器。
- TXT ZIP 只读取压缩包里唯一的 TXT；有多个时必须用 `entry` 明确文件名。不展开写入磁盘，不执行包内内容，限制解压大小。正文文件和页面编码分别配置。
- TXT 的 `headingPattern` 默认识别“第X章/节/回”。原始顺序保留；分章前的非空文字保存为“前言”。可用已经核实的 `startAfter` / `endBefore` 文本标记指定正文边界，未找到标记会报错，不猜测删除正文。
- 若文件头明确是书名、作者和简介，可设置 `preamble: "metadata"`，原文另存 `source-preamble.txt`。如果文件同时有站点生成的章节标题和正文原始标题，应利用已核实的缩进/数字格式区分，配置 `headingPattern`；可选 `innerHeadingPattern` 只提取每章正文第一行的原始标题，保留 `catalogTitle`，不动后续正文或顺序。
- `resource.expectedCount` 可校验已经核实的分章数量。只有分章数量一致不足以证明内容正确，还需要核对目录标题/通知/附录的差异。
- EPUB 验证内置书名、作者，按 OPF spine 顺序读 XHTML 并按 h1/h2 分章，保留段落。加密 EPUB、复杂无法确定分章的格式会停止，需要其他来源或明确适配，不绕过加密。
- 资源哈希变化时不能复用旧章节，防止不同版本混装。超过60000字符的单章只报错，不截断。

资源来源也可以同时配置 `catalog` 与 `chapter`：先逐项精确比对文件标题和在线目录的前缀，只允许已核实为同一作品、同一来源的补采。正文保留文件原始标题，链接绑定在线目录位置；文件缺少的末尾目录项按章节规则下载。任一中间项不匹配就停止，不能按近似标题拼接。核对记录保存在 `resource-catalog-check.json`。

## 输出和质量报告

```text
.novel-crawler/
  sources.json                       站点及各书最近验证记录
  candidates/                        本书候选配置
  cache/                             原始响应、来源及 SHA-256
  jobs/<id>/
    spec.json / catalog.json         来源规则和完整目录
    chapters/                        原子写入的章节检查点
    rejected/                        未通过正文校验的内容及原因
    partial.json                     不完整结果
    probe-report.json                最近试采报告
    download-report.json             最近下载报告
    download-report.md               可直接阅读的报告摘要
    history/                         各次运行报告
    export.json                      输出文件哈希，防止覆盖人工修改
downloads/书名--作者--来源ID.json      完整且结构检查通过的结果
```

站点库只在本地积累并在新任务中复用。记录整本成功与仅试采成功的区别，随时间降低优先级；同一站点的不同书独立验证，同书的试验版本只统计最近结果。失败来源仍记录原因和状态，不能因为域名曾成功就跳过试采。`--state-dir` 可隔离试验；新目录有独立站点库。已产生章节后改变提取规则需换新状态目录，或在来源配置添加新的 `variant` 标签以创建独立任务；旧结果保留，不能混用正文。

`completeAgainstSource` 仅表示完整下载当前来源目录；不保证该来源等于原作者完整版本。`structuralPass` 表示无空章、乱码、重复正文等已检测的严重问题。`warnings` 提示标题不一致、短章、高相似正文、自定义字体等疑点；只有数字/中文章号不同而题名一致的情况单独列为 `information`，仍保留两个标题。任何语义判断、隐蔽删文和段落错序都不在可靠检测范围内，程序不宣称“无错版”。

正文保持原样，已识别的广告/脚本节点及正文边界的重复标题、导航独立行会移除。通知、番外和短章保留。严重问题阻止完整导出；可疑内容保留在检查点和报告中。普通完整结果仍可能带警告，需要在交付时说明。

导出字段兼容 `infra/import-plan.mjs`：书籍 `title/author/sourceUrl/chapters`，章节 `title/content/chapter_number/link`；额外保存来源和采集证据。使用既有导入验证器，不改数据库、阅读进度或 R2。已有书更换 `sourceUrl` 可能被识别为另一本书，上传前必须核对身份映射。

导出时为 `title` 和 `catalogTitle` 中明确的“第X章/节/回/卷”与章名补齐一个空格，例如 `第1章陨落的天才` → `第1章 陨落的天才`。不改变数字写法、章名内部空格或已有冒号等分隔符；只有章号、通知或番外等标题保持原样。发生格式调整时，用 `sourceTitle` / `sourceCatalogTitle` 保留来源原值；原始检查点不修改，续传导出也会应用相同格式。

下载不自动上传线上。此次本地工具修改不需要切换网站服务版本；只有修改线上运行代码时才按项目部署约定发布。
