# 登录会话与续期

所有角色（包括管理员）统一使用 72 小时有效期。前台页面打开、回到可见状态以及点击、触摸、键盘、滚动等操作会报告活动；没有操作的页面没有循环心跳，隐藏页面不会发送续期请求。以最后一次合并记录的活动为基准，计时误差在正常情况下约五分钟以内。

浏览器使用五分钟窗口合并操作，localStorage 和 Web Locks 协调同一账号的多个标签页。每个窗口最多发送一次活动请求和一次不访问数据库的 CSRF 请求。请求失败也占用窗口，避免断网时频繁重试；401 清除页面登录状态，临时网络错误不清除。没有 Web Locks 或存储被禁用时退化为标签页限频，服务端继续保护会话写入。

`POST /api/auth/activity` 使用原有登录验证与 CSRF 保护，读取当前会话及账号，不缓存权限，不绕过密码修改、退出和封禁。新增 `lastActiveAt` 字段，距离上次记录不足五分钟不写数据库；到期后按会话 ID 条件更新现有记录，推进 `expiresAt` 至当前时间加 72 小时，同时重发有同样期限的 HttpOnly Cookie 和 JWT。进程内共享正在进行的续期，数据库条件更新防止并发重复修改。没有全表扫描、逐用户定时器或新增索引。原有业务读取、预取和后台请求均不触发续期。

JWT 仍校验签名和到期时间，数据库仍校验到期时间、账号状态和权限版本。CSRF 绑定稳定的会话 ID，避免 JWT 轮换打断其他标签页的正常提交。续期不使用 upsert，退出、密码修改或封禁删除的会话不会被重新创建。

已经有效的旧登录在第一次活动报告时转为新规则，无需批量清除登录记录；已经过期的登录仍需重新登录。旧版本可以读取新增字段与同格式 JWT，代码回滚不需要数据库回退。
